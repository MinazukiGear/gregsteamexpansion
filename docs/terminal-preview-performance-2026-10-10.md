# 终端预览性能基线与重复计算优化

日期：2026-10-10。基于 beta.2 发布后的开发工作区，不新增机器，不改配方、施工预算、材料事务、工程数据或网络协议。beta.2 标签与公开附件保留原发布状态。

## 测量方法

使用 `tools/benchmark_terminal_preview.py`，在独立 GameTest 世界放置 16 个未建造的 3×3 蒸汽粉碎机控制器，以及一个默认 15×15 蓄热熔炉控制器。紧凑结构以 1、4、16 个目标和 1、2、8 名模拟生存使用者组成九种负载，大型结构单独测一使用者、一目标，轮换顺序测两轮。每组先预热一批，再测五批，批次之间让出服务端 tick，保存每批全部使用者预览的中位数和最大耗时。每组样本较少，用于本轮基线与前后比较，不作尾延迟分布结论。

模拟使用者背包为空，关闭 AE 查询，按服务端线程顺序调用真实 `preview()`。数据只描述服务端预览批次，不代表真实网络并发、完整服务器 MSPT、堆分配或客户端全息帧率；没有据此调整施工额度。耗时不作为自动门禁阈值。

基准测试使用专用命名空间，普通 GameTest、配置重启与依赖组合不会运行它。每次生成新的报告目录，并保存源码指纹、环境、原始日志和测量 JSON；旧测试世界归档，不打开开发存档。

```bash
python tools/benchmark_terminal_preview.py --offline --label baseline
python tools/benchmark_terminal_preview.py --offline --label optimized
```

两份正式测量使用相同基准代码、夹具和环境，终端生产代码仅修改预览计算实现；分别留存真实优化前与优化后的报告，不使用旧逻辑模拟计时。

试运行曾修正模板命名空间与空中夹具位置，并缩减高开销采样；这些未完成或中断的报告只保留排查来源，不纳入前后比较。大型结构的多目标/多人压力、真实 AE 网络、堆内存与客户端全息另行测量。

## 本轮验收

Windows x64、Zulu JDK 17 本地验证：

- 优化前后独立基准均完成 20 组记录，报告对应真实源码；基准、规划器和构建配置一致，仅预览生产源码指纹不同。
- 普通回归 **192/192** 项必需 GameTest 通过，`compileJava runGameTestServer build` 成功。新增预览回归核对单目标/批量材料、目标切换、方块与背包变化、四种施工模式和未加载目标；基准本身不计入 192 项普通回归。
- 资源生成一致性、语言键、设计契约、Java 17 JAR 可移植性与蒸汽经济门禁通过；Python 可移植性工具测试 **9/9** 通过。
- 原存档 46 个文件、开发配置、客户端选项与已发布 beta.2 附件的 SHA-256 核对一致。

完整本地门禁日志保留于 `.tmp/terminal-preview-regression-build.log`。以上为本地验证记录；四平台 CI 的执行与结果以对应提交的 GitHub Actions 为准，客户端帧率尚未测量。beta.2 的历史四平台 CI 记录仍对应原标签源码。
