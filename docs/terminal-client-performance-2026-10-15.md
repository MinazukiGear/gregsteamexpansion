# 终端真实客户端全息性能记录（2026-10-15）

本轮完成真实客户端前后各 30 组对照。第二轮大型结构静止组的渲染线程分配 P50 为 `1,414,464 → 1,089,912 B/帧`（减少约 23%），绘制提交 P95 为 `5.4147 → 4.7948 ms`。整帧尾延迟没有稳定改善，不能将提交和分配的变化换算为同等 FPS 提升。

## 测量范围

本轮运行实际 Forge/OpenGL 客户端，测量本机玩家当前选中预览的帧间隔、渲染线程提交耗时和 Java 线程分配量。客户端在独立平坦世界中重放服务端规划器生成的快照；不把服务端 GameTest 耗时称为客户端 FPS，也不把 CPU 提交耗时称为 GPU 执行时间。

固定条件：Windows 11 x64、AMD Ryzen 7 6800H、AMD Radeon(TM) Graphics、OpenGL `4.6.0 Core Profile Context 26.8.1.260806`、Zulu Java `17.0.13`、Forge `47.4.10`、GTCEu `7.5.3`。窗口为 `1280×720`，视距和模拟距离均为 `4`，快速画质、关闭云和 AO、最少粒子、关闭垂直同步、帧率上限 `120`、FOV `70`。这是本机开发依赖集合的结果，不能外推到其他 GPU、光影、大型整合包或普通 Forge 安装环境。

每组预热 `240` 帧、采样 `600` 帧，共两轮、每轮 15 组；第二轮旋转场景顺序。场景包括：无预览、单目标粉碎机、16 目标工程、15×15 熔炉；有预览时分别测静止、视角摆动、全量快照替换和每 10 tick 状态增量；大型熔炉另测完整及单层显示。16 目标工程切换前两个真实目标，其他单目标组重复替换该目标快照。增量组重放一格满足/缺失状态变化，用于测客户端更新路径，不代表实时施工或网络传输基准。

单目标和 16 目标工程均只提交当前选中的 `26` 格；大型结构为 `845` 格。相邻控制器是世界中的普通方块，不产生其他目标的全息。所有性能组均关闭界面并持有终端。

## 工具与口径

`--label` 只为报告命名，不切换源码。复现旧基线须使用报告中的旧源码快照；直接在当前实现上先后运行两个标签不会得到优化前后对照。

```text
python tools/benchmark_terminal_client.py --label baseline --offline
python tools/benchmark_terminal_client.py --label optimized --offline
python tools/benchmark_terminal_client.py --checks-only --offline
```

需要有图形桌面的 JDK 17 客户端环境；脚本使用仓库公共超时/进程树诊断工具。只有显式 `gseClientBenchmark=true` 才注册采样器并读取时钟及线程分配计数，普通客户端和服务端不采样。该模式拒绝与服务端验证或原人工验收客户端目录混用。

- `frame` 为相邻 RenderTick START 的真实墙钟间隔，包含限帧等待和其他客户端工作；不能直接归因于全息。FPS 仅能由同组帧间隔均值换算，P95/P99 以毫秒报告。
- `draw` 为全息渲染方法内部 CPU 提交时间；`ghost` 包含模型顶点及半透明批次提交，`outline` 包含轮廓顶点及提交。它们不等待 GPU 完成。
- `allocated_bytes` 为渲染线程在该方法内分配的字节数，不包含其他线程、显存或整帧分配；通过 JDK ThreadMXBean 采集。不支持时报告缺失，不伪造零值。
- 逐帧原始纳秒、字节数、绘制格数、状态更新次数、GC 次数、机器与 OpenGL 信息保存在 JSON。报告含全量 Java 源码快照与 SHA-256；Git HEAD 仍是上轮提交，因此必须用源码指纹标识本轮未提交实现。

预热与采样循环在前后对照中保持一致。基线首次脚本误把 FOV 序列化为 `70.0`，Minecraft 将非法值回退为默认 `70`；已核对本地 1.20.1 的 Options/OptionInstance 源码及启动日志。最终脚本使用正确序列化值 `0.0`，并在启动时显式设置 FOV `70`，有效视角一致。其他工具修正包括路径重定向保护和采样结束后的正确性检查，均不改变计时循环。状态更新次数及 GC 次数覆盖该组预热和采样全过程；耗时和分配的原始数组仅含 600 个采样帧。

隔离目录固定为 `build/verification/terminal-client/`，每次新建独立世界和报告目录；不读取或改写实际 `run/saves`、`run/config`、`run/options.txt` 及公开 beta.2 文件。原始报告和截图保留在构建目录，文档记录结果及定位方式。

## 优化内容

实测大型预览的模型提交是主要 CPU 段，分配约每帧 1.4 MB。原 AlphaVertexConsumer 依赖 VertexConsumer 默认批量方法：每个四边形创建亮度和光照数组，再把完整顶点拆成多个调用转发给底层消费者。调整为通过底层消费者的带透明度批量方法提交，复用只读亮度/全亮数组，继续执行 Forge 的烘焙光照、法线与模型查询。不缓存第三方动态模型或四边形。

透明度保留旧路径的字节取整：`0.18` 对应 `46`，`0.35` 对应 `89`；处理浮点往返，避免变成 `45` 或 `88`。状态颜色改为不可变常量；轮廓使用原始坐标参数，避免每格创建并变换三个 AABB；空快照直接跳过绘制。

本轮只改客户端渲染与显式基准入口，工程、材料、网络协议、服务端刷新和施工路径保持既有规则：每位玩家独立工程、只显示自己的选中预览、每 10 tick 刷新、主动操作立即响应、施工前实时重新校验材料。

### 未采用的试运行

首次优化复测 `20261015T121638Z-optimized-f3368fa0` 完成了 30 组采样，但在随后的 `clearLevel` 退出检查中，保存退出画面重入 RenderTick，导致基准采样数组越界。该次不作为验收通过的优化报告；原始数据、源码和日志保留，清理记录为 `.tmp/terminal-client-aborted-run-2026-10-15.json`。修正为退出检查前先禁用采样，最终复测须重新完成整组采样及离线检查。

复测 `20261015T122511Z-optimized-04b9bcb1` 又定位到开发依赖 Modern UI 默认 `screen.framerateInactive=30`：窗口失焦后，实际帧间隔从约 8.4 ms 改为 33.4 ms。该次中止并排除，记录见 `.tmp/terminal-client-background-limit-aborted-2026-10-15.json`。最终脚本只在隔离测试配置中将后台/最小化限帧关闭，保留普通实例的原配置；基线大型结构组的原始帧均值约 8.5 ms，与最终固定上限条件核对后再作对照。
