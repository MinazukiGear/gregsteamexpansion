# 焦炉与大型焦炉初步设计草案

本文档用于逐步设计 Greg Steam Expansion 对 GTCEu 现有焦炉的修改，以及它的上位多方块机器“大型焦炉”。当前只记录上游现状、设计目标、初步建议和后续决策顺序，不包含任何代码实现要求，也不表示机器已经定案。

## 文档状态与讨论规则

- 当前状态：初步构想，尚未定案，尚未实现。
- 当前基准环境：Minecraft `1.20.1`、Forge `47.4.10`、GTCEu Modern `7.5.3`。
- 本轮不修改 Java、资源、配方数据、Mixin、配置或已有设计文档。
- 后续每次只讨论一个边界明确的主题。我先给出推荐方案、理由、代价和备选方案，由用户最终决定。
- 除“GTCEu 7.5.3 现状”外，本文所有带有“建议”“候选”“待决定”字样的内容都不是实现要求。
- 只有用户明确确认的内容，才可在后续修订中移入“已确认设计”；不能因为某个方案被标为推荐就默认采用。
- 未完成前一步时，不提前锁定依赖它的结构尺寸、并行数、耗时、燃料或配方成本。

## 设计对象与初步目标

本设计包含两台具有明确上下位关系的机器：

1. 对 GTCEu 现有焦炉进行有针对性的调整，使其继续承担早期焦炭与杂酚油的起步生产，同时解决操作、自动化或平衡方面最终确认的问题。
2. 新增大型焦炉，作为现有焦炉的规模化升级，提供更高吞吐、更完整的自动化和更清晰的生产线接口。

初步建议是保留两台机器的分工，而不是让大型焦炉单纯成为“更快但更贵的同一个方块”：

| 维度 | 现有焦炉的建议定位 | 大型焦炉的建议定位 |
| --- | --- | --- |
| 科技职责 | 早期起步、少量生产、低维护 | 钢铁或蒸汽时代后段的连续批量生产 |
| 结构规模 | 保持紧凑 | 明显更大，并在外观上表现独立加热与多炉室 |
| 配方范围 | 基础木材、煤炭焦化 | 至少覆盖全部基础焦炉配方，可讨论扩展配方 |
| 吞吐方式 | 单配方、单并行 | 单配方多并行，或按炉室数量形成批量能力 |
| 动力与热量 | 倾向保留无外部动力的原始特征 | 候选为燃料加热、蒸汽辅助或蓄热运行，尚待决定 |
| 自动化 | 简单、可选 | 独立输入、固体输出和流体输出接口 |
| 产物倍率 | 保持配方原产物 | 优先提高吞吐，不直接无成本提高单份原料产率 |

## GTCEu 7.5.3 现状

以下内容来自当前项目实际依赖的 GTCEu `7.5.3` 源码，只作为后续设计的上游基线。

### 注册身份与结构

| 项目 | 上游现状 |
| --- | --- |
| 控制器 | `gtceu:coke_oven` |
| 控制器实现 | `CokeOvenMachine`，继承 `PrimitiveWorkableMachine` |
| 配方类型 | `gtceu:coke_oven` |
| 结构外壳 | `gtceu:coke_oven_bricks` |
| 专用仓 | `gtceu:coke_oven_hatch` |
| 外形 | 固定 `3×3×3` |
| 内部 | 正中心为 `1` 格空气 |
| 控制器位置 | 底层正面中央 |
| 其余结构位置 | 焦炉砖块，或最多 `5` 个焦炉仓 |
| 外部能源 | 不消耗 EU、蒸汽或燃料 |

完整结构共 `27` 格，其中 `1` 格为控制器、`1` 格为内部空气，剩余 `25` 格可由焦炉砖块和焦炉仓组成。上游只限制焦炉仓最多 `5` 个，没有要求必须放置焦炉仓，也没有为多个焦炉仓分配独立库存。

### 内部处理与自动化

- 配方类型最多接受 `1` 路物品输入，产生 `1` 路物品输出和 `1` 路流体输出，不接受配方流体输入。
- 机器内部具有 `1` 个物品输入槽、`1` 个物品输出槽和 `1` 个流体输出罐。
- 流体输出罐容量为 `32,000 mB`。
- 控制器界面可直接操作物品输入、物品输出和流体输出；玩家也可拿流体容器与控制器交互来抽取流体。
- 焦炉仓同时代理控制器的物品输入、物品输出和流体输出，并不是三种分离的专用接口。
- 多个焦炉仓访问的仍是同一组内部库存，不会增加槽位、储罐容量或并行能力。
- 焦炉仓每 `5 tick` 尝试向其正面相邻容器自动输出物品和流体。
- 上游焦炉按普通原始多方块配方逻辑运行；当前没有独立的温度、预热、燃料、维护或并行系统。

### 默认焦炉配方

| 配方 | 输入 | 物品输出 | 流体输出 | 耗时 |
| --- | --- | --- | ---: | ---: |
| 原木制木炭 | `1` 个可燃原木 | `1` 个木炭 | `250 mB` 杂酚油 | `900 tick`（45 秒） |
| 煤制焦炭 | `1` 个煤炭 | `1` 个焦炭 | `500 mB` 杂酚油 | `900 tick`（45 秒） |
| 煤块制焦炭块 | `1` 个煤炭块 | `1` 个焦炭块 | `4,500 mB` 杂酚油 | `8,100 tick`（405 秒） |

煤块配方的输入、输出、杂酚油和时间均为单个煤炭配方的 `9` 倍，因此它目前主要用于整块投料，不带额外速度或产率奖励。

### 当前可见的设计切入点

这些只是值得讨论的问题，不代表必须全部修改：

- 焦炉仓最多可放 `5` 个，但每个仓都代理同一份输入和输出，多仓的主要差异只是可连接方向更多。
- 单输入槽、单输出槽和单并行适合起步阶段，但无法自然承接中后期焦炭需求。
- `32,000 mB` 内部流体罐对起步足够；自动化不当时，杂酚油满罐可能成为停机点，因此需要明确“堵塞、保留或销毁”的规则。
- 机器完全不需要热源，操作简单，但大型焦炉若继续完全免费运行，较高并行可能缺少持续成本。
- 上游控制器、砖块、焦炉仓和配方已有固定资源 ID；任何替换方案都必须考虑旧世界结构、玩家库存和现有自动化。
- 现有煤块配方严格等价于九份煤炭配方。大型焦炉的并行计算不能让两条路径产生意外的时间或产率差。

## 总体设计方向建议

### 建议一：保留现有焦炉的身份与起步职责

建议继续使用上游 `gtceu:coke_oven` 作为下位机器，不额外注册一个功能重复的“本模组焦炉”。如果最终需要修改，应优先精确改变其结构资格、处理逻辑、界面提示或配方规则，同时尽量保留原控制器、砖块、仓和已有世界方块的身份。

这样做的主要好处是：

- 玩家已有焦炉和结构不必无理由报废；
- 任务书、配方查看器和其他模组对上游资源 ID 的引用更容易保持有效；
- “大型焦炉由普通焦炉升级而来”的关系更直观；
- 可以把新内容集中在真正有差异的大型焦炉上。

代价是后续实现需要精确划定上游覆盖边界，并为 GTCEu 版本变化准备兼容检查。是否采用这一兼容优先路线，仍需用户确认。

### 建议二：普通焦炉不以大幅强化为目标

建议普通焦炉继续保留以下核心特征：

- 固定 `3×3×3` 结构；
- 单配方、单并行；
- 不使用 EU；
- 产物数量沿用焦炉配方，不提供额外产率倍率；
- 允许手动使用，并保留一个简单的自动化入口。

优先讨论的改进应是规则清晰度和使用体验，例如：

- 焦炉仓究竟允许 `0–1` 个、`0–5` 个，还是拆分出专用接口；
- 满输出时是否在开工前完整预检；
- 中途输出被占满时是暂停、回退还是完成后等待输出；
- 是否在 GUI、物品提示和 Jade 中显示堵塞原因与预计完成时间；
- 是否继续允许控制器直接用流体容器抽取杂酚油。

不建议在尚未确定大型焦炉定位前，先给普通焦炉增加高并行、复杂温度或大量新配方，否则两台机器容易失去上下位差异。

### 建议三：大型焦炉主要出售“规模化能力”

大型焦炉的首要收益建议是：

1. 一次处理同一种配方的多份输入；
2. 在稳定供热后缩短批次时间；
3. 用独立接口可靠处理大量固体与杂酚油；
4. 以持续供热、预热时间、占地和建造成本换取吞吐；
5. 保持每份输入的基础产物守恒，使机器优势容易预测和调平衡。

首版不建议同时叠加“高并行、极限缩时、额外焦炭、额外杂酚油、低运行成本”五种优势。更稳妥的顺序是先确定目标吞吐，再选择两项主要优势和与之对应的成本。

## 现有焦炉的候选修改

### 身份和旧世界兼容

推荐候选：保留控制器、焦炉砖块、焦炉仓和配方类型的上游资源 ID，不自动把现有方块替换成本模组同名方块。

待决定：

- 已经成型且带有多个焦炉仓的旧结构，在新规则下是否继续有效；
- 若焦炉仓数量收紧，旧结构是立刻失效、给出迁移提示，还是保留兼容资格；
- 是否修改上游合成配方，以及修改后旧物品是否完全保留用途；
- 是否让其他模组新增到 `gtceu:coke_oven` 配方类型的配方自动进入两台机器。

### 结构与焦炉仓

候选 A：保持上游 `0–5` 个焦炉仓。兼容性最好，也允许从多个方向接管道，但结构规则略显松散。

候选 B（初步推荐）：允许 `0–1` 个焦炉仓。手动玩家可以不造仓，自动化玩家只需一个全功能仓；规则最容易理解，但会让已有多仓结构失效。

候选 C：保留旧焦炉仓只用于普通焦炉，并新增分离式物品输入、物品输出和流体输出接口。自动化最明确，但会显著抬高起步成本，也会增加本不需要的大量部件。

在确定仓数量前，应先确认普通焦炉是否仍要承担“只用一个仓完成全部自动化”的便利定位。

### 运行和输出安全

初步推荐以下语义，具体细节待逐项确认：

- 开始配方前同时确认输入足够，并确认最坏情况下的物品和流体输出都有空间。
- 配方开始时原子扣取本批次输入，避免部分扣取。
- 正常运行中不因管道短暂停顿而丢失进度；成品可在内部形成“待输出”状态，直到所有结果能够完整落入输出库存。
- 默认不销毁杂酚油，也不允许“流体满时继续产焦炭但吞掉副产流体”。
- 结构失效、区块卸载、世界重载和服务器重启后不得复制或丢失已经扣取的输入及待输出产物。

这些规则会提高可靠性，但“开工前预留全部输出”可能使拥有小型外部容器的机器更早停机。后续需要在严格预检与完成后等待之间二选一，不能两种语义混用。

### 配方与耗时

初步建议普通焦炉的三个上游基础配方先保持原产物和基准耗时，以便把大型焦炉的增益单独衡量。随后再讨论：

- 是否统一煤块配方与九份煤炭的批量调度语义；
- 是否补充其他原木、木制品、煤粉或矿物的焦化配方；
- 是否迁移或覆盖其他模组加入的焦炉配方；
- 工作强度是否影响耗时、产物、合成成本，或三档暂时相同。

## 大型焦炉的候选设计

### 暂定注册身份

以下命名仅作为讨论占位，不是已确认注册要求：

| 项目 | 暂定值 |
| --- | --- |
| 中文名 | 大型焦炉 |
| 英文名 | Large Coke Oven |
| 资源 ID | `gregsteamexpansion:large_coke_oven` |
| Java 机器类 | `LargeCokeOvenMachine` |
| 注册字段 | `LARGE_COKE_OVEN` |

建议让其控制器配方消耗 `1` 个上游焦炉控制器作为升级核心，借此明确上下位关系。具体外框材料、工具需求和是否需要钢制机器部件，应在科技阶段确定后再设计。

### 科技阶段

候选 A：青铜蒸汽时代中段。较早获得规模化焦炭，但可能压缩普通焦炉的使用寿命。

候选 B（初步推荐）：钢铁/高压蒸汽阶段。玩家已用普通焦炉完成第一批焦炭和钢，再用钢制结构与蒸汽基础设施换取规模化生产，上下位关系最清晰。

候选 C：低压电力阶段。更容易使用泵、传送带和电路解释自动化，但与本模组扩展蒸汽时代的核心方向较弱，也可能直接与电力焦化设备竞争。

### 结构路线

候选 A（首版稳妥方案）：固定尺寸结构，例如固定的炉体、燃烧层和空心焦化室。优点是结构验证、预览、自动搭建、平衡和测试更简单；缺点是后续只能通过改数值或另做机器扩展规模。

候选 B（主题表现更强）：固定截面、可变长度的炉组。长度决定焦化室数量和最大并行，能够直观表现“多炉室电池”；缺点是接口数量、并行公式、区块边界、结构预览和存档迁移都会更复杂。

候选 C：多个固定等级或不同尺寸。可提供明确升级台阶，但会增加控制器、配方、纹理和维护成本。

初步推荐先以候选 A 完成第一版设计，等完整运行规则稳定后再评估是否值得使用候选 B。若用户更看重大型工业炉组的视觉与扩建体验，则应在任何数值设计前直接选择候选 B，避免固定结构定案后返工。

### 热源与持续成本

大型焦炉不应默认沿用“高并行且完全免费”的运行方式。可选路线如下：

| 路线 | 说明 | 优点 | 主要代价 |
| --- | --- | --- | --- |
| 外部燃料加热 | 另设燃料输入，燃烧产生炉温 | 焦化与外部加热的主题明确 | 需要燃料白名单、热值、灰烬及断料规则 |
| 标准蒸汽供热 | 消耗 GTCEu 标准蒸汽推动或维持焦化 | 与本模组蒸汽基础设施衔接最好 | 蒸汽直接作为高温热源的表现需要合理包装 |
| 燃料加热 + 蒸汽辅助 | 燃料提供热量，蒸汽承担送风、循环或增速 | 机制层次丰富，适合大型设备 | 输入与状态复杂，首版设计和测试成本最高 |
| 无外部消耗、仅慢速预热 | 依靠启动等待换取后续并行 | 使用简单，不增加新燃料系统 | 一旦热稳态形成，长期吞吐几乎没有持续成本 |

当前不直接推荐最终路线。若目标是“纯蒸汽时代生产线”，优先比较标准蒸汽供热；若目标是“更接近工业焦化炉”，优先比较外部燃料加热。应先由用户确定玩法主题，再设计温度和消耗公式。

### 温度与预热

如果大型焦炉采用有持续成本的热源，初步建议加入简单而可解释的炉温状态：

- 冷炉不能立即满速运行，需要预热到启动温度；
- 达到启动温度后才能开配方，继续升温可以缩短处理时间，但不凭空提高产率；
- 停止供热后缓慢降温，短暂停机不应把全部预热投资清零；
- 结构失效时停止加热和加工，是否快速散热留待安全规则决定；
- 不建议首版同时模拟每个炉室的独立温度、气压和气体成分。

如果最终选择完全无外部消耗，则建议不再加入可长期白赚增速的复杂蓄热系统，只使用固定启动延迟或固定处理速度。

### 并行与速度

建议把“最大并行”和“处理时间倍率”分开决定：

- 最大并行表示一个批次最多处理多少份同一种配方；
- 处理时间倍率表示稳定运行后每份配方完成得多快；
- 实际并行应为最大并行、可用输入份数、输出空间和当前供热能力四者共同允许的最小值；
- 一个批次优先只执行同一种配方，避免多配方调度在第一版引入不可预测的输入争抢；
- 每份输入的焦炭、木炭和杂酚油原则上按原配方线性相乘；
- 煤炭块配方与九份煤炭配方在等量输入下应保持可解释的一致关系。

数值不应在结构和热源之前定案。确定目标后，应先填写如下吞吐预算表，再反推并行、耗时和消耗：

| 场景 | 普通焦炉基线 | 大型焦炉目标 | 允许的资源成本 |
| --- | ---: | ---: | ---: |
| 每分钟煤炭处理量 | 待实测/换算 | 待决定 | 待决定 |
| 每分钟原木处理量 | 待实测/换算 | 待决定 | 待决定 |
| 每分钟杂酚油产量 | 随配方 | 随目标吞吐 | 输出能力需覆盖 |
| 冷启动至首批完成 | `45` 秒加操作时间 | 待决定 | 受预热影响 |
| 稳态持续运行成本 | `0` | 待决定 | 燃料或蒸汽 |

### 输入输出与自动化

大型焦炉建议至少区分以下职责：

- 物品输入；
- 固体产物输出；
- 杂酚油流体输出；
- 若采用蒸汽供热，则另有蒸汽供给接口；
- 若采用燃料加热，则根据燃料形态决定固体燃料输入、流体燃料输入或统一燃烧室接口。

建议默认不允许控制器本体承担所有自动化，以免大型结构的接口设计失去意义。接口种类、最少和最多数量、是否复用本模组已经规划的通用仓室，以及是否兼容 AE2/ME，均应在热源确定后单独讨论。

### 配方范围

大型焦炉至少应能处理普通焦炉保留的全部基础配方。新增配方可分为三层讨论：

1. 等价兼容层：其他模组加入同一焦炉配方类型的合理配方是否自动可用；
2. 批量便利层：煤粉、木材批次或压缩物的等价焦化，不改变单位产率；
3. 大型炉专属层：只有大型焦炉能完成的新焦化或煤化工配方。

初步建议先完成前两层的规则，再讨论专属产物。否则机器结构、动力、并行和配方扩展会同时变化，难以判断平衡问题来自哪里。

### 故障与安全

后续至少需要明确以下状态，但现在不预设爆炸或惩罚：

- 输入不足；
- 固体输出堵塞；
- 杂酚油输出堵塞；
- 热源或蒸汽不足；
- 预热中；
- 主动暂停；
- 结构失效；
- 区块卸载与世界重载；
- 控制器被拆除；
- 工作强度合法降档后已有温度和进行中批次如何处理。

建议先以“停机且不吞物、不吞流体、不复制产物”为安全底线，再由用户决定是否增加降温、进度回退、排放、着火或爆炸等额外后果。

## 工作强度接入占位

按照现有[全局工作强度设计](difficulty.md)，本设计最终必须显式声明 Easy、Normal、Expert 三档行为，即使三档暂时使用相同值。

候选受控字段包括：

- 普通焦炉控制器、焦炉砖块和焦炉仓的获取成本；
- 普通焦炉的配方耗时；
- 大型焦炉控制器、结构方块和专用接口的获取成本；
- 大型焦炉的预热成本、维持消耗、最大并行和处理时间倍率；
- 是否允许某些扩展配方以及其产率。

已经存在的全局规则仍应作为约束候选：本模组多方块控制器三档固定产出 `1` 个，本模组新增仓室三档固定产出 `1` 个。大型焦炉具体哪些数值随工作强度变化，要在普通与大型两台机器的 Normal 基线完成后再设计，不宜现在猜测。

## 推荐的详细设计顺序

后续建议严格按以下顺序推进。每一步完成后，先把用户确认的结果写回本文档，再进入下一步。

### 第 1 步：确定要解决的问题与不改内容

需要用户决定：

- 对普通焦炉最不满意的是速度、自动化、结构、免费运行、储罐，还是其他问题；
- 哪些上游体验必须原样保留；
- 大型焦炉最重要的两个卖点是什么。

本步产出：一份按优先级排序的目标清单，以及一份明确的“不在本次设计范围”清单。

先做本步的原因：只有先确定痛点，后面的结构和数值才不会为了增加机制而增加机制。

### 第 2 步：确定上游修改与旧世界兼容边界

需要用户决定：

- 是否保留 `gtceu:coke_oven` 及其配套方块的身份；
- 已放置结构和已有物品需要达到什么兼容程度；
- 焦炉仓数量和职责是否改变；
- 是否接受精确覆盖上游配方或行为。

本步产出：上游对象的“保留、修改、禁用、新增”矩阵，以及旧存档迁移原则。

### 第 3 步：确定两台机器的科技阶段与上下位关系

需要用户决定：

- 普通焦炉应服务到哪个阶段；
- 大型焦炉位于青铜蒸汽、钢铁/高压蒸汽还是低压电力阶段；
- 大型控制器是否消耗普通焦炉控制器作为升级核心；
- 大型焦炉出现后，普通焦炉是否仍保留低成本或无动力优势。

本步产出：科技树位置、解锁条件和两台机器的职责对照表。

### 第 4 步：冻结配方集合与单位产物语义

需要用户逐项决定基础配方是否保留、修改或移除，再决定是否接受外部同类型配方和大型炉专属配方。

本步产出：每条配方的输入、固体输出、流体输出、基准耗时、适用机器及兼容来源。此时只定义单位配方，不先乘并行。

### 第 5 步：完成普通焦炉规则

依次确定：

1. 结构和焦炉仓数量；
2. 手动交互与自动输入输出；
3. 开工扣取和输出堵塞语义；
4. 暂停、结构失效、重载和拆除；
5. GUI、提示和运行反馈；
6. 三档工作强度差异。

本步产出：一台可以独立实现和验收的普通焦炉完整规格。

### 第 6 步：选择大型焦炉结构路线

先在固定尺寸、可变长度或多等级结构中三选一，再绘制逐层结构图。结构图必须明确控制器、内部空气、固定核心、外壳、加热层和所有接口的合法位置及数量。

本步产出：完整结构谓词、代表布局、预览规则和自动搭建边界，但暂不填最终吞吐数值。

### 第 7 步：确定大型焦炉热源和温度系统

依次确定：

1. 使用燃料、蒸汽、混合热源或无外部消耗；
2. 可接受资源的精确白名单或标签边界；
3. 冷炉、预热、可开工、满速和冷却状态；
4. 每 tick 扣取还是按批次预扣；
5. 断供、恢复、主动暂停和结构失效的温度行为；
6. 是否存在排放、着火、爆炸或其他安全后果。

本步产出：可以用示例逐 tick 演算的状态机和资源守恒规则。

### 第 8 步：反推并行、速度和资源消耗

先由用户给出希望的大致吞吐或相对普通焦炉的倍率，再设计：

- 最大并行；
- 实际并行选择；
- 温度或结构对耗时的倍率；
- 每批及每 tick 的供热成本；
- 输出空间的最坏情况预检；
- 煤炭与煤炭块配方的一致性。

本步必须用至少三组完整示例验证：输入不足、满并行稳态、运行中断供。所有例子都应列出扣取输入、耗时、消耗和最终输出。

### 第 9 步：确定接口与自动化

需要确定每种接口的最少数量、最多数量、容量、速率、方向、封面行为、主动输入输出和是否允许共享。随后再讨论 AE2/ME 等可选兼容，不能让可选模组成为基础结构的硬依赖。

本步产出：结构接口表、自动化时序和所有满仓/断管行为。

### 第 10 步：设计控制器与部件的获取方式

在科技阶段、结构和接口全部确定后，再设计有序合成、组装机配方和材料成本。控制器配方是否消耗普通焦炉应在此落实；配方还需检查镜像、标签替代、工具槽和现有配方冲突。

本步产出：Easy、Normal、Expert 三档的完整获取配方和资源 ID 清单。

### 第 11 步：完成界面、提示与表现

需要覆盖：

- 控制器 GUI 的输入、输出、温度、热源、并行、进度和故障信息；
- 默认物品提示与按住 Shift 的完整说明；
- Jade/探针信息及服务端同步范围；
- 空闲、预热、工作、暂停、堵塞和故障的纹理、粒子与声音优先级；
- 色盲和无声音条件下仍可识别的状态表达。

本步产出：玩家无需阅读源码即可判断机器为什么不工作的完整信息规范。

### 第 12 步：兼容、迁移与验收设计

最后编写：

- 上游版本核验点；
- 旧世界与进行中配方迁移；
- 配方查看器和任务引用；
- 数据包与其他模组配方接入边界；
- 单元测试、GameTest 和用户手工验收矩阵；
- 性能边界、区块卸载和服务器重启测试。

只有本步完成后，设计才具备进入代码实现阶段的条件。进入实现前仍需由用户再次明确授权。

## 建议从哪里开始

下一轮建议只处理“第 1 步：确定要解决的问题与不改内容”，暂不讨论具体结构尺寸和数值。

我建议的初始目标排序为：

1. 大型焦炉提供可靠的批量吞吐和独立自动化接口；
2. 普通焦炉保持早期价值与低门槛，并修正最终确认的易用性问题；
3. 两台机器对同一份基础原料保持可预测的产物守恒；
4. 大型焦炉通过占地、建造成本、预热和持续供热中的若干项支付吞吐优势；
5. 兼容已有 `gtceu:coke_oven` 方块、配方和世界数据；
6. 新的专属焦化产物、复杂污染和极端事故机制暂放在首版范围之外。

以上排序全部属于建议，等待用户逐项保留、调整或否决。
