# 焦炉与大型焦炉设计

本文档记录 Greg Steam Expansion 对 GTCEu 现有焦炉及其上位多方块机器“大型焦炉”的设计。普通焦炉、焦炉仓和大型焦炉的全部设计步骤（第 1 至第 10 步、第 11A 至第 11E 步、第 12A 至第 12E 步）已经定案。本文档当前不授权任何代码实现。

## 文档状态与讨论规则

- 当前状态：普通焦炉与焦炉仓已定案；大型焦炉的身份、结构、运行、安全、表现、获取配方、建造成本、工作强度、物品属性、兼容、迁移及验收边界已全部定案；进入代码实现前仍需用户再次明确授权。
- 当前基准环境：Minecraft `1.20.1`、Forge `47.4.10`、GTCEu Modern `7.5.3`。
- 两个“已确认设计”章节是后续实现依据；本文档已无未确认讨论清单，文末章节只记录定案状态与实现门槛。
- 实际游戏测试与最终验收由用户执行；进入代码实现前仍需用户另行明确授权。

## 普通焦炉与焦炉仓已确认设计

### 焦炉与焦炉仓的身份及修改边界

- 继续保留并使用 GTCEu 现有焦炉控制器 `gtceu:coke_oven`，不注册一个功能重复的 `gregsteamexpansion` 版普通焦炉。
- 继续保留并使用 GTCEu 现有焦炉仓 `gtceu:coke_oven_hatch`，不注册一个功能重复的 `gregsteamexpansion` 版普通焦炉仓。
- 继续保留并使用 GTCEu 现有焦炉砖块 `gtceu:coke_oven_bricks`，不以本模组同名方块替换现有结构外壳。
- 后续对普通焦炉和焦炉仓的改动直接作用于上述精确的 GTCEu 注册对象，范围可以包含结构资格、交互和运行行为；不能按名称模糊匹配或批量修改其他原始多方块机器及仓室。
- 已存在于玩家物品栏、容器和世界中的上述物品与方块原则上继续保留原注册身份和用途，不进行无必要的方块或物品替换。
- GTCEu 的任务、配方、配方查看器条目及其他内容对上述资源 ID 的既有引用，应尽可能保持有效。
- 大型焦炉不复用普通焦炉的注册身份，作为 `gregsteamexpansion:large_coke_oven` 新增多方块控制器独立注册。
- 本项决定只确认注册身份和上游修改边界，不代表现有焦炉结构在修改后必然继续成型。旧结构兼容程度必须等焦炉仓职责、合法数量和结构规则确定后单独决定。

### 可配置焦炉仓

`gtceu:coke_oven_hatch` 保留原注册身份，但改为只有以下三种互斥模式；不新增拆分仓、综合模式或关闭模式。

| 模式 | 正面对外能力 | 明确拒绝 |
| --- | --- | --- |
| 物品输入 | 外部可插入合法焦炉原料 | 抽取物品及全部流体能力 |
| 物品输出 | 外部可抽取固体产物 | 插入物品及全部流体能力 |
| 流体输出 | 外部可抽取配方流体产物 | 流体输入及全部物品能力 |

#### 模式与工具交互

- 新放置的仓默认为物品输入，模式由仓自身持久化；区块卸载、世界重载和服务器重启后保持。
- 潜行使用螺丝刀按“物品输入 → 物品输出 → 流体输出”循环；非潜行螺丝刀优先操作覆板或上游部件，其他工具、空手和普通物品不能切换模式。
- 服务端对一次交互去重。切换成功后才消耗正常工具耐久、播放螺丝刀声并向操作者显示新模式；拒绝时保持原模式、不消耗耐久，并播放轻微失败声和显示原因。
- 未成型或非运行、非待输出的焦炉允许切换；正在推进或持有待输出结果时锁定全部仓模式，不存在通过主动暂停绕过的路径。
- 正面以相同形状的绿色、橙色、蓝色方框分别表示物品输入、物品输出和流体输出；文字识别由 Jade 与操作栏提供。全部文本使用本地化键，至少提供简体中文和英文。

#### 朝向、传输与覆板

- 仓保留上游六面朝向，扳手可正常旋转；模式标志、能力和覆板均只作用于当前正面。运行或待输出时旋转只改变物流方向，不改变批次、库存、模式或成型状态。
- 物品输入模式只被动接受插入，不主动抽取；两种输出模式允许外部从正面抽取，并每 `5 tick` 向正面相邻目标主动推送对应产物。
- 主动传输失败时未转移内容完整留在焦炉内，不掉落、不销毁、不覆盖目标，也不回退批次；`5 tick` 周期不限制外部设备主动访问的频率。
- 正面支持 GTCEu 合法覆板。覆板只能过滤、限速、关闭或以红石条件控制当前模式已有的物流，不能增加能力、反转输入输出、切换模式或暂停加工；模式筛选同时约束主动推送与外部能力访问。
- 仓旋转或模式改变后立即刷新能力，覆板按新正面及新模式重新取交集；不兼容功能保持无效。成功旋转沿用上游工具反馈，被拒绝时不消耗耐久。

#### 数量、共享库存与旧存档

- 每座普通焦炉允许 `0–5` 个仓，不要求三种模式各一个，也不限制单种模式数量；零仓时仍可手动操作，至少三个仓分别设置三种模式即可实现完整自动化。
- 全部仓代理控制器的同一组输入、固体输出和流体输出库存；增加仓只增加连接方向，不增加槽位、储罐容量、并行或单份产量。
- 缺少模式数据的旧仓统一初始化为物品输入并立即持久化，不根据相邻设备或库存猜测，不提供临时综合模式，也不移动、清空、转换库存或改变批次。
- 每个存档首次发现旧仓迁移时只发送一次概括性系统提醒并记录日志，提示玩家用螺丝刀重新配置；后续旧仓不逐个刷屏。
- 原有 `0–5` 仓结构继续有效，唯独位于底层几何中心的旧仓必须移到其他合法外壳位置，并把该中心恢复为焦炉砖；迁移不会自动恢复旧自动化方向。


### 普通焦炉结构

- 普通焦炉继续使用 GTCEu 7.5.3 原有的固定 `3×3×3` 结构，不扩大、缩小或改为可变尺寸。
- 整座结构共占用 `27` 格；正中心固定为空气，不能用焦炉砖块、焦炉仓或其他方块填充。
- 控制器固定在底层正面中央，结构可以随控制器朝向面向四个水平方向搭建。
- 内部中心空气格正下方的底层几何中心位置固定使用 `gtceu:coke_oven_bricks`，不能替换为焦炉仓或其他方块。
- 除中心空气、控制器和上述固定焦炉砖外，其余 `24` 个结构位置使用 `gtceu:coke_oven_bricks`，或按照已确认规则替换为总计 `0–5` 个可配置焦炉仓。
- 不为普通焦炉增加烟囱、独立燃烧室、维护口、蒸汽仓、能源仓或其他固定结构核心。
- 更新前已经符合上述结构、使用 `0–5` 个焦炉仓且底层几何中心原本就是焦炉砖的旧焦炉，更新后不需要拆除、移动或重新摆放结构方块。
- 底层几何中心原本使用焦炉仓的旧结构是唯一由该固定位置规则引入的结构兼容例外；玩家需要把该仓移到其余 `24` 个合法外壳位置之一。
- 本项只确认结构组成，不决定动力、配方、处理速度、内部容量、运行状态或安全规则。

### 普通焦炉结构独占

- 普通焦炉的所有结构位置均不可共用，不能同时参与另一座普通焦炉、大型焦炉或其他多方块结构。
- 独占范围包含控制器、全部焦炉砖外壳、固定底层中心焦炉砖、所有焦炉仓以及内部中心空气格所在坐标。
- 普通焦炉使用的是普通 `gtceu:coke_oven_bricks` 也不改变独占规则；同一个焦炉砖方块不能同时被两个结构图案计数。
- 同一个焦炉仓同一时刻只能连接一座普通焦炉，不能把同一组内部库存代理给多个控制器。
- 两座多方块结构的占用体积只要有任意一个坐标重叠，后尝试成型的普通焦炉就不能成型，并显示结构重叠原因。
- 两座普通焦炉不能让外表面直接相邻或贴靠；两座 `3×3×3` 结构的外表面之间必须至少保留一整格间隔。
- 判定时把每座普通焦炉的 `3×3×3` 占用包围盒向六个方向各扩展一格作为间距排斥范围；另一座普通焦炉的占用包围盒不能与该范围相交。面对面、边对边或角对角的直接贴靠都不合法。
- 一格间隔只限制另一座普通焦炉的结构占用位置，不要求该间隔始终为空气；普通管道、容器和其他不属于焦炉结构的方块可以放在间隔内。
- 间距规则对水平并排、竖直堆叠和任意朝向的普通焦炉统一生效，不能通过旋转控制器绕过。
- 普通焦炉与未来大型焦炉之间需要保留多少间隔，留到大型焦炉结构设计时确认，不由本项提前决定。
- 一座焦炉结构失效或控制器被拆除后，其焦炉仓解除控制器连接但继续保存自身模式；未连接期间不接受或输出任何机器库存。
- 结构解除后，原占用位置可以被另一座多方块结构使用；重新连接的焦炉仓继续使用解除前保存的模式。
- 每座成功成型的普通焦炉记录其独占的 `27` 个结构坐标及一格间距排斥范围；间距排斥范围不取得其中普通方块的所有权，只阻止另一座普通焦炉在该范围内成型。
- 已经成功成型的焦炉优先保留占用权，后尝试成型、与现有独占范围重叠或违反一格间距的焦炉不能成型。
- 区块卸载和服务器重启期间继续保存结构占用与间距排斥记录，不能借卸载让另一控制器抢占。
- 只有在相关区块已经加载并确认结构真正失效，或控制器被拆除后，才释放该焦炉的占用与间距排斥记录。
- 旧世界首次迁移时，如果多个原本成型的焦炉互相重叠或直接贴靠，则按控制器坐标 `(X, Y, Z)` 从小到大排序，坐标最小者优先取得占用权。
- 其他冲突焦炉进入结构无效状态，并显示“与另一多方块结构重叠”或“与另一焦炉间距不足”的具体原因；进行中配方按一般结构失效规则回退至 `1 tick`。
- 优先焦炉被拆除、移动或真正失效并释放占用后，其他控制器可以重新执行结构检查；满足结构与间距规则时正常成型。
- 保存数据中发现控制器已经不存在的陈旧占用记录时，必须等控制器所在区块实际加载并确认方块缺失后再释放，不能仅因区块暂时不可用删除记录。

### 普通焦炉与大型焦炉的动力、温度及启动边界

- 普通焦炉和大型焦炉均无需任何外部能源即可运行。
- 两台机器均不消耗 EU、GTCEu 标准蒸汽、其他蒸汽、固体燃料、液体燃料、燃气或专用热媒。
- 两台机器均不要求能源仓、蒸汽供给仓、燃料输入仓或其他只为提供运行能源而存在的结构接口。
- 不允许在实现中把配方输入的一部分隐藏扣除为燃料，也不允许以减少焦炭、木炭或杂酚油产量的方式暗中支付运行能源。
- 普通焦炉和大型焦炉都不具有炉温、预热、升温、满温、蓄热或冷却状态，也不保存任何相关进度。
- 两台机器在结构有效且配方开工条件满足时均可立即开始配方，不设置冷启动等待或固定启动延迟。
- 两台机器的处理速度在一次配方中保持固定，不因连续运行时间、空闲时间、结构温度或环境温度动态变化。
- 无外部能源和无预热不等于两台机器必须具有相同吞吐。大型焦炉的优势和约束改由结构占地、建造成本、最大并行和固定处理时间承担。

### 普通焦炉并行

- 普通焦炉的最大并行固定为 `1`，每次只执行一份焦炉配方。
- 输入槽中堆叠多个相同原料时，机器也只为当前批次扣取并处理一份配方所需的数量，不把剩余堆叠自动合并为多并行批次。
- 当前批次完成并按照后续确定的输出规则处理完产物后，机器才能选择并开始下一份配方。
- 煤炭块制焦炭块仍被视为一份独立的焦炉配方；它不会在运行层被拆成九份煤炭配方，也不表示普通焦炉获得九并行。
- 使用多个焦炉仓不会增加最大并行、配方槽位或单次输入数量。
- 普通焦炉不通过连续运行、额外仓室、工作强度或任何环境条件提高并行；批量并行能力保留给大型焦炉设计。
- 本项只确认普通焦炉的并行语义，不决定三个基础配方是否保持上游耗时，也不决定批次开始和完成时的输入输出原子性。

### 普通焦炉基础配方耗时

- 普通焦炉的三个 GTCEu 7.5.3 基础焦炉配方继续使用上游固定耗时，不因本模组工作强度、连续运行时间、焦炉仓数量或环境条件变化。

| 配方 | 固定耗时 |
| --- | ---: |
| 原木制木炭 | `900 tick`（45 秒） |
| 煤制焦炭 | `900 tick`（45 秒） |
| 煤炭块制焦炭块 | `8,100 tick`（405 秒） |

- 煤炭块配方的固定耗时严格为单个煤炭配方的 `9` 倍，不提供整块投料的批量速度奖励。
- 每份配方从 `0` 进度运行至完成所需的 tick 数固定不变；结构失效或输出等待如何影响已有进度，仍由后续运行状态规则决定。
- 本项只确认耗时，不提前确认单位输入、物品输出、流体输出、扩展配方范围或大型焦炉的耗时倍率。

### 普通焦炉基础配方输入与产物

- GTCEu 7.5.3 自带的三个基础焦炉配方继续保留原单位输入、物品输出和流体输出。

| 配方 | 单位输入 | 必定物品输出 | 必定流体输出 |
| --- | --- | --- | ---: |
| 原木制木炭 | `1` 个属于可燃原木标签的原木 | `1` 个木炭 | `250 mB` 杂酚油 |
| 煤制焦炭 | `1` 个 GTCEu 煤炭宝石输入 | `1` 个焦炭 | `500 mB` 杂酚油 |
| 煤炭块制焦炭块 | `1` 个 GTCEu 煤炭块输入 | `1` 个焦炭块 | `4,500 mB` 杂酚油 |

- 上表所有物品与流体产物均为必定产出，不设置概率副产物。
- 同一行中的物品与流体组成不可分割的一份配方结果；玩家不能选择只生产物品或只生产流体，也不能通过缺少某种输出接口主动放弃另一种产物。
- 普通焦炉不对基础配方增加额外焦炭、木炭或杂酚油倍率。
- Easy、Normal、Expert 三档的单位输入和单位产物完全相同，工作强度不改变上表数值。
- 煤炭块配方的输入、物品输出和杂酚油输出严格为单个煤炭配方的 `9` 倍，与已经确认的九倍耗时保持一致。
- 本项未由本模组新增其他焦化配方；外部焦炉配方的兼容规则见下文。

### 普通焦炉的外部配方兼容

- 普通焦炉继续读取完整的 `gtceu:coke_oven` 配方类型，不为修改后的焦炉另建一份只包含本模组配方的封闭配方类型。
- 数据包或其他模组加入 `gtceu:coke_oven` 配方类型的合法配方可以自动被普通焦炉识别，不按配方命名空间设置白名单或黑名单。
- 外部配方必须符合该焦炉配方类型的接口范围：最多 `1` 路物品输入、`1` 路物品输出、`0` 路流体输入和 `1` 路流体输出。
- 普通焦炉严格采用外部配方自身声明的输入、输出和固定耗时，不把三个 GTCEu 基础配方的数值套用到外部配方。
- 焦炉仓物品输入模式根据服务端当前已经加载的合法焦炉配方动态判断可插入物品，不能只硬编码原木、煤炭和煤炭块。
- 焦炉仓流体输出模式允许抽取或主动推送合法焦炉配方实际产生的任意流体，不把流体能力硬编码为只能输出杂酚油。
- 格式非法、超出接口范围或无法满足焦炉处理约束的配方不能启动，并需要记录能够定位配方资源 ID 和拒绝原因的明确错误。
- 本阶段不由 Greg Steam Expansion 新增其他焦化配方；以后若增加，也应注册到同一个配方类型并遵守相同接口范围。
- 外部配方是否同样提供给大型焦炉，在大型焦炉的配方范围阶段正式确认，不由本项自动决定。

### 普通焦炉的配方启动与输出原子性

- 普通焦炉准备开始配方时，必须先确认一份完整配方所需的全部输入均可用。
- 机器同时按照配方可能产生的最坏情况，预检内部物品输出和流体输出是否能够完整容纳本批次的所有结果；概率输出也按能够全部产生的情况预留空间。
- 输入不足、输出类型不兼容或任一输出空间不足时，配方不启动、不扣取任何输入，进度保持为 `0`。
- 所有开工条件满足后，机器以一次原子操作扣取本批次的完整输入并开始计时；不允许只扣取部分输入或在后续 tick 分段扣取。
- 配方运行期间必须为当前批次保留已经预检的输出空间。控制器、焦炉仓及其他能力访问均不允许外部设备向物品输出库存或流体输出库存插入内容。
- 配方完成时，物品结果和流体结果作为同一份不可分割的结果整体提交。正常路径不能先写入一种结果，再因另一种结果失败而留下半完成状态。
- 若异常自动化、兼容组件或其他非正常状态仍导致完成结果无法整体写入，机器必须把完整结果保存为“待输出结果”，停止开始新配方，并在空间恢复后再次尝试整体提交。
- 进入待输出状态后不能再次扣取输入、重新计算概率、重复生成结果或回退成未完成配方。
- 待输出结果及其状态必须持久化，在区块卸载、世界重载和服务器重启后准确恢复，不能丢失或复制。
- 待输出结果完整提交后，机器清除该状态，才可以寻找并开始下一份配方。
- 待输出状态下不允许切换焦炉仓模式；结构失效和控制器拆除时分别按照本文后续已经确认的对应规则处理进行中配方与待输出结果。

### 普通焦炉内部库存

- 普通焦炉保留 `1` 个物品输入槽、`1` 个物品输出槽和 `1` 个流体输出罐。
- 物品输入槽和物品输出槽均遵守槽内物品自身的正常最大堆叠数量，不额外提高至超出物品上限的数量。
- 流体输出罐的固定容量为 `32,000 mB`。
- 普通焦炉不设置流体输入罐，也不接受任何配方流体输入。
- 放置更多焦炉仓不会增加物品槽数量、物品槽容量、流体罐数量或流体罐容量。
- 物品输出槽和流体输出罐只允许焦炉提交配方结果，以及玩家或合法自动化向外抽取；控制器、焦炉仓和其他能力路径均不允许外部向其中插入物品或流体。
- 物品输入槽只接受能够匹配服务端当前已加载合法焦炉配方的物品。输入过滤规则与焦炉仓物品输入模式保持一致。
- 任何配方若在最坏情况下无法被一个正常物品输出槽和 `32,000 mB` 流体输出罐完整容纳，就不能在普通焦炉中启动。
- 内部库存的实际内容和待输出结果分别持久化，不能把待输出结果临时塞入输入槽或使用隐藏扩容绕过上述固定容量。

### 普通焦炉控制器交互

- 普通焦炉控制器 GUI 允许玩家手动向物品输入槽放入能够匹配合法焦炉配方的原料。
- 玩家可以通过控制器 GUI 手动取出物品输出槽中的固体产物。
- 玩家可以通过控制器 GUI 的流体槽，或手持兼容的空流体容器与控制器交互，抽取流体输出罐中的产物。
- 控制器不允许玩家或外部设备向流体输出罐灌入流体；手持装有流体的容器不能把内容倒入焦炉输出罐。
- 焦炉实际推进配方时仍允许打开控制器 GUI、补充输入槽和抽取内部已经存在的物品或流体产物。这些操作不能改变当前批次已经原子扣取的输入、固定耗时或待提交结果。
- 控制器的任意面均不向管道、漏斗、机械臂、封面或其他自动化设备暴露物品或流体传输能力。
- 所有外部自动化输入和输出必须经过处于对应模式的焦炉仓，不能通过控制器侧面、背面、顶部或底部绕过仓模式。
- 因此，使用 `0` 个焦炉仓的合法结构仍可完全手动运行，但不能进行物品或流体自动化。
- 本项只确定控制器的库存交互边界；普通焦炉不提供主动暂停，具体规则见下文。

### 普通焦炉不提供主动暂停

- 普通焦炉不提供任何由玩家或自动化主动暂停加工的功能。
- 软锤不能切换普通焦炉的“允许工作”状态，控制器 GUI 不设置工作启停按钮，也不接受红石信号作为暂停控制。
- 对普通焦炉使用软锤或其他未定义的工作控制工具时，不改变机器状态、不消耗工具耐久，也不重置或中断当前配方。
- 配方开始后，在结构保持有效且世界区块正常加载的情况下持续推进至完成；玩家不能主动冻结进度以调整仓模式、输出或其他运行条件。
- 普通焦炉因没有新输入而处于空闲、因开工预检失败而无法启动、因结构失效而停止，或因待输出结果无法提交而锁定，都属于被动状态，不视为主动暂停。
- 运行中的配方和待输出结果均继续锁定所有已连接焦炉仓的模式；不存在先暂停机器再使用螺丝刀切换模式的绕过方式。
- 普通焦炉没有进行中配方且没有待输出结果时，玩家仍可按照既定规则切换焦炉仓模式。
- 本项不自动决定大型焦炉是否提供主动暂停；大型焦炉的工作控制在其自身设计阶段处理。

### 普通焦炉结构失效

- 控制器仍然存在，但任一必要结构方块被破坏、移除或替换为不合法方块时，普通焦炉立即进入结构失效状态。
- 一般结构失效时，机器停止推进配方、不寻找新配方、不尝试提交待输出结果，也不执行焦炉仓主动传输。
- 一般结构失效会保留当前锁定配方、已经原子扣取的输入身份、固定耗时、最终产物参数和待输出结果，但把进行中配方的当前进度回退至 `1 tick`。
- 结构重新满足合法图案后，机器从 `1 tick` 继续原批次，不重新搜索配方、不重新扣取输入，也不重新计算概率或产物。
- 如果结构失效前已经处于待输出状态，则完整保留待输出结果；重新成型后继续尝试整体提交，不回到加工阶段。
- 上述一般规则不适用于下述“底层中心焦炉砖被拆除”的特殊情况。

底层中心焦炉砖具有特殊清空规则：

- “底层中心”指 `3×3×3` 结构底层的几何中心，即内部中心空气格正下方的位置；它不是底层正面中央的焦炉控制器。
- 该位置的焦炉砖被玩家、爆炸、活塞、命令或其他方式拆除或替换时，不使用一般结构失效的批次保留规则。
- 普通焦炉立即取消当前加工和待输出状态，把进度重置为 `0`，清除已经锁定的配方、耗时、概率结果及其他批次参数。
- 内部流体输出罐和待输出结果中已经存在的全部流体直接丢失，不限于杂酚油；不生成流体方块、流体容器、掉落物或可恢复数据。
- 当前配方尚未完成时，取消配方后不再生成其原本计划产生的流体；当前配方已经完成并进入待输出状态时，待输出流体同样全部清空。
- 物品输入槽、物品输出槽中的全部物品，以及待输出结果中已经生成的全部固体产物，都以正常物品实体掉落在焦炉附近，不保留在控制器或焦炉仓中。
- 当前配方已经原子扣取但尚未完成时，机器需要保存并掉落本批次实际扣取的原物品；不能生成完成产物，也不能按标签替换成另一种等价物。
- 物品掉落和杂酚油清空必须只执行一次；后续区块重载、再次破坏其他结构方块或重新成型不能重复生成物品。
- 焦炉仓各自保存的模式不因该清空事件重置；重新搭建后仍使用原模式。
- 被拆除的焦炉砖本身是否产生方块掉落，继续遵守 Minecraft/Forge 和其战利品表的正常方块破坏规则，与机器内部物品掉落分开处理。
- 底层几何中心固定使用 `gtceu:coke_oven_bricks`，不属于焦炉仓可替换位置。其余 `24` 个外壳位置继续共同允许 `0–5` 个焦炉仓。
- 外部配方产生的非杂酚油流体也遵守相同清空规则，不能因流体种类或配方命名空间绕过该事件。

### 普通焦炉区块卸载与世界重载

- 普通焦炉控制器或结构所需区块未加载期间，机器不推进当前配方、不寻找或开始新配方、不提交待输出结果，也不执行焦炉仓主动传输。
- 机器不按照区块卸载时长、退出世界时长或服务器关闭时长补算离线进度、批次数量、物品产物或流体产物。
- 卸载前必须持久化当前锁定配方、实际扣取输入、固定耗时、当前准确进度、已经确定的概率结果、内部物品与流体库存以及完整待输出结果。
- 正常重新加载且结构仍然合法时，从卸载前保存的准确进度继续同一批次，不回退至 `1 tick`、不重新扣取输入，也不重新计算配方或概率结果。
- 单纯的区块卸载、退出世界或服务器重启不视为结构失效，不能因此触发一般结构失效回退或底层中心焦炉砖的特殊清空规则。
- 重新加载后若结构检查发现实际结构已经不合法，才进入一般结构失效状态，并按照该规则把进行中配方进度回退至 `1 tick`。
- 待输出状态跨区块卸载、世界重载和服务器重启完整保留；重新加载后仍锁定焦炉仓模式，并在结构合法时继续尝试整体提交。
- 焦炉仓各自保存的模式正常恢复。主动传输计时从重新加载后的正常调度继续，不补做卸载期间错过的传输次数。
- 重载恢复只能在服务端完成并同步结果；客户端显示不能自行补算进度或推测离线产物。

### 旧版进行中配方迁移

- 首次使用本设计的新逻辑加载旧存档时，若普通焦炉存在由 GTCEu 旧逻辑保存的进行中配方，则取消该旧批次并把进度重置为 `0`。
- 旧逻辑已经扣取的该批次输入不返还，也不生成原配方计划产生的任何物品或流体结果。
- 迁移只取消进行中批次；输入槽剩余物品、物品输出槽、流体输出罐、控制器方块和焦炉结构中的既有内容与方块全部保留。
- 取消旧批次后，控制器进入持久化的“等待重新输入”状态。即使输入槽中还保留能够匹配焦炉配方的物品，也不能自动开始工作。
- 必须在迁移完成后，通过控制器 GUI 或物品输入模式焦炉仓成功插入至少一个合法焦炉配方原料，才能解除“等待重新输入”状态。
- 仅查看 GUI、抽取已有输入、改变相邻容器、重新加载区块或让输入槽中的旧堆叠保持不变，都不能解除该状态。
- 输入槽已经达到堆叠上限、无法直接再插入时，玩家或自动化需要先取出至少一个物品，再重新插入合法原料；只有成功插入事件才算重新输入。
- 一次合法重新输入解除锁定后，机器按照输入槽当时的完整内容正常重新匹配配方，不要求以后每个批次都重复执行额外解锁。
- “等待重新输入”标记需要跨区块卸载和服务器重启保存，不能通过重载绕过；解除后也要立即保存，不能在下次重载时重新出现。
- 迁移需要显示一次明确提示并记录受影响控制器的位置，说明旧版进行中批次已取消且必须重新输入物品才能恢复工作。
- 迁移后的新批次开始保存实际扣取的原物品，完整遵守关键部位拆除或控制器拆除时的物品掉落规则。

### 普通焦炉控制器拆除

- 普通焦炉控制器与底层几何中心焦炉砖共同作为两个会触发彻底清空的关键部位；控制器被移除时不使用一般结构失效的批次保留规则。
- 控制器被玩家、爆炸、命令或其他方式拆除或替换时，立即取消当前加工和待输出状态，把进度重置为 `0`，并清除锁定配方、固定耗时、概率结果及其他批次参数。
- 物品输入槽、物品输出槽、当前配方已经实际扣取的原物品，以及待输出结果中已经生成的全部固体产物，都以物品实体掉落在原控制器附近。
- 内部流体输出罐和待输出结果中的全部流体直接丢失，不限流体种类，也不生成流体方块、流体容器或其他可恢复数据。
- 当前配方尚未完成时，不生成其计划产出的物品或流体；只能返还并掉落实际扣取的原物品。
- 控制器方块自身是否掉落及其掉落数量继续遵守 Minecraft/Forge 和控制器战利品表的正常规则，与机器内部内容掉落分开处理。
- 无论控制器方块物品是否生成，掉落的控制器都不携带内部库存、流体、锁定配方、加工进度、待输出结果或其他运行状态。
- 重新放置原控制器掉落物或另一个同类控制器后，形成的是一台全新的普通焦炉，不能恢复被拆除机器的任何运行状态。
- 状态清空、内部物品掉落和流体丢失必须通过同一个清理入口只执行一次。爆炸、命令移除或相邻更新不能造成重复掉落。
- 没有被一同拆除的焦炉仓继续保存各自模式；控制器拆除不会远程重置或替换焦炉仓方块数据。

### 普通焦炉运行状态与显示优先级

普通焦炉使用以下主状态优先级。数字越小，显示优先级越高：

| 优先级 | 状态语义 | 触发条件 |
| ---: | --- | --- |
| 1 | 结构无效 | 结构尚未成型，或已经成型的结构被破坏 |
| 2 | 待输出结果 | 存在尚未整体提交的完整待输出结果 |
| 3 | 运行中 | 当前配方正在正常推进进度 |
| 4 | 等待重新输入 | 旧版进行中批次已被迁移取消，尚未发生新的合法物品插入 |
| 5 | 等待输入 | 物品输入槽为空，没有候选配方 |
| 6 | 输入无效 | 输入槽非空，但没有任何合法焦炉配方能够匹配 |
| 7 | 物品输出堵塞 | 已有合法候选配方，但其物品结果无法完整容纳 |
| 8 | 流体输出堵塞 | 已有合法候选配方，但其流体结果无法完整容纳 |
| 9 | 物品与流体输出均堵塞 | 同一合法候选配方的两类结果均无法完整容纳 |
| 10 | 准备启动 | 所有条件满足，但尚未进入开始配方的下一次服务端处理 tick |

- 对同一时刻只显示优先级最高的一项主状态；控制器 GUI 的详细信息区域可以同时列出所有实际阻塞原因。
- 输出堵塞只在存在合法候选配方时判断。没有合法输入时，不根据未知配方提前推测所需输出空间。
- 普通焦炉不具有缺少能源、缺少蒸汽、燃料不足、预热中、温度不足或主动暂停状态。
- 状态由服务端权威判定并同步，客户端不能根据槽位动画、纹理或本地配方缓存自行推测实际状态。

状态文本和组件优先复用 GTCEu 已有内容：

- GTCEu 已经提供完全相同语义的机器状态、配方逻辑状态、文本组件、图标或本地化键时，直接复用上游内容，不在 `gregsteamexpansion` 下创建同义副本。
- 结构无效、运行中、等待输入或输出空间不足等常见语义，应先核对 GTCEu 7.5.3 的现有状态系统和本地化资源，再决定是否需要补充。
- 只有 GTCEu 没有能够准确表达本设计语义的状态时，才能新增本模组状态或本地化键。预计优先核对“待输出结果”“等待重新输入”“输入无效”“物品与流体同时堵塞”是否需要新增。
- 上游状态只有在语义完整一致时才能复用，不能为了减少本地化条目而把不同原因错误映射为同一个提示。
- 若 GTCEu 后续版本改变状态键或组件接口，兼容层应按实际支持版本重新核验；面向玩家的含义和上述优先级不能随意改变。

### 普通焦炉控制器 GUI

- 普通焦炉控制器继续使用 GTCEu 原有焦炉界面的 `176×166` 尺寸和原始风格，不另做明显不同的大型机器界面。
- GUI 保留左侧物品输入槽、中间配方进度条、右侧物品输出槽、最右侧流体输出罐以及下方玩家物品栏的布局。
- GUI 增加一行只读的主状态文本，按照已经确认的状态优先级显示当前最高优先级状态。
- 同时存在多个阻塞原因时，主状态仍只显示最高优先级的一项；状态文本或配套状态图标的悬浮提示完整列出当前实际存在的全部阻塞原因。
- 进度条的悬浮提示显示当前完成百分比和按固定配方耗时计算的预计剩余时间。没有进行中配方时不显示虚假的剩余时间。
- 流体输出罐的悬浮提示显示实际流体名称、当前数量和固定 `32,000 mB` 容量；空罐也应显示容量上限。
- 输入槽、输出槽和流体罐继续遵守已经确认的插入与抽取限制，GUI 不能绕过合法配方过滤或向输出库存插入内容。
- GUI 不增加主动暂停按钮、工作启停按钮、能源信息、蒸汽信息、燃料信息、温度信息或预热信息。
- GUI 不提供焦炉仓模式的查看或远程控制；焦炉仓模式只能在世界中直接查看，并用螺丝刀对目标焦炉仓切换。

### 普通焦炉与焦炉仓 Jade 信息

普通焦炉控制器的 Jade 信息按以下范围显示：

- 显示结构有效或结构无效状态。
- 显示按照已确认优先级选出的当前主运行状态。
- 配方正在推进时，显示完成百分比和按固定耗时计算的预计剩余时间；没有进行中配方时隐藏这两项。
- 显示流体输出罐中的实际流体名称、当前数量和固定 `32,000 mB` 容量；空罐显示为空并保留容量信息。
- 存在一个或多个输入输出阻塞原因时，除主状态外列出当前全部阻塞原因。
- 不显示能源、蒸汽、燃料、温度、预热或主动暂停信息。

焦炉仓的 Jade 信息按当前模式显示：

- 始终显示焦炉仓自身保存的当前模式。
- 显示该仓是否已经连接到一座结构有效的普通焦炉；未连接时仍显示仓模式，并额外显示“未连接”。
- 物品输入模式只显示所连接焦炉的输入槽内容，不显示输出槽或流体罐内容。
- 物品输出模式只显示所连接焦炉的输出槽内容，不显示输入槽或流体罐内容。
- 流体输出模式只显示所连接焦炉的流体名称、当前数量和容量，不显示输入槽或物品输出槽内容。
- 焦炉仓不能通过 Jade 泄露当前模式无权访问的其他库存内容。

Jade 数据与兼容约束如下：

- 优先复用 GTCEu 已有的 Jade 数据字段、状态组件和本地化文本；只有上游缺失且语义无法准确表达时才由本模组新增。
- 结构、状态、进度、剩余时间、库存摘要和仓模式均由服务端计算并同步，客户端不能通过方块外观或本地配方自行推测。
- 数据值没有变化时不需要每 tick 重复发送完全相同的载荷；进度显示可以使用足以保持读数准确的节流或客户端插值，但服务端保存进度始终是权威值。
- Jade 只是信息展示渠道，不能通过其界面插入、抽取、切换仓模式或控制机器运行。

### 普通焦炉运行表现

- 普通焦炉控制器继续使用 GTCEu 现有焦炉的空闲正面纹理、工作正面纹理及对应自发光纹理，不为普通焦炉重新设计一套控制器外观。
- 只有配方正在实际推进进度时，控制器才显示点火和自发光工作纹理。
- 结构无效、等待输入、输入无效、物品或流体输出堵塞以及待输出结果状态均显示熄火的空闲纹理。
- 配方实际推进时，继续从控制器正面生成 GTCEu 原焦炉使用的火焰和大烟粒子。
- 配方实际推进时，继续按上游概率播放熔炉燃烧声，并遵守 GTCEu 的机器声音配置；配置关闭机器声音时不播放。
- 空闲、结构无效、输入无效、输出堵塞和待输出状态不循环播放燃烧声，也不继续产生工作粒子。
- 焦炉仓不产生火焰、烟雾、持续环境音或独立运行声；切换模式时只播放已经确认的螺丝刀交互音效。
- 焦炉仓继续使用原有基础模型，并在面向机器外部的正面叠加当前模式标志；该标志在结构成型后仍然保持可见。
- 物品输入模式使用绿色方框，物品输出模式使用橙色方框，流体输出模式使用蓝色方框。
- 三个方框的形状、尺寸、边框和内部图案完全相同，只改变方框颜色；不加入箭头、水滴、物品轮廓、字母或其他模式符号。
- 模式的非颜色文本识别由 Jade 当前模式文本和螺丝刀切换后的操作栏提示提供，不在方框纹理中重复表达。
- 普通焦炉不新增大型机械动画、内部炉膛动态渲染或持续环境音。
- 拆除底层中心焦炉砖或控制器触发彻底清空时，只有机器实际存在内部物品、内部流体、进行中配方或待输出结果，才播放一次特殊清空反馈。
- 特殊清空反馈播放一次熄火声，并在原控制器与炉膛中心附近生成短暂黑烟粒子，用于表示炉体泄漏和熄灭。
- 特殊反馈只作表现，不生成真实流体或杂酚油方块，也不造成爆炸、火焰、实体伤害、负面效果或额外方块破坏。
- 特殊声音和黑烟与状态清理使用同一个单次触发保护，不能因邻接更新、重复结构检查或区块重载重复播放。
- 空机器没有内部物品、流体、进行中配方或待输出结果时，拆除关键部位只使用对应方块的正常破坏声音与粒子，不播放特殊清空反馈。

### 普通焦炉与焦炉仓物品提示

普通焦炉控制器使用“默认摘要 + 按住 Shift 展开完整说明”的两级物品提示。

控制器默认摘要依次说明：

1. 这是无需能源、固定单并行的早期焦化设备。
2. 按住 Shift 查看结构、自动化和关键部位拆除警告。

控制器按住 Shift 后依次说明：

1. 结构固定为 `3×3×3`，内部正中心必须保持空气。
2. 炉膛正下方的底层几何中心必须使用焦炉砖，不能替换为焦炉仓。
3. 其余合法外壳位置共同允许 `0–5` 个可配置焦炉仓；没有仓时只能手动使用。
4. 机器不消耗能源或燃料，不具有温度、预热、冷却和主动暂停。
5. 机器固定单并行，并读取完整的 `gtceu:coke_oven` 配方类型。
6. 拆除普通外壳会使进行中配方停止，并把进度回退至 `1 tick`；修复结构后继续同一批次。
7. 拆除控制器或底层中心焦炉砖会重置加工、丢失全部内部及待输出流体，并将全部内部、已扣取和待输出物品掉落到世界。

焦炉仓同样使用两级物品提示。

焦炉仓默认摘要依次说明：

1. 使用螺丝刀切换物品输入、物品输出和流体输出模式。
2. 新放置及旧存档首次迁移的默认模式为物品输入。

焦炉仓按住 Shift 后依次说明：

1. 绿色方框表示物品输入，橙色方框表示物品输出，蓝色方框表示流体输出；三种方框只使用颜色区分。
2. 螺丝刀固定按“物品输入 → 物品输出 → 流体输出 → 物品输入”循环。
3. 焦炉实际推进配方或持有待输出结果时禁止切换仓模式。
4. 物品输入模式不主动从相邻容器抽取；两种输出模式每 `5 tick` 向仓正面主动推送对应产物。
5. 所有焦炉仓共享控制器内部库存，增加仓不会增加槽位、储罐、容量或并行。
6. 仓未连接到有效焦炉时仍保存自身模式，并可正常使用螺丝刀切换。

- 默认摘要只保留定位和最重要的操作入口，完整限制与危险集中放在 Shift 说明中。
- 物品提示的具体换行、标题、普通文本颜色、关键数值颜色和警告颜色留到本地化与美术阶段确定。
- 颜色不能成为焦炉仓物品提示中的唯一信息；即使模式方框只按颜色区分，文字仍必须明确写出每种颜色对应的模式。
- 所有提示使用本地化键，至少提供简体中文和英文。

- 自动搭建开始放置前必须检查目标 `3×3×3` 结构及其一格间距排斥范围；与已有普通焦炉重叠或间距不足时直接拒绝搭建，不先放置部分砖块。
- 自动搭建不能从焦炉或焦炉仓内部库存挪用物品，也不能复制、吞掉或错误消耗玩家终端提供的材料。
- 自动搭建完成后，玩家根据需要自行放置最多五个焦炉仓，并使用螺丝刀逐个设置模式。

### 普通焦炉环境危害

- 普通焦炉保留 GTCEu 7.5.3 原始机器提供的一氧化碳环境危害行为。
- 当 GTCEu `environmentalHazards` 配置启用时，每份配方的加工进度首次成功到达完成点，排放一次强度 `0.1` 的一氧化碳危害。
- 危害按完成的配方份数计算，不按输入物品数量、配方持续时间或杂酚油产量计算。煤炭块制焦炭块是一份独立配方，因此完成时同样只排放一次 `0.1`。
- 输入不足、开工预检失败、结构失效、区块卸载、等待输入、输入无效和输出堵塞均不产生排放。
- 配方已经完成但因异常进入待输出状态时，危害完成事件必须随批次记录为已经触发；待输出重试、区块重载或最终提交结果不能再次排放。
- 拆除底层中心焦炉砖、拆除控制器或其他关键清空事件不额外产生一氧化碳危害；它们只执行已经确认的熄火声和黑烟视觉反馈。
- GTCEu `environmentalHazards` 配置关闭时完全不产生该危害，也不积累等待以后补发的排放。
- 危害类型、向控制器正面尝试插入危害容器、无法捕获时创建环境危害区域以及其余扩散行为继续沿用 GTCEu 上游实现。
- 大型焦炉的环境危害强度和按批次还是按并行份数计算，留到大型焦炉设计阶段单独决定。

### 普通焦炉与焦炉仓的工作强度

普通焦炉与焦炉仓在 Easy、Normal、Expert 三档下使用完全相同的玩法规则：

- 普通焦炉的 `3×3×3` 结构、固定底层中心焦炉砖、焦炉仓合法位置和 `0–5` 个仓数量范围完全相同。
- 焦炉仓的三种模式、默认模式、螺丝刀循环顺序、模式锁定、每 `5 tick` 主动输出和旧存档初始化规则完全相同。
- 三个 GTCEu 基础焦炉配方的单位输入、单位产物和固定耗时完全相同；外部 `gtceu:coke_oven` 配方也不因工作强度被机器额外修改。
- 普通焦炉在三档均固定单并行，具有一个物品输入槽、一个物品输出槽和一个 `32,000 mB` 流体输出罐。
- 焦炉控制器和焦炉仓的合成材料、固定九宫格图案及每次产出 `1` 个的数量完全相同。
- 严格开工预检、原子扣取、待输出保险、无主动暂停、结构失效回退、关键部位清空、控制器拆除和旧批次迁移规则完全相同。
- 每份成功完成配方产生的 `0.1` 强度一氧化碳危害完全相同，并继续只受 GTCEu `environmentalHazards` 配置控制。
- GUI、Jade、物品提示、模式颜色、工作纹理、粒子与声音在三档完全相同。
- Easy、Normal、Expert 均不为普通焦炉或焦炉仓提供额外加速、产率、并行、库存容量、传输速率、危害减免或结构宽容。
- 合法降低工作强度不重置普通焦炉状态、不改写焦炉仓模式，也不触发配方、库存或旧存档迁移。


## 大型焦炉已确认设计

### 已确认注册身份

大型焦炉作为本模组新增的独立多方块控制器注册，不替换或重定向 GTCEu 现有普通焦炉。

| 项目 | 已确认值 |
| --- | --- |
| 中文名 | 大型焦炉 |
| 英文名 | Large Coke Oven |
| 资源 ID | `gregsteamexpansion:large_coke_oven` |
| Java 机器类 | `LargeCokeOvenMachine` |
| 注册字段 | `LARGE_COKE_OVEN` |
| 注册关系 | 新增独立控制器，不替换 `gtceu:coke_oven` |

上述名称和标识符已经定案，后续结构、配方和显示设计均应沿用。大型焦炉控制器已经确认必须消耗 `1` 个普通焦炉控制器；具体配方布局、外框材料、工具需求和机器部件已由第 11A 步定案，见下文《已确认大型焦炉控制器配方》。

### 已确认科技阶段

- 大型焦炉在玩家已经获得钢材并进入高压蒸汽阶段后解锁。
- 玩家需要先依靠普通焦炉取得焦炭并完成首批钢材，不能在青铜蒸汽时代中段直接跳过普通焦炉。
- 大型焦炉是普通焦炉之后的规模化生产设备，但仍处于蒸汽科技体系范围内，不推迟到低压电力阶段。
- “进入高压蒸汽阶段”只表示科技树、材料和建造门槛，不代表大型焦炉运行时需要蒸汽。
- 大型焦炉继续固定为无外部能源机器，不消耗蒸汽、燃料或 EU，也不设置能源仓。

### 已确认的控制器升级材料关系

- 大型焦炉控制器的获取配方必须固定消耗 `1` 个 `gtceu:coke_oven`。
- 被消耗的是物品形态的普通焦炉控制器，不是世界中已经成型的多方块结构。
- 普通焦炉内部库存、杂酚油、加工进度、朝向、结构所有权及其他世界状态均不会转移给大型焦炉控制器。
- 玩家如要使用已经放置的普通焦炉控制器作为材料，必须先按普通焦炉既定规则自行清空并拆除；配方不得直接从世界结构中远程消耗控制器。
- 本项只确定必需的升级核心。配方形式、布局与其余材料要求已由第 11A 步定案为唯一一条有序工作台配方，见下文《已确认大型焦炉控制器配方》。

### 已确认的上下位职责分工

- 普通焦炉永久保留为低成本、紧凑、单并行的分散式焦化设备；大型焦炉是高压蒸汽阶段的规模化升级设备。
- 大型焦炉解锁后，普通焦炉及焦炉仓不会被禁用、降效或从配方与任务体系中移除。
- 普通焦炉继续沿用已经定案的全部结构、配方、耗时、产率、自动化和危险行为，不因玩家解锁、制造或放置大型焦炉而改变。
- 普通焦炉适合小规模、异地或备用生产；大型焦炉以更高批量吞吐、大型结构和集中自动化作为主要优势。
- 两台机器处理同一单位配方时必须保持原料与产物守恒。大型焦炉不得仅因机器等级较高而无成本提高普通焦炉配方的单位产率。
- 若后续设计大型焦炉专属配方或额外产物，必须由用户单独确认，不能借专属规则反向修改普通焦炉配方。

### 已确认的首版核心目标

大型焦炉首版按以下优先级设计：

1. 可靠的批量焦化吞吐；
2. 完整的集中自动化；
3. 清晰的大型工业设备表现。

具体约束如下：

- 批量吞吐必须通过明确的最大并行和固定耗时实现，所有输入与输出均需在开工前完整预检，不能以吞物、产物溢出或不稳定调度换取速度。
- 结构需要提供职责清晰的物品输入、固体输出和杂酚油输出接口，使正常连续生产不依赖玩家反复打开控制器或手动搬运产物。
- 结构规模、炉室布局、工作状态和故障提示应直观体现它是普通焦炉的上位设备，不能依赖隐藏数值或新增能源系统解释其能力。
- 提高单位原料产率不属于首版核心目标。大型焦炉处理普通焦炉配方时，产能优势来自并行和固定速度，不得让相同数量的煤炭或原木无成本产生更多焦炭、木炭或杂酚油。
- 本节只固定目标与优先级，不预先确定并行数、结构尺寸、仓室种类或具体配方。

### 已确认的首版内容边界

- 首版不新增大型焦炉专属配方，也不新增只能由大型焦炉产出的固体或流体产物。
- 首版不创建仅为大型焦炉服务的新中间材料或完整煤化工材料链。
- 首版先集中完成大型焦炉本体的结构、并行、固定速度、自动化和状态规则；专属煤化工内容可在首版规则稳定后另行立项。
- 本项不预先决定外部 `gtceu:coke_oven` 配方是否自动兼容，也不排除使用现有物品与流体的批量便利配方；这些内容留到第 4 步逐项决定。
- 首版不设置维护仓、工具维护、部件磨损、维护周期或随机故障。
- 大型焦炉不会因运行时长、完成批次数量或随机判定进入维护故障；输入不足、输出堵塞、结构失效、区块卸载和控制器拆除均按本文已确认的确定性规则处理。
- 首版只注册并使用一个 `gregsteamexpansion:large_coke_oven` 控制器，不设置 MK2、MK3 或其他控制器等级。
- 首版不设置改变速度、并行或产率的升级模块，也不提供控制器原地升级机制；机器能力固定为本文确认的结构、最大并行 `6` 和 `0.5×` 耗时。
- 单一控制器规则不限制第 5 步选择固定尺寸或固定截面可变长度结构；若采用可变长度结构，同一个控制器可以根据合法结构计算能力。
- 首版不以 AE2、物流管道、存储网络或其他可选模组作为大型焦炉成型、运行或完整自动化的前置条件，也不新增对应的专用仓室。
- 大型焦炉只通过大型焦炉仓提供物品与流体接口；外部模组通过标准能力、GTCEu 管道或覆板进行的正常交互属于自然互操作。
- 首版不承诺处理任何可选模组的私有网络、频道、存储单元或断网状态；专用兼容必须另行设计，不能反向改变基础接口规则。

### 已确认的配方来源兼容

- 大型焦炉直接使用完整的 `gtceu:coke_oven` 配方类型作为加工配方来源，不新增 `large_coke_oven` 专用配方类型。
- GTCEu、数据包或其他模组成功注册到 `gtceu:coke_oven` 类型，且符合该类型既有输入输出约束的配方，均可被大型焦炉读取。
- 兼容配方的单份输入、单份输出和原始耗时定义保持不变；大型焦炉只根据自身规则另外计算实际并行与固定耗时。
- 无效、注册失败或无法由 `gtceu:coke_oven` 类型正常加载的配方，不由大型焦炉额外修复、转换或推测。
- 外部配方的新增、移除或修改会自然同步影响大型焦炉；不为大型焦炉维护一份重复的配方白名单。

### 已确认的基础配方单位语义

大型焦炉沿用普通焦炉已经确认的三条 GTCEu 基础配方：

| 配方 | 单份输入 | 单份固体输出 | 单份流体输出 | 原始基准耗时 |
| --- | --- | --- | ---: | ---: |
| 原木制木炭 | `1` 个可燃原木 | `1` 个木炭 | `250 mB` 杂酚油 | `900 tick`（45 秒） |
| 煤制焦炭 | `1` 个煤炭 | `1` 个焦炭 | `500 mB` 杂酚油 | `900 tick`（45 秒） |
| 煤炭块制焦炭块 | `1` 个煤炭块 | `1` 个焦炭块 | `4,500 mB` 杂酚油 | `8,100 tick`（405 秒） |

- 大型焦炉不修改这些配方的单份输入与产率；煤炭块配方与九份煤炭配方保持严格的九倍关系。
- 并行批次的输入、固体输出和流体输出均按实际并行数线性相乘，同一批次不会因并行份数增加而额外延长耗时。
- 表中耗时是配方提供的原始基准值；大型焦炉实际批次耗时固定为 `max(1, ceil(原始耗时 ÷ 2)) tick`。
- 首版不主动新增煤粉、木材包、压缩木材、整组原木、整组煤炭或其他批量便利配方；原料批量大小由大型焦炉的实际并行数决定。
- 已由 GTCEu、数据包或其他模组合法加入 `gtceu:coke_oven` 类型的粉、块或压缩物配方仍然自然兼容，不因其具有批量便利性质而被排除。

### 已确认结构总体路线

- 首版只支持一套固定尺寸结构，不同时识别固定截面可变长度结构或多个固定等级结构。
- 首版始终使用同一个 `gregsteamexpansion:large_coke_oven` 控制器；结构成型后不会通过延长炉体、更换控制器或安装模块改变规模。
- 固定结构以三个横向炉室、`7×7×5` 包围范围、最大并行 `6` 和完整自动化体现大型设备定位。
- 固定结构的成型谓词、逐层预览、接口合法位置、自动搭建和存档状态均只需要覆盖一套布局。
- 未来可以另行设计可变长度版本，但首版控制器和首版存档不预留两种结构路线之间的动态转换。

### 已确认外观参考与改编原则

- 大型焦炉首版外观仿照 Immersive Technology 的高级焦炉，但采用放大式改编，不按原结构的 `3×3×3` 主体尺寸直接复刻。
- 必须保留的视觉语言包括宽大的砖制炉体、顶部突出的进料构件、正面炉门和背部服务接口；参考机器的钢板材质分区不纳入本设计。
- 最终结构需要比普通焦炉更明显地表现大型设备与多个焦化炉室，同时适配 GTCEu 的结构预览、控制器和通用输入输出接口。
- 参考机器的顶部输入、正面物品输出和背面杂酚油输出只作为外观语言参考；实际自动化全部由五个候选位置上的大型焦炉仓承担。
- 不直接复用 Immersive Technology 的纹理、模型或其他受保护资产，只重新制作符合本模组与 GTCEu 视觉体系的方块和状态表现。
- 不继承参考机器的外置加热器、能源消耗或加速能力；大型焦炉继续遵守无外部能源、无温度和固定速度规则。

### 已确认主体尺寸与顶部轮廓

- 大型焦炉固定主体尺寸为 `7×5×5`，尺寸顺序为“宽 × 高 × 深”。
- 主体尺寸固定为 `7×5×5`，不保留其他尺寸变体。
- 主体顶部使用现有 `gtceu:coke_oven_bricks` 搭建两层阶梯式进料斗轮廓，因此完整结构包围范围为 `7×7×5`。
- 正面继续表现多个焦化炉室，并保留中央竖向控制与结构轴；炉室外观数量与最终并行数不直接绑定。
- 顶部第 `6` 层中央使用一块焦炉砖作为进料斗底颈；第 `7` 层使用八块焦炉砖围成 `3×3` 环形斗口，环中心固定为空气。
- 顶部进料斗只承担结构和外观语义，不新增专用顶部方块，也不提供任何物品、流体、能源或其他自动化能力；实际输入输出只能通过大型焦炉仓完成。

### 已确认控制器位置与结构朝向

- 玩家面对结构正面时，宽度为左右 `7` 格，高度为主体 `5` 格，深度从正面向后为 `5` 格。
- 大型焦炉控制器固定在主体最底层正面的水平中心，即正面第 `4` 格、主体第 `1` 层。
- 控制器正面必须朝向结构外部，完整主体从控制器所在正面层向后延伸 `4` 格。
- 结构只允许绕竖直轴旋转，可以朝北、南、东或西成型；不允许控制器朝上、朝下或形成侧躺结构。
- 四个水平朝向使用完全相同的相对结构，不因世界坐标方向改变材料、接口数量或机器能力。
- 正面布局以中央控制器轴为基准保持左右镜像对称；后续全部位置均以相对控制器坐标描述。
- 顶部进料斗以主体平面中心为轴：第 `6` 层底颈位于宽度第 `4` 格、深度第 `3` 格，第 `7` 层 `3×3` 斗口覆盖宽度第 `3–5` 格、深度第 `2–4` 格。

### 已确认主体外壳材料

- `7×5×5` 主体的全部默认外壳位置统一使用 `gtceu:coke_oven_bricks`，不设置钢制背面、钢制服务墙或其他外壳材料分区。
- 大型焦炉控制器占用的固定正面位置不是焦炉砖块；顶部进料斗的底颈和环形斗口全部固定使用 `gtceu:coke_oven_bricks`。
- 只有五个已确认候选接口位置可以用大型焦炉仓替换焦炉砖块。
- 除控制器及合法大型焦炉仓接口外，其余实体结构位置必须保持为 `gtceu:coke_oven_bricks`，不能使用其他外壳、玻璃、框架或装饰方块替代。
- 对 Immersive Technology 高级焦炉的仿照保留整体比例、顶部进料和正面炉门语言，不再保留原结构的强化砖与钢板前后分区。

### 已确认内部炉室数量与横向排列

- 主体外壳以内的 `5×3×3`（宽 × 高 × 深）可规划区域采用三炉室布局，由两面完整纵向隔墙分成左、中、右三间窄炉室。
- 以玩家面对正面时从左到右的主体宽度编号计算，第 `2`、`4`、`6` 格分别形成一条炉室列；每条炉室占内部高度 `3` 格、内部深度 `3` 格，单间尺寸为 `1×3×3`。
- 第 `3`、`5` 格形成两面完整纵向隔墙，隔墙均覆盖内部高度 `3` 格和内部深度 `3` 格。
- 三间炉室合计包含 `27` 格固定空气，两面隔墙合计包含 `18` 块固定焦炉砖；内部不设置额外核心。

### 已确认目标稳态吞吐

- 大型焦炉在持续供料、输出空间充足且结构及接口均有效时，目标稳态吞吐固定为 `12` 座普通焦炉同时运行的等效吞吐，即普通焦炉基线的 `12×`。
- Easy、Normal、Expert 三档均使用相同的 `12×` 目标稳态吞吐，不因工作强度提高或降低大型焦炉的长期处理能力。
- 普通焦炉处理煤炭或可燃原木的基线为每 `900 tick` 完成 `1` 份，因此大型焦炉目标为平均每分钟处理 `16` 份煤炭或原木，并产生相同数量的对应固体产物。
- 煤炭路线在目标吞吐下平均每分钟产生 `8,000 mB` 杂酚油；原木路线平均每分钟产生 `4,000 mB` 杂酚油。
- 普通焦炉处理煤炭块的基线为每 `8,100 tick` 完成 `1` 份，因此大型焦炉目标为平均每分钟处理约 `1.778` 个煤炭块，并产生等量焦炭块及平均每分钟 `8,000 mB` 杂酚油。
- 三条基础配方在等量原料下继续守恒；煤炭块路线的长期吞吐与九份煤炭路线严格一致，不提供额外速度或产率奖励。
- 本项目标只冻结稳定连续运行时的长期吞吐，不提前决定最大并行、固定耗时倍率、首批完成时间或输入不足时的开工行为。
- 最大并行 `6` 与固定 `0.5×` 耗时共同实现 `12×` 目标，Easy、Normal、Expert 三档一致。

### 已确认最大并行与实际并行

- 大型焦炉的最大并行固定为 `6`，Easy、Normal、Expert 三档使用完全相同的最大并行，不由三个可见炉室、接口数量、连续运行时间或其他条件动态计算。
- 一个批次只执行一种 `gtceu:coke_oven` 配方，不把煤炭、原木或不同外部配方混合到同一批次，也不把三个可见炉室作为彼此独立的配方处理槽。
- 输入不足 `6` 份时不等待凑满；只要至少存在一份可完整执行且输出能够容纳的配方，机器立即采用当前条件允许的最高实际并行开工。
- 实际并行按 `min(6, 可用输入份数, 固体输出可容纳份数, 流体输出可容纳份数)` 计算；配方缺少某类输出时，对应输出项不构成限制。
- `gtceu:coke_oven` 配方类型最多具有 `1` 个物品输入项、`1` 个物品输出项、`0` 个流体输入项和 `1` 个流体输出项。可用输入份数按该唯一物品输入项的完整数量计算；输入数量不足一整份时不能启动残缺配方。
- 实际并行由完整输入和固体、流体输出模拟共同限制；概率输出在开工时预先抽取并保存精确快照。
- 公式结果小于 `1` 时不开工，也不扣取任何输入；结果为 `1–6` 时一次性锁定该批次的实际并行。
- 批次开始后，新加入的输入、被腾出的输出空间或其他外部库存变化均不能提高或降低已经锁定的实际并行；下一批次重新按当时条件计算。

### 已确认固定耗时倍率

- 大型焦炉对全部 `gtceu:coke_oven` 配方统一使用固定 `0.5` 耗时倍率，Easy、Normal、Expert 三档完全一致。
- 实际批次耗时使用公式 `max(1, ceil(配方原始耗时 × 0.5))`，等价于 `max(1, ceil(配方原始耗时 ÷ 2))`；结果始终为整数 tick。
- 向上取整保证奇数耗时的外部配方不会因取整而获得超过两倍的处理速度；原始耗时为 `1` 或 `2 tick` 时均按最低 `1 tick` 完成。
- 原木制木炭和煤制焦炭的原始 `900 tick` 均变为 `450 tick`（22.5 秒）；煤炭块制焦炭块的原始 `8,100 tick` 变为 `4,050 tick`（202.5 秒）。
- 满 `6` 并行时，基础煤炭或原木路线每分钟处理 `16` 份，煤炭块路线每分钟处理约 `1.778` 份，满足已确认的普通焦炉 `12×` 稳态吞吐。
- 固定耗时倍率只作用于配方提供的原始耗时，不再乘以实际并行数；同一配方采用 `1–6` 中任意实际并行时，该批次耗时完全相同。
- 批次开始时计算并锁定实际整数耗时。运行中新加入的输入、输出空间变化、连续运行时间、空闲时间、三个可见炉室、生物群系、天气或维度均不触发重新计算。
- 本项不允许其他工作强度、接口、覆板、外部能源或未来升级模块改变 `0.5` 倍率；若数据包配方本身修改原始耗时，只影响修改后新开始的批次，进行中批次仍使用已经锁定的耗时。

### 已确认配方选择与输入竞争

- 大型焦炉使用“最近成功配方优先”的确定性选择规则；正在运行的批次始终锁定其配方，不在批次中途重新选择或切换。
- 控制器尚未保存成功配方时，按逻辑输入槽编号从小到大扫描，由编号最小且能够参与一条完整合法配方的输入槽决定首个候选配方；只含无效物品或不能组成完整配方的靠前槽位不阻塞后续扫描。
- 同一个起始输入能够匹配多条完整配方时，候选配方按资源 ID 字典序排列，并选择排序最前者；不能依赖模组加载顺序、容器迭代顺序或随机数。
- 首个批次成功开工后，控制器保存该配方的资源 ID 作为偏好配方；后续每次准备新批次时均先尝试偏好配方，不再先按输入槽顺序选择其他配方。
- 只要偏好配方具有至少一整份输入，并且固体与流体输出能够容纳至少一份，就继续以该配方当前可达到的最高实际并行开工；不能为了获得更高并行或更短耗时改选其他配方。
- 偏好配方不存在一整份完整输入时，机器重新按输入槽顺序及配方资源 ID 顺序寻找其他可执行配方；另一配方成功开工后立即取代旧偏好，成为后续批次的新偏好配方。
- 偏好配方具有完整输入但固体或流体输出连一份都无法容纳时，机器等待输出而不改选其他配方，避免临时堵塞让生产线静默切换产品。
- 偏好配方输出只允许较低并行时，机器按当前可容纳的最高实际并行继续运行该配方，不因无法达到满 `6` 并行而切换。
- 同一配方需要从多个输入槽扣取内容时，按输入槽编号从小到大确定扣取来源，并在完整开工预检成功后统一扣取；不能让容器内部遍历顺序改变结果。
- 煤炭与煤炭块等不同原料同时存在且尚无偏好配方时，由它们所在的首个有效输入槽决定首次选择；偏好建立后则遵守上述持续运行与回退规则。
- 偏好配方资源 ID 需要持久化，在区块卸载、世界重载和服务器重启后保持；空闲机器重载后仍先尝试保存的偏好，不把重载视为“第一次运行”。
- 数据包重载导致偏好配方被移除或不再合法时，该偏好视为无法组成完整输入，并在下一次选配方时回退到固定输入槽顺序；进行中批次如何迁移仍在后续步骤决定。
- 控制器被拆除、结构迁移或版本升级时是否保留偏好，由对应的状态清理与迁移步骤决定；普通结构暂时失效本身不自动改变偏好。

### 已确认吞吐与守恒算例

以下算例同时约束输入数量、实际并行、耗时与产物守恒；开工和完成均使用本文确认的原子模拟、快照与待输出规则。

| 场景 | 开工前条件 | 实际并行 | 扣取与剩余 | 应生成产物 | 耗时 |
| --- | --- | ---: | --- | --- | ---: |
| 输入少于上限 | `4` 煤炭，空间充足 | `4` | 扣取 `4`，剩余 `0` | `4` 焦炭与 `2,000 mB` 杂酚油 | `450 tick` |
| 输入等于上限 | `6` 煤炭，空间充足 | `6` | 扣取 `6`，剩余 `0` | `6` 焦炭与 `3,000 mB` 杂酚油 | `450 tick` |
| 输入超过上限 | `14` 煤炭，空间持续充足 | 依次为 `6`、`6`、`2` | 三批共扣取 `14` | `14` 焦炭与 `7,000 mB` 杂酚油 | 共 `1,350 tick` |
| 固体完全堵塞 | `6` 煤炭，固体空间为 `0` | `0` | 不扣取 | 不生成 | 不开工 |
| 流体限制并行 | `6` 煤炭，固体空间充足，流体仅余 `2,499 mB` | `4` | 扣取 `4`，剩余 `2` | `4` 焦炭与 `2,000 mB` 杂酚油 | `450 tick` |
| 多项共同限制 | `20` 煤炭，固体可容纳 `5` 份，流体可容纳 `4` 份 | `4` | 扣取 `4`，剩余 `16` | `4` 焦炭与 `2,000 mB` 杂酚油 | `450 tick` |

煤炭块与煤炭的等量比较固定如下：

- 一批 `6` 个煤炭块运行 `4,050 tick`，生成 `6` 个焦炭块和 `27,000 mB` 杂酚油。
- 同样的 `4,050 tick` 可以连续运行九批满并行煤炭，共处理 `54` 个煤炭并生成 `54` 个焦炭和 `27,000 mB` 杂酚油。
- `6` 个煤炭块恰好对应 `54` 个煤炭，因此两条路线保持严格九倍关系，不产生额外速度或产率差异。

外部配方使用以下通用算例验证多单位输入、不同产物数量和奇数耗时：

```text
单份输入：2 X
单份输出：3 Y + 750 mB 流体
原始耗时：901 tick
现有输入：11 X
固体空间：可容纳 12 Y（4 份）
流体空间：2,300 mB（3 份）
```

结果固定为实际并行 `min(6, 5, 4, 3) = 3`，扣取 `6 X` 并剩余 `5 X`，运行 `ceil(901 ÷ 2) = 451 tick` 后应生成 `9 Y` 和 `2,250 mB` 流体。

满并行持续运行的最终校验如下：

- 煤炭或原木每 `450 tick` 处理 `6` 份，即每分钟 `16` 份。
- 煤炭路线平均每分钟产生 `8,000 mB` 杂酚油，原木路线平均每分钟产生 `4,000 mB` 杂酚油。
- 煤炭块每 `4,050 tick` 处理 `6` 份，即平均每分钟约 `1.778` 份。
- 上述计算在 Easy、Normal、Expert 三档完全一致。

- 新部件的中文名固定为“大型焦炉仓”，英文名为“Large Coke Oven Hatch”，资源 ID 为 `gregsteamexpansion:large_coke_oven_hatch`，Java 注册字段为 `LARGE_COKE_OVEN_HATCH`，建议实现类名为 `LargeCokeOvenHatchPartMachine`。
- 只注册这一种大型焦炉仓物品与方块，不再拆分或注册独立的物品输入仓、固体输出仓和流体输出仓，也不设置需要先合成的空白仓体。
- 大型焦炉仓具有且只具有物品输入、固体输出和流体输出三种互斥工作模式；不提供流体输入、能源、维护、关闭或同时暴露多种能力的综合模式。

- 当前模式作为仓自身持久化状态保存，并在区块卸载、世界重载和服务器重启后保持；同一时刻只允许对外暴露当前模式对应的能力。

### 已确认大型焦炉仓数量与模式配额

- 一座合法大型焦炉必须安装至少 `3` 个、最多 `5` 个大型焦炉仓；其余未安装仓的候选位置必须使用 `gtceu:coke_oven_bricks`。
- 物品输入、固体输出和流体输出三种模式必须各至少存在 `1` 个，否则结构不具备成型资格；砖制顶部进料斗和控制器不能替代任何一种必需仓模式。
- 因仓总数上限为 `5` 且另外两种模式各至少需要一个，任一种模式实际最多可以使用 `3` 个；合法分配包括 `1/1/1`、`2/1/1`、`2/2/1` 和 `3/1/1` 及其模式排列。
- 使用 `3`、`4`、`5` 个大型焦炉仓时，结构分别需要 `153`、`152`、`151` 块焦炉砖。

- 未连接任何大型焦炉的仓可以自由切换模式。已成型但未运行且没有待输出批次时，只有切换后仍满足三种模式各至少一个，螺丝刀操作才成功。
- 尝试切换结构中最后一个某模式的仓时拒绝操作，保持原模式、不消耗螺丝刀耐久并提示缺少该必需接口；不能让已成型机器因一次模式切换直接失效。
- 运行中或持有待输出批次时禁止切换模式；其他允许切换的状态仍必须满足三种模式各至少一个。
- 增加同模式仓不能提高已经固定的最大并行 `6`，也不增加内部槽位或容量，只增加可连接的对外工作位置。
- Easy、Normal、Expert 三档使用完全相同的仓总数范围、三种模式最低配额和模式切换保护。

### 已确认内部物品与流体库存

- 大型焦炉的全部配方库存统一归控制器所有，大型焦炉仓自身不持有独立物品或流体库存，只按当前模式代理控制器的对应共享库存。
- 控制器具有 `6` 个普通物品输入槽、`6` 个普通固体输出槽和 `1` 个固定容量为 `64,000 mB` 的流体输出罐，不设置任何流体输入槽或流体输入罐。
- 全部物品输入模式仓暴露同一组六个输入槽，全部固体输出模式仓暴露同一组六个输出槽，全部流体输出模式仓暴露同一个流体输出罐。
- 增加同模式仓只增加外部自动化的连接位置和方向，不增加槽位、储罐容量、最大并行、传输倍率或单份配方产率。
- 输入和输出槽遵守物品自身的正常最大堆叠限制；同一物品可以跨多个槽共同满足一份或一个并行批次的数量需求，扣取顺序继续按槽位编号从小到大。
- 六个输入槽允许同时缓存多种合法候选原料，但 `gtceu:coke_oven` 配方每份最多仍只有一个物品输入项；库存槽数量不能扩大配方类型已经确认的 I/O 项数。
- 六个输出槽共同接收当前批次的唯一物品输出项。不同批次产生的不同固体可以占用不同槽，但物品不兼容或空间不足时按输出限制降低实际并行或阻止开工。
- 流体输出罐同一时刻只保存一种流体与组件数据完全相同的流体堆栈，不混合、转换、覆盖或自动替换不同流体；产生另一种流体的配方必须等待现有流体完全排空。
- `64,000 mB` 能够容纳两批满并行煤炭块产生的 `54,000 mB` 杂酚油，并保留 `10,000 mB` 缓冲；容量不随仓数量、工作强度或连续运行时间变化。
- 大型焦炉仓被拆除或改变模式时，共享库存仍保留在控制器中，不随仓移动、复制或掉落；结构失效时库存保留，控制器拆除时按单次清理规则结算。
- 仓模式与共享库存相互独立。某类共享库存非空本身不阻止模式改变，但切换仍须满足最低模式配额和运行状态锁定。
- Easy、Normal、Expert 三档使用完全相同的输入槽、输出槽和流体罐规格。

### 已确认大型焦炉仓主动传输、方向与覆板

- 每个大型焦炉仓只在自身正面暴露当前模式对应的自动化能力，其余五面不接受物品或流体能力访问。
- 背面三个候选位置上的仓必须正面朝向机器后方，左侧和右侧候选位置上的仓必须分别朝向机器左侧和右侧；朝向不符合所在位置的仓不具备结构资格。
- 未连接任何大型焦炉的仓允许按通用规则向六个方向旋转；已经成型的仓若被尝试旋转到所在位置唯一合法的外向方向以外，操作直接拒绝、不改变朝向且不消耗扳手耐久。
- 大型焦炉运行中同样不能通过旋转仓改变工作面；合法朝向本身不因批次、模式或覆板变化。
- 物品输入模式只被动接受外部设备从仓正面插入合法原料，不主动从相邻容器或管道抽取物品。
- 固体输出和流体输出模式分别允许外部设备随时从仓正面主动抽取对应共享库存，也由控制器每 `5 tick` 各执行一次主动输出轮询。

- 轮询遇到完全不能接收的目标时继续检查下一个对应模式仓；找到第一个能够接收任意内容的目标并执行一次传输后，本轮该类型立即结束，不再从其他仓重复推送。
- 增加同模式仓只提供备用连接与输出方向，不增加每 `5 tick` 的控制器级主动推送轮数；外部设备主动抽取的实际调用频率仍由外部设备决定。
- 目标不存在、能力不匹配、覆板拒绝、空间不足或只能接收部分内容时，未成功转移的物品或流体全部保留在控制器共享库存，不能掉落、销毁、复制或覆盖目标内容。
- 只有大型焦炉仓面向机器外部的正面允许安装 GTCEu 合法覆板；覆板安装、拆除、物品返还及自身配置继续使用 GTCEu 通用规则。

- 仓模式改变后覆板原样保留，并重新按新模式与覆板能力的交集计算实际能力；不兼容的覆板功能保持无效，不能成为模式切换的旁路。
- 红石覆板只能控制所在仓的物流行为，不能暂停、恢复、重置或改变大型焦炉加工；主动推送与外部能力访问必须经过相同的仓模式和覆板过滤。
- Easy、Normal、Expert 三档使用相同朝向、轮询顺序、`5 tick` 周期和覆板规则。

### 已确认开工预检、批次快照与原子扣取

- 大型焦炉只有在结构、`3–5` 个大型焦炉仓、三种必需模式配额和全部仓朝向均有效，且不存在进行中批次或尚未提交的待输出批次时，才能尝试开始新批次。
- 控制器先按已确认的“最近成功配方优先”规则选择候选配方，再从最大并行 `6` 开始向下尝试，寻找输入与全部输出均可完整容纳的最高实际并行。
- 每个候选并行必须先在库存副本中完成无副作用模拟，包括按槽位顺序取得完整物品输入、生成本批次精确产物，以及把全部固体和流体产物同时放入当前共享输出库存。
- 配方具有概率产物时，在候选批次准备开工时为每份实际并行预先判定一次，并把合并后的精确结果写入批次输出快照；后续完成、等待输出、结构恢复和世界重载均不得重新抽取。
- 如果某个候选并行的输入或任一输出模拟失败，则继续尝试更低并行；所有并行均失败时不创建批次、不扣取输入，也不更新偏好配方。
- 只有完整模拟成功后，才在同一个服务端操作中一次性提交全部物品输入扣取并创建批次；不能先扣除部分槽位或部分输入，再因其他条件失败而留下残缺状态。
- 真实扣取必须与模拟的槽位、物品身份、组件数据和数量完全一致；若提交阶段发现任何不一致，整次开工失败，不创建批次，也不得保留部分扣取。
- 成功创建的批次立即持久化配方资源 ID、实际并行、已扣输入摘要、精确固体与流体输出快照、锁定总耗时、当前进度、批次唯一序号以及“输出尚未提交”标志。
- 固体输出槽和流体输出罐拒绝玩家及外部设备主动插入，因此开工时确认的可用空间正常情况下只能保持或增加；即使如此，完成时仍需按第 8B 步重新执行完整提交模拟。
- 实际并行为 `1–6` 时均使用同一套预检、快照和原子扣取流程；Easy、Normal、Expert 三档没有宽松预检、概率重抽或先扣后补差异。

### 已确认完成提交与待输出保险

- 批次进度达到锁定总耗时时，控制器使用已经持久化的精确输出快照重新模拟固体输出槽和流体输出罐；不重新运行配方、不重新计算并行，也不重新判定概率产物。
- 只有固体与流体产物都能完整容纳时，才在同一个服务端操作中把全部产物提交到共享库存；任一类不能完整容纳时两类均不提交，不能形成半完成批次。
- 提交失败时，批次进入持久化“等待输出”状态，进度固定在完成值，并继续保存配方资源 ID、实际并行、批次唯一序号和完整输出快照。
- 等待输出期间不开始新批次、不再次扣取输入、不重新加工、不重抽概率结果，也不重复产生完成声音、粒子、一氧化碳或其他一次性事件。
- 玩家可以通过控制器 GUI 取走共享库存中的已有产物，大型焦炉仓也继续按正常规则输出已有库存；流体类型不兼容时必须等待现有流体完全排空。
- 相关固体或流体库存发生变化后，在下一服务端 tick 尝试重新提交；即使未收到库存变化通知，也每 `20 tick` 执行一次保底重试。
- 结构无效、三种必需仓模式不足或仓朝向错误时保留等待输出记录但不提交，直到结构及接口重新有效。
- 成功提交时，固体与流体同时进入共享库存，并在同一持久化状态中把批次标记为“输出已提交”，随后清除输出快照和进行中记录。
- 新批次最早从成功提交后的下一服务端 tick 开始，不能在同一次完成或重试回调中再次开工。
- 成功提交不会立即额外执行主动输出；新产物继续等待原有每 `5 tick` 一次的控制器级输出轮询。
- 完成反馈和环境危害均在进度首次到达完成点时结算，并使用批次唯一序号和独立已处理标志保证最多发生一次。
- Easy、Normal、Expert 三档使用相同的全有或全无提交、等待输出、重试周期和防重复规则。

### 已确认无主动暂停与红石加工控制

- 大型焦炉首版不提供任何玩家主动暂停功能；控制器 GUI 不设置暂停按钮，软锤、螺丝刀、扳手及其他工具也不能暂停或恢复加工。
- 控制器收到任何强度的红石信号时均不暂停、不取消正在进行的批次，也不阻止下一批按正常条件开工；控制器不保存红石停机或玩家暂停状态。
- 大型焦炉仓上的红石覆板只能控制所在仓当前模式允许的物流，不能暂停、恢复、重置、取消或阻止控制器加工。
- 正在推进批次或持有待输出结果时，禁止切换结构中任何大型焦炉仓的模式；即使切换后仍满足三种模式最低配额也必须拒绝。
- 被拒绝的模式切换保持原模式、不消耗螺丝刀耐久、不重置或中断批次，也不能移动、清空或复制共享库存与输出快照。

- 已成型仓继续只能保持所在候选位置唯一合法的外向工作面，不能借运行状态旋转到非法方向。
- 大型焦炉只有结构失效、必要区块不可用或批次已经到达完成点时停止推进；这些状态不转换为隐藏的主动暂停开关。
- Easy、Normal、Expert 三档均不提供主动暂停或红石加工控制。

### 已确认普通结构失效时精确冻结

- 控制器仍然存在，但任一必要焦炉砖、内部隔墙或顶部进料斗砖缺失，固定空气格被占用，大型焦炉仓数量或三种模式配额不足，仓朝向错误，出现非法接口，或与另一座焦炉发生结构或间距冲突时，大型焦炉立即进入普通结构失效状态。
- 普通结构失效时立即停止推进配方、寻找新配方、提交待输出结果和执行大型焦炉仓主动传输。
- 进行中批次精确保留失效瞬间的当前进度，不回退到 `1 tick`，也不重置为 `0`；同时保留配方资源 ID、实际并行、已扣输入摘要、精确输出快照、锁定总耗时、批次唯一序号和偏好配方。
- 结构持续无效期间进度完全冻结，不执行离线补算、概率重抽、输入退还、产物生成或环境危害结算。
- 结构重新满足全部图案、仓模式、朝向、独占和间距要求后，从原精确进度继续同一批次，不重新扣取输入、选择配方或生成输出快照。
- 已处于等待输出状态的批次继续保存完整待输出记录，不回到加工阶段；结构恢复有效后按照既定规则重新尝试原子提交。
- 共享输入、固体输出和流体输出库存继续保存在控制器中，玩家仍可通过控制器 GUI 查看和取回；失效结构中的大型焦炉仓不再暴露能力或执行主动传输。
- 普通结构失效本身不掉落库存、不清空流体、不生成计划产物，也不能因连续拆除多个结构方块而重复退还、生成或销毁同一批内容。
- 该精确冻结会允许玩家通过主动破坏结构实现一种需要重新修复结构的物理停机方式；这不创建 GUI、工具或红石暂停状态，也不能绕过结构重新成型检查。
- Easy、Normal、Expert 三档使用相同的精确冻结与恢复规则。

### 已确认不存在非控制器关键清空部位

- 大型焦炉不设置关键底部砖、炉篦、隐藏核心或其他非控制器关键清空部位。
- 拆除或替换主体外壳、内部隔墙、砖制顶部进料斗或大型焦炉仓，以及占用任一固定空气格，均只触发已经确认的普通结构失效与精确进度冻结。
- 上述非控制器结构变化不清空共享流体罐，不掉落、销毁或退还共享输入、固体输出、已扣输入及待输出快照，也不重新生成概率产物。
- 结构重新满足全部条件后继续原批次或原等待输出状态，不因被破坏位置不同而采用另一套恢复规则。
- 被拆除的焦炉砖或大型焦炉仓自身是否产生方块物品，继续遵守各自正常战利品表；方块自身掉落与控制器共享库存及批次记录完全分离。
- 非控制器结构首次失效只触发一次熄火声与短暂黑烟，不附带库存损失、伤害、着火或爆炸。
- 普通结构失效不需要维护“强制清空已经执行”标志，因为该路径从不执行批次或库存清空。
- 控制器被拆除是唯一执行批次取消与库存清理结算的结构破坏事件。
- Easy、Normal、Expert 三档不存在不同的关键砖或非控制器清空惩罚。

### 已确认控制器拆除结算

- 大型焦炉控制器被玩家、爆炸、命令、活塞或其他方式拆除、替换或移走时，不使用普通结构失效的精确冻结规则，而是立即取消进行中批次或等待输出状态。
- 清理时把进度重置为 `0`，并清除锁定配方、实际并行、锁定耗时、偏好配方、精确输出快照、批次唯一序号及其他运行状态。
- 六个输入槽和六个固体输出槽中已经存在的全部物品均以正常物品实体掉落在原控制器附近。

- 控制器在批次已经完成并处于等待输出时被拆除，不返还原始输入，而是掉落待输出快照中的全部固体产物；该批次尚未提交的流体产物按流体丢失规则处理。

- 控制器方块自身是否掉落及掉落数量继续遵守其正常战利品表和破坏来源；控制器掉落物永不携带共享库存、流体、仓模式、偏好配方或批次状态，重新放置后是一台全新机器。
- 未被拆除的大型焦炉仓继续保留自身模式、朝向、染色和覆板，但失去控制器后不能访问已经结算并清除的共享库存。
- 批次取消、内部物品掉落、流体丢失和结构所有权释放必须通过同一个结算入口执行，并使用一次性清理标志保证爆炸、相邻更新、重复移除回调或重载最多结算一次。
- 创造模式、爆炸、活塞和命令移除使用相同的内部库存与批次结算规则；不同来源只影响控制器方块自身是否产生掉落。
- 空闲时拆除只掉落输入槽与固体输出槽现有物品；加工中额外返还本批已扣原料；等待输出时额外掉落待输出固体产物；任意状态下全部现存或待输出流体均丢失。
- Easy、Normal、Expert 三档使用完全相同的控制器拆除结算。

- 重新成型不修改任何大型焦炉仓的模式、朝向、染色或覆板，也不重新排列、合并或迁移控制器共享库存。

- 其他方块图案错误显示“结构无效”及首个错误坐标；所有权重叠显示“与另一多方块结构重叠”；间距冲突显示“与另一焦炉间距不足”。

### 已确认大型焦炉一氧化碳排放计量

- 大型焦炉沿用普通焦炉按“完成的配方份数”计量一氧化碳的语义，不按输入物品数量、配方耗时、固体产物数量或杂酚油产量换算。
- 实际并行数为 `p` 时，一个批次产生一次合并的一氧化碳危害事件，强度固定为 `0.1 × p`；`p` 的合法范围为 `1–6`，因此单批强度范围为 `0.1–0.6`。
- 危害事件在该批次加工进度首次成功到达完成点时触发，不等待固体与流体产物成功提交到共享输出库存；若产物暂时无法提交并进入待输出状态，本批次也已经完成排放计量。
- 批次持久化保存独立的危害结算标记。待输出重试、结构修复、重新成型、所有权恢复、区块重载、世界重载和服务器重启均不能再次触发同一批次的危害事件。
- 当 GTCEu `environmentalHazards` 配置在批次首次到达完成点时关闭，本批次不产生环境危害，并立即把危害结算标记记为已经处理；以后启用配置时不积累、不追补该批次的排放。
- 开工预检失败、没有创建批次、等待输入、输入不足、尚未到达完成点的结构失效或区块卸载、输出空间预检失败以及输出堵塞本身均不产生额外排放。
- 拆除非控制器结构方块不会额外排放；拆除控制器时也不为尚未完成的批次补发排放。已经到达完成点的批次则保持其原有危害结算结果，不因拆除重复触发。
- 危害类型、从控制器正面尝试插入兼容危害容器、捕获失败时创建环境危害区域以及其余扩散行为继续沿用 GTCEu 上游实现；本模组只把该次事件的强度替换为 `0.1 × p`。
- 在满并行 `p=6` 下，每批强度为 `0.6`。结合已经确认的 `0.5` 耗时倍率，其单位时间排放与 `12` 台执行相同配方的普通焦炉一致，不因合批获得污染折扣。
- Easy、Normal、Expert 三档使用完全相同的排放公式、触发时点和防重复规则。

### 已确认大型焦炉结构破坏反馈与事故上限

- 大型焦炉采用确定性的安全事故上限；机器自身在任何状态下都不会主动生成火焰或爆炸，不造成实体伤害、负面效果或既定方块拆除之外的额外方块破坏。
- 非控制器结构第一次从完整有效变为无效时，只播放一次短促熄火声，并在控制器及本次验证发现的首个错误坐标附近生成短暂黑烟；该反馈只作表现，不改变已经确认的精确冻结、库存、批次或所有权规则。
- 普通结构失效反馈按一次“有效 → 无效”状态边沿触发。机器持续无效期间的相邻更新、重复结构检查、区块重载、世界重载和服务器重启均不能重复播放。
- 只有结构重新通过完整验证并成功恢复成型后，失效反馈资格才重置；此后再次出现新的“有效 → 无效”状态边沿时可以再次播放一次。
- 控制器被拆除时，若机器存在任意共享物品、共享流体、进行中批次或待输出批次，则随已经确认的单次清理结算播放一次更明显的熄火声，并在原控制器与炉室区域生成短暂黑烟。
- 空闲且没有任何物品、流体、进行中批次或待输出批次的控制器被拆除时，只使用方块正常破坏声音与粒子，不播放特殊清空反馈。
- 控制器拆除的特殊声音和黑烟必须与批次取消、物品掉落、流体丢失及所有权释放共用同一个单次清理保护；不同移除回调、相邻更新或重载不能重复播放。
- 输出空间预检失败和待输出堵塞不会产生额外一氧化碳、黑烟事故、火焰、爆炸、伤害或方块损坏；控制器状态符号、GUI 和 Jade 提供持续提示。
- 外部来源的爆炸仍可依照 Minecraft、NeoForge、GTCEu 及方块自身的正常规则破坏控制器、仓或焦炉砖，但大型焦炉不会因而生成二次爆炸或连锁事故；内部结算仍按实际被移除的部位执行。
- 结构失效反馈与控制器拆除反馈均不模拟真实烟气或流体，不生成可收集物、环境危害区域或额外一氧化碳事件。
- Easy、Normal、Expert 三档使用完全相同的结构破坏反馈、事故上限和单次触发规则。

### 已确认大型焦炉运行状态集合与优先级

- 大型焦炉采用“唯一主状态 + 详细原因”的两级状态模型。任一时刻只能有一个对外显示的权威主状态，但 GUI 的详细信息区域可以同时列出被更高优先级状态遮盖的其他真实情况。
- 主状态按下表从高到低决定；数字越小，显示优先级越高：

| 优先级 | 主状态 | 触发条件 |
| ---: | --- | --- |
| 1 | 结构范围未完全加载 | 完整 `7×7×5` 包围范围涉及的任一结构相关区块不可用，当前不能完成权威结构验证 |
| 2 | 结构无效 | 相关区块均可用，但结构、接口、朝向、固定空气、所有权或一格间距中的任一要求不满足 |
| 3 | 等待重新输入 | 未来存档迁移无法安全恢复旧批次，已经取消旧批次并锁定到发生一次新的合法输入变化之前 |
| 4 | 等待输出 | 批次已经到达完成点，但精确输出快照尚未整体提交到共享输出库存 |
| 5 | 正在工作 | 已存在锁定批次，且本 tick 可以正常推进加工进度 |
| 6 | 启动前输出堵塞 | 存在至少一份完整合法输入，但连实际并行 `1` 的精确产物也无法完整容纳，因而没有创建批次 |
| 7 | 输入无效 | 输入槽非空，但不存在任何能够匹配其中物品的合法焦炉配方 |
| 8 | 输入不足 | 存在可以识别的候选配方原料，但现有数量不足以完成一份配方 |
| 9 | 准备启动 | 配方、输入及输出条件均满足，但按照 tick 边界规则尚未原子创建下一批次 |
| 10 | 空闲 | 不存在进行中或待输出批次，且输入槽为空 |

- “缺少必需的大型焦炉仓”不是独立主状态，而是“结构无效”的详细原因；详细原因继续区分仓总数或模式配额不足、仓朝向错误、固定空气受阻、首个图案错误坐标、所有权重叠和机器间距不足。
- “等待输出”只描述已经完成但尚未提交的精确批次快照，其详细原因分为固体输出堵塞、流体输出堵塞及固体与流体同时堵塞。
- “启动前输出堵塞”描述尚未扣取输入、尚未创建批次时的输出空间预检失败，同样区分固体、流体及两者堵塞；不得与已经完成批次的“等待输出”混用。
- 输入槽为空时使用“空闲”，不显示“输入不足”；输入槽非空时，只有至少存在一个原料身份可匹配但数量不足的候选配方才使用“输入不足”，其余无匹配情况使用“输入无效”。
- 同时满足多个条件时只对外显示优先级最高的一项。例如结构失效时即使内部仍保存待输出批次，主状态仍为“结构无效”，详细信息可以同时注明“修复后将继续等待输出”。
- 状态及全部详细原因由服务端统一计算并形成同一份权威状态快照；控制器 GUI、Jade、控制器纹理、粒子和声音只能读取该快照，不得根据客户端槽位、动画或本地配方缓存分别推测。
- 状态文本、图标和本地化键优先复用 GTCEu 7.5.3 中语义完全一致的现有内容；只有缺少准确语义时才在 `gregsteamexpansion` 下新增，不得把含义不同的状态强行合并。
- 大型焦炉没有主动暂停、能源不足、燃料不足、蒸汽不足、温度不足、预热中或需要维护等状态。
- Easy、Normal、Expert 三档使用完全相同的主状态集合、详细原因和显示优先级。

### 已确认大型焦炉控制器 GUI

- 大型焦炉控制器使用固定 `212×208` 的单页 GUI，整体配色、边框、槽位、流体槽、进度条、字体和悬浮提示风格与 GTCEu 7.5.3 机器界面保持一致，不拆分为库存页与状态页。
- GUI 顶部显示机器名称，并设置一条只读的“状态图标 + 唯一主状态”状态栏；悬浮状态栏时显示权威状态快照中的全部详细原因，以及结构验证已经提供的首个错误坐标或正确朝向等排障信息。
- 机器库存区域从左到右依次排列为 `3×2` 六个物品输入槽、配方图标与进度箭头、`3×2` 六个固体输出槽，以及一个标注 `64,000 mB` 容量的纵向流体输出罐。
- 六个输入槽按界面上从左到右、从上到下固定编号为 `1–6`，与配方选择扫描顺序及原子扣取顺序完全一致；每个输入槽的悬浮提示附带其槽位编号。
- 配方信息行显示当前配方名称或代表物、实际并行 `p/6`、当前进度与锁定总耗时、完成百分比及预计剩余时间；tick 数可以作为精确悬浮信息显示，主要界面使用易读时间。
- 进行中和等待输出状态显示批次已经锁定的配方；准备启动或启动前输出堵塞时显示按既定选择规则得到的候选配方；空闲、输入不足或输入无效时不把任何配方伪装成“当前配方”。
- 最近成功配方若存在，只能在附加提示中明确标记为“优先配方”；它不是运行中批次，也不能覆盖当前锁定配方或候选配方的显示。
- 已完成但尚未提交的精确输出快照显示在“等待输出”的详细信息中，明确标记为“待提交产物”；它不能在实际提交前提前画入六个共享输出槽或流体罐。
- 正在工作时显示随权威进度推进的进度条和剩余时间；结构失效或结构范围未完全加载时保持冻结进度并显示恢复条件；等待输出时进度固定显示为 `100%`，且不再显示仍在加工。
- GUI 继续执行已经确认的手动交互规则：玩家可以向输入槽放入合法原料并取回尚未扣取的输入，可以从固体输出槽取出物品，也可以使用空流体容器从流体罐排出流体。
- 固体输出槽拒绝任何手动放入，流体罐拒绝外部容器向内灌装；GUI 在结构未成型、结构失效或结构范围未完全加载时仍可打开，以便查看状态和回收控制器内未锁定的库存。
- GUI 不提供启动、暂停、停止、清空、强制提交、手动选择配方、修改优先配方、切换大型焦炉仓模式或远程旋转仓的按钮。
- GUI 不显示能源、蒸汽、燃料、温度、预热、维护、控制器等级或其他本机器不存在的系统栏位。
- 界面显示的数据和交互结果均以服务端为准，客户端不得根据本地槽位或配方缓存提前显示批次已启动、产物已提交或状态已经恢复。
- Easy、Normal、Expert 三档使用完全相同的 GUI 尺寸、布局、交互权限和信息范围。

### 已确认大型焦炉 Jade 与探针信息

- 大型焦炉采用按目标方块职责分级的信息范围；Jade 及其他后续明确支持的探针集成只负责查看，不提供物品或流体搬运、仓模式切换、方块旋转、批次控制或任何其他写操作。
- 玩家查看大型焦炉控制器时，显示机器名称、权威主状态及首个当前可处理的详细原因；结构无效时沿用结构验证提供的缺失接口、正确朝向、首个错误坐标、重叠或间距信息。
- 控制器在正在工作、等待输出或准备启动时显示对应的锁定配方或候选配方及实际并行 `p/6`；其他状态不把最近成功的优先配方误显示为当前配方。
- 控制器在正在工作时显示完成百分比和预计剩余时间；等待输出时显示 `100%`、待提交产物状态及固体、流体或两者堵塞的原因；没有锁定批次时隐藏加工进度。
- 控制器探针信息不逐槽展开六个输入槽、六个固体输出槽或完整待输出快照；查看完整库存和批次细节需要打开控制器 GUI。
- 玩家查看大型焦炉仓时，始终显示该仓自身保存的当前模式、合法外向工作面的世界方向，以及正面覆板当前是否允许该模式对应的物流。
- 仓的连接状态区分“已连接且结构有效”“已归属但结构无效”和“未连接”。结构失效不把仍由控制器持有的仓错误显示为未连接。
- 物品输入模式仓只显示共享输入库存的已用槽位数与总槽位数，固体输出模式仓只显示共享固体输出库存的已用槽位数与总槽位数；两者均不逐项公开物品堆栈，也不显示无权访问的其他库存。
- 流体输出模式仓只显示共享流体输出罐中的流体名称、当前存量及固定 `64,000 mB` 容量；空罐显示为空并保留容量信息，不显示物品库存。
- 玩家查看已经归属于大型焦炉的普通焦炉砖或顶部进料斗砖时，只显示“属于大型焦炉”及控制器所在方向；若所有权记录仍在但结构无效，则额外显示“已归属，结构无效”。
- 已归属的焦炉砖不显示配方、并行、进度、库存或堵塞详情；未归属的普通焦炉砖保持其原有方块信息，不新增大型焦炉字段。固定空气位置本身不提供探针信息。
- 探针数据只在玩家实际查看对应方块且位于集成允许的查看范围内时按需从服务端同步，不向周围玩家持续广播整台机器库存或批次快照；具体刷新频率和缓存期限按《已确认性能与区块边界》执行。
- 客户端可以在两次权威进度同步之间做短时显示插值，但服务端保存的状态、进度、配方、并行、库存摘要和仓模式始终具有最终权威，插值不得越过完成点或自行触发状态变化。
- 优先复用 GTCEu 与相应探针模组已有的数据组件和本地化文本；集成未安装时不加载其专用类，不影响大型焦炉注册、存档或运行。
- Easy、Normal、Expert 三档使用完全相同的探针信息范围和权限边界。

### 已确认大型焦炉纹理、模型、粒子与声音

- 大型焦炉采用“三炉室同步、克制反馈”的表现方案。三个炉门由控制器根据同一份权威状态快照统一渲染，不给通用的 `gtceu:coke_oven_bricks` 增加方块实体、持久化状态或独立 tick。
- 只有主状态为“正在工作”且服务端本 tick 实际推进了加工进度时，三个炉门才同步点亮并显示自发光火焰；仅保存着冻结批次不能维持点火表现。
- 实际并行 `1–6` 不映射到特定炉室或点亮数量。三个炉室始终同步开始和熄灭，避免暗示每个可见炉室分别持有批次或固定对应两个并行份额。
- 空闲、输入无效、输入不足、启动前输出堵塞、等待输出、等待重新输入、结构无效和结构范围未完全加载时，三个炉门均显示熄灭状态。
- 控制器正面设置小型状态符号：正在工作使用火焰形，启动前输出堵塞或等待输出使用带感叹号的箱形，结构无效使用断裂轮廓；其余状态不点亮特殊符号。
- 状态符号必须以不同轮廓表达含义，颜色只作辅助，不能成为区分工作、堵塞与结构无效的唯一手段；具体文字原因仍由 GUI 与 Jade 提供。
- 大型焦炉仓正面同时使用颜色与图形显示当前模式：物品输入使用绿色内向箭头，固体输出使用橙色箱形外向箭头，流体输出使用蓝色水滴外向箭头。
- 仓模式标志只出现在仓的合法外向正面，并随仓自身朝向与持久化模式更新；覆板可以覆盖其正常占用区域，但不能让客户端根据覆板外观误判实际模式。
- 顶部砖制进料斗保持由现有焦炉砖组成的静态结构，不播放投料动画，不渲染虚拟物品，不作为烟囱，也不产生工作烟雾。
- 正在工作时从三个炉门生成低密度火焰与烟雾；粒子数量按整台大型焦炉设置总预算，在三个炉门之间分配，不能让每个炉门各自复制一台普通焦炉的完整粒子密度。
- 批次进度首次到达完成点时，整台机器只播放一次短促完成声并生成一次轻微烟气脉冲，不按实际并行份数重复；对应批次保存单次反馈标记，待输出重试、修复或重载不能再次触发。
- 工作声由控制器位置播放一条低音量炉火循环。只有实际推进进度时维持播放；进度冻结、完成或状态改变时立即淡出，恢复实际推进后再淡入。
- 启动前输出堵塞与等待输出不循环报警、不持续生成黑烟，也不继续播放炉火循环；控制器状态符号、GUI 和 Jade 承担持续提示职责。
- 结构首次失效与控制器拆除继续使用第 9B 步已经确认的单次熄火声和黑烟反馈，本项不增加第二套触发或额外事故效果；结构范围未完全加载本身不播放失效反馈。
- 所有粒子遵守客户端粒子等级与关闭设置，全部机器声音遵守相应声音分类及 GTCEu 可适用的机器声音配置；粒子关闭或静音时，炉门明暗、不同轮廓的状态符号及文字信息仍能完整表达状态。
- 所有新增贴图、模型、粒子和声音资产均重新制作，只复用 GTCEu 的视觉尺度、像素密度和材质语言，不复制参考模组资产。
- Easy、Normal、Expert 三档使用完全相同的模型、状态纹理、粒子和声音规则。

### 已确认大型焦炉物品提示与结构说明

- 大型焦炉控制器与大型焦炉仓均使用“默认摘要 + 按住 Shift 展开完整说明”的两级物品提示；默认摘要只保留定位、最重要数值和操作入口，完整结构与限制集中在 Shift 说明中。
- 控制器默认摘要依次说明：这是无需能源的大型批量焦化设备；最大并行 `6`、固定使用原配方 `0.5×` 耗时且满载吞吐等同 `12` 台普通焦炉；按住 Shift 查看结构、接口与危险说明。
- 控制器按住 Shift 后依次说明：
  1. 完整结构包围范围固定为 `7×7×5`，具有三个同步炉室和顶部砖制进料斗；
  2. 合法结构根据仓数量使用 `151–153` 块 `gtceu:coke_oven_bricks` 和 `3–5` 个大型焦炉仓，三种仓模式各至少一个；
  3. 顶部进料斗只承担结构与外观语义，全部自动化必须通过大型焦炉仓；
  4. 机器不消耗能源，不具有燃料、温度、预热、维护或主动暂停；
  5. 最大并行 `6` 且耗时减半，但单份输入与产物完全服从原焦炉配方，不提高单位原料产率；
  6. GTCEu 环境危害启用时，每完成一份并行配方产生 `0.1` 强度的一氧化碳；

- 配方被移除后，其待输出快照仍按原快照提交，这是数据包重载场景下唯一的“配方已消失但批次继续”路径，不视为配方缓存残留。
- 偏好配方被移除时按已确认规则视为无法组成完整输入，并在下一次选配方时回退固定输入槽顺序；进行中批次不受影响。
- 输入输出数量或类型超出 `1` 路物品输入、`1` 路物品输出、`0` 路流体输入、`1` 路流体输出的接口范围，或格式非法的配方拒绝在大型焦炉开工，并记录包含配方资源 ID 与拒绝原因的明确错误；同类错误只在发现时记录一次，不逐 tick 重复刷写日志。
- 数据包重载不重置共享库存、大型焦炉仓模式、覆板、结构所有权或间距记录；重载本身不触发结构失效反馈，也不产生一次性事件重放。

### 已确认存档版本与未来迁移

- 首版即把存档版本字段写入大型焦炉控制器与大型焦炉仓的持久化数据；读取时缺失版本字段的数据一律视为首版，并按首版语义原样初始化。
- 控制器侧的全部运行数据——共享库存、批次记录、结构所有权——使用同一控制器版本字段，不为每个字段单独维护版本号；大型焦炉仓只保存自身模式与版本字段。
- 未来字段变更或结构规则调整时，旧数据先按旧版本语义完整读取，再迁移为新版本语义；迁移不得复制、清空或重复结算任何输入、产物、流体或一次性事件。
- 未来无法安全迁移的批次按已确认的迁移语义处理：取消批次、不返还已扣输入、清除批次记录并进入“等待重新输入”状态；输入槽、输出槽和流体罐中的既有内容全部保留。
- 结构规则未来改变时，旧机器在下次完整结构验证中按新规则判定；不再合法的结构进入已确认的普通结构失效（精确冻结），不提供旧尺寸永久豁免或自动转换。
- 每次迁移在日志中记录受影响控制器位置与迁移原因；迁移结果由服务端权威写入并同步，客户端不能自行推测或补算。

### 已确认性能与区块边界

- 大型焦炉不在每个服务端 tick 扫描完整 `7×7×5` 包围范围，也不反复搜索附近控制器；常规每 tick 逻辑仅为批次进度计数与每 `5 tick` 输出轮询计数，保持常数开销。
- 完整结构验证只在明确事件触发时执行：相关方块放置或破坏、成型回调、区块重载恢复、所有权竞争与间距冲突检查；验证不通过时不做定时轮询重试，由下一个相关事件驱动重新验证。
- 已经成型且无相关方块变化的机器不重复执行完整结构验证；结构失效由事件驱动进入，由重新成型检查恢复。
- 大型焦炉仓主动传输保持已确认的每 `5 tick` 控制器级轮询；轮询只检查对应模式仓正面目标的能力，不遍历机器周围方块。
- Jade 与探针数据按玩家实际查看按需同步，并对进度类字段使用节流；载荷无变化时不重复发送，已归属焦炉砖不产生持续同步流量。
- 多台大型焦炉同时运行时互不扫描、不共享全局搜索；每台机器每 tick 开销为常数级，整体开销随机器数量线性增长。
- 完整包围范围涉及区块不可用时按已确认规则暂停推进，不申请强制加载区块票。
- Easy、Normal、Expert 三档使用相同的验证触发、轮询与同步策略。

### 已确认用户验收清单与执行边界

以下清单整理验收类别、代表操作与预期结果，全部由用户亲自执行；未经用户执行或明确确认的项目一律保持“未验收”，构建成功、数据生成成功或静态检查通过都不能替代实际验收，也不能据此把任何项目标记为通过。

结构验收：

- 按基础结构预览与自动化代表预览各搭建一次，四个水平朝向各成型一次；预期正常成型并显示空闲或准备启动状态。
- 拆除任意外壳砖后打开控制器 GUI 结构预览；预期定位到首个错误坐标，主状态为结构无效，进行中批次进度精确冻结，修复后从原进度继续。
- 拆除控制器；预期按已确认结算掉落内部物品与待输出固体（如有）、全部流体丢失，播放一次熄火声与黑烟。

接口布局验收：

- 分别搭建 `1/1/1`、`2/1/1`、`2/2/1`、`3/1/1` 及其模式排列；预期全部合法成型。
- 移除任一模式的最后一个仓、尝试安装普通焦炉仓或其他非法接口、把仓旋转到非法朝向；预期结构无效并显示对应详细原因。
- 运行中或等待输出时尝试切换仓模式与旋转仓；预期拒绝、保持原状、不消耗耐久。

配方与吞吐验收：

- 原木、煤炭、煤炭块各运行一批；预期实际并行与耗时（`450` / `450` / `4,050 tick`）正确，产物数量守恒。
- 分别以 `4`、`6`、`14` 份煤炭开工；预期与《已确认吞吐与守恒算例》完全一致。
- 至少选取一条外部 `gtceu:coke_oven` 配方验证多单位输入与奇数耗时取整。
- 持续满供料运行；预期煤炭或原木路线达到每分钟 `16` 份稳态吞吐。

堵塞与恢复验收：

- 分别堵塞固体输出与流体输出；预期“启动前输出堵塞”与“等待输出”正确区分，等待输出进度显示 `100%`，解除堵塞后自动恢复且不重复提交。
- 区块卸载重载、退出重进世界、重启服务器各一次；预期进度精确恢复、物品与流体不复制不丢失、一次性事件不重放、偏好配方保持。

安全与环境验收：

- 启用与关闭 `environmentalHazards` 各测一批；预期启用时按 `0.1 × p` 排放一次，关闭时不产生也不积累补发。
- 用外部爆炸破坏结构；预期只按实际被移除部位结算，无二次爆炸、火焰或连锁事故。

档位与表现验收：

- Easy 与 Expert 各抽查一批；预期与 Normal 数值完全一致，降档不重置状态。
- 核对三炉门同步点火与熄灭、状态符号轮廓区分、粒子总预算、完成声单次播放、失效与拆除反馈单次触发。

多机与性能验收：

- 两台大型焦炉外表面贴靠尝试成型；预期拒绝并提示间距不足，间隔一格后正常成型。
- 两台以上同时满载运行；预期互不干扰、吞吐各自达标，无异常卡顿。
