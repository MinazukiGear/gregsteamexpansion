# 机器与机器部件总体设计

本文档汇总 Greg Steam Expansion 的单方块机器、多方块机器、仓室、总线、能源仓及其他机器部件。普通物品、结构方块和非机器方块另见[物品与方块总体设计](items-and-blocks.md)。

## 当前设计范围

当前纳入：

- 已定案的蒸汽供给仓、蒸汽流体输入/输出仓与蒸汽进气室；
- 已有独立规格的单方块机器和多方块控制器的范围索引；
- 机器与机器部件的身份、替代关系、获取方式、运行边界、兼容性和实现验收条件。

当前总览不重复展开：

- 单方块机器的输入、输出、GUI、配方处理和运行数值，具体内容由各机器独立规格定义；
- 多方块控制器的机器结构、并行、温度、能耗和安全机制，具体内容由各控制器独立规格定义；
- 尚无独立规格的其他蒸汽仓、排气仓、总线、能源仓及机器接口；
- 为尚未设计的单台机器预先确定专属零件数量或强行注册一次性占位内容。

## 内容范围总览

| 当前类别 | 状态 | 说明 |
| --- | --- | --- |

| 多方块控制器 | 独立规格 | 大型蓄热蒸汽熔炉见[开发指导](large-heat-storage-steam-furnace.md)，蒸汽粉碎机与大型蒸汽粉碎机见[设计规格](steam-crushers.md) |

## 已定案：蒸汽供给仓

### 身份与替代关系

| 字段 | 设计 |
| --- | --- |
| 状态 | 已定案，尚未实现 |
| 类型 | GTCEu 多方块机器部件、蒸汽供给接口 |
| 中文名 | 蒸汽供给仓 |
| 英文名 | Steam Supply Hatch |
| 资源 ID | `gregsteamexpansion:steam_supply_hatch` |
| Java 注册字段 | `GSEMachines.STEAM_SUPPLY_HATCH` |
| Java 实现类 | `SteamSupplyHatchPartMachine` |
| 科技阶段 | 蒸汽时代 |
| 核心用途 | 储存并向需要 `PartAbility.STEAM` 的多方块机器提供 GTCEu 标准蒸汽 |
| 方块物品 | 与方块同名、同 ID，最大堆叠 64 |

- 本模组自行注册完整的新机器部件，不再把 `GTMachines.STEAM_HATCH` 作为本模组代码中的蒸汽供给仓别名，也不修改 `SteamHatchPartMachine` 的构造器或机器定义元数据。
- 新仓使用独立资源 ID、实现类、本地化、模型、物品提示和数据生成条目；只有结构能力继续复用 GTCEu 的 `PartAbility.STEAM`，以兼容蒸汽烤炉、蒸汽碾磨机及本模组后续蒸汽多方块机器。
- GTCEu 蒸汽输入仓的原始单槽缓存为 `64,000 mB`；本模组替代仓按“缓存减半”重新实现为 `32,000 mB`，不再通过 Mixin 修改上游旧仓容量。
- GTCEu 原对象 `gtceu:steam_input_hatch` 保留注册身份只为安全读取旧存档，不再作为可获取、可放置或可参与结构的正常玩法内容。
- 不尝试从已经冻结的 Forge 注册表中注销上游方块或物品。强行注销会产生缺失映射、空气替换和方块实体数据丢失，不属于可接受的“禁用”方式。

### GTCEu 蒸汽输入仓的禁用范围

目标限定为 GTCEu 7.5.3 的 `GTMachines.STEAM_HATCH`、资源 ID `gtceu:steam_input_hatch`、实现类 `SteamHatchPartMachine` 及配方 ID `gtceu:steam_hatch`。禁用必须同时完成以下项目：

1. 以精确 ID 覆盖或移除 `gtceu:steam_hatch`，使任何工作强度和 `steelSteamMultiblocks` 配置下都不能继续合成上游蒸汽输入仓。
2. 在 `PartAbility.STEAM` 登记阶段精确跳过 `gtceu:steam_input_hatch`，并登记本模组蒸汽供给仓；旧仓因此不能让蒸汽多方块结构成型，新仓成为普通结构中唯一的标准蒸汽供给部件。
3. 从 GTCEu 创造模式页和 EMI/其他配方查看器的普通物品索引中隐藏旧仓；管理员仍可通过完整资源 ID 识别遗留对象，但不能把它误认为可用内容。
4. 拦截旧仓物品的放置行为并先按 `1:1` 转换为本模组蒸汽供给仓，再执行正常放置；通过命令或旧容器取得的遗留物品不能重新放置出旧方块。
5. 旧仓方块不再暴露可被机器消费的蒸汽能力，也不允许仅因仍持有流体槽而绕过结构能力禁用。

- 禁用逻辑只能精确匹配上述注册对象和 ID，不能按名称包含 `steam`、实现类父类、`PartAbility.STEAM` 的全部内容或所有 GTCEu 输入仓批量处理。
- 启动时必须核验“旧仓未登记、新仓已经登记、旧配方不存在”三个条件；出现半生效状态时记录明确错误并阻止载入世界，避免机器在不同重启间接受不同仓。
- 若保留 `[7.5.3,8.0.0)` 的 GTCEu 依赖范围，则每个实际支持版本都必须重新核验注册阶段、配方 ID 和能力登记方式；否则应把依赖范围收窄到已经验证的版本。

### 流体缓存与行为

- 蒸汽供给仓创建 `1` 个输入流体槽，固定容量为 `32,000 mB`，只接受 GTCEu 标准蒸汽及该流体所属的上游标准蒸汽标签。
- 仓本身不生产蒸汽、不消耗蒸汽执行配方，也不把其他模组的同名蒸汽、过热蒸汽或其他蒸汽变体自动转换为 GTCEu 蒸汽。
- 对外提供 Forge 流体输入能力和 GTCEu 配方输入能力；默认允许从相邻流体管道主动或被动输入，不能向外部管道主动输出。
- 面向机器外侧的正面允许安装 GTCEu 封面，输入方向、自动输入开关和封面限制沿用标准 GTCEu 流体仓行为；`swapIO()` 固定返回不允许切换，不能改造成蒸汽输出仓。
- GUI 使用蒸汽风格背景，显示仓名、当前存量、`32,000 mB` 上限、单个流体槽和玩家物品栏。物品提示、GUI、Jade/探针和流体能力查询必须报告同一个实际上限。
- 大型蓄热蒸汽熔炉等机器规定的每仓 `1,200 mB/t` 机器侧供汽上限继续独立生效；仓有 `32,000 mB` 缓存不表示它能在一个 tick 内全部送入机器。

### 工作强度

缓存容量和配方产出都是蒸汽供给仓自身的固定设计。缓存不读取[全局工作强度机制](difficulty.md)的单方块锅炉缓存倍率；配方产出明确作为本模组新增方块通用产量 `2 / 1 / 1` 的例外，三档均固定为 `1` 个。

| 英文难度 | 中文显示名 | 每份配方产出 | 单仓缓存容量 |
| --- | --- | ---: | ---: |
| `Easy` | 摸鱼 | `1` | `32,000 mB` |
| `Normal` | 舒适 | `1` | `32,000 mB` |
| `Expert` | 压榨 | `1` | `32,000 mB` |

- 三档的配方产出、槽位数、蒸汽过滤、自动输入、封面支持、结构能力和 GUI 行为完全一致。
- 从遗留上游仓迁移或转换得到的新仓始终按 `1:1` 处理，不读取配方产出倍率，防止旧物品在 Easy 下被复制。

### 获取方式

蒸汽供给仓使用固定的青铜材料路线，以青铜板形成壳体、普通青铜流体管形成进汽通道、青铜桶提供内部容器。基础手工配方为：

```text
B P B
B T B
B P B
```

| 符号 | 输入 |
| --- | --- |
| `B` ×6 | GTCEu 青铜板（`plate / Bronze`） |
| `P` ×2 | GTCEu 普通青铜流体管（`pipeNormalFluid / Bronze`） |
| `T` ×1 | GTCEu 青铜桶（`gtceu:bronze_drum`） |

- 配方资源 ID 为 `gregsteamexpansion:shaped/steam_supply_hatch`；它输出本模组新仓，不覆盖或重新使用 `gtceu:steam_hatch`。
- 配方始终使用上述青铜材料，不读取 GTCEu 的 `machines.steelSteamMultiblocks` 配置，也不生成钢板、普通钢流体管和钢桶分支。
- 每份配方在 Easy、Normal 与 Expert 下均固定产出 `1` 个蒸汽供给仓。
- 当前不提供组装机路线，也不接受普通流体输入仓、旧蒸汽输入仓或任意储罐作为无损替代材料。
- 旧仓物品到新仓物品的 `1:1` 迁移属于存档兼容，不是正常获取配方，应从配方查看器隐藏且不能反向转换。

### 方块、模型与提示

- 方块具有六向朝向，使用 GTCEu 机器方块与机器部件的标准物理属性、扳手旋转、正确工具采集、掉落自身和封面行为；不增加含水、红石模式、发光或独立工作状态。
- 模型继续使用与当前 `steelSteamMultiblocks` 配置一致的 GTCEu 青铜或钢制蒸汽外壳纹理，但正面覆盖层由本模组提供，不复用上游蒸汽输入仓的泵封面图案。
- 新正面图案使用朝向机器内部的粗蒸汽管法兰、阀门轮廓和向内汇聚的箭头语言，强调“向结构供汽”而不是通用流体输入；在青铜和钢制底壳上都必须保持清晰。
- 未成型和已成型状态可以改变正面接口的连接表现，但不发光、不播放持续动画，也不把视觉状态写成额外玩法能力。
- 默认提示包含 `流体容量：32,000 mB` 和 `接受流体：蒸汽`；增加一行灰色说明：`为蒸汽多方块机器提供蒸汽。`
- 对应英文说明为 `Supplies steam to steam multiblock machines.`；所有中文文本只使用“蒸汽供给仓”，不再把新对象称为“蒸汽输入仓”。

### 旧存档迁移

- 服务器首次加载含 `gtceu:steam_input_hatch` 的区块时，在服务端把旧方块原位替换为 `gregsteamexpansion:steam_supply_hatch`，保留朝向、外观染色、可迁移封面和仓内蒸汽。
- 迁移前先完整读取旧方块实体状态，成功创建并写入新仓后再移除旧方块实体；任一步骤失败时保持旧对象和原数据不变并记录坐标，不能留下空气或半写入的新仓。
- 旧仓中不超过 `32,000 mB` 的蒸汽直接写入新仓。超过新上限的存量也不得删除或复制：新仓暂时保留超额蒸汽、拒绝继续输入并允许机器正常消耗，降至 `32,000 mB` 以内后恢复普通容量行为。
- 能够由新仓支持的封面按原面迁移；不兼容封面以物品形式安全掉落。迁移不得同时保留封面数据并生成掉落，避免复制。
- 物品栏、容器、掉落物和玩家手中的旧仓在被加载、移动或尝试使用时按 `1:1` 转换；转换不携带额外蒸汽，也不产生配方统计或工作强度产量加成。
- 完成迁移后不反向写回旧 ID。即使以后移除本模组，已经迁移的新仓也按本模组内容缺失处理，因此发布说明必须把该迁移标记为不可逆的世界升级。

### 实现验收

1. `gregsteamexpansion:steam_supply_hatch` 独立注册且名称、模型、掉落和物品模型完整；`gtceu:steam_input_hatch` 仍可解析旧存档，但不出现在正常获取入口中。
2. `gtceu:steam_hatch` 不存在，本模组只加载固定的青铜配方；无论 `machines.steelSteamMultiblocks` 和工作强度为何值，每份都只产出 `1` 个。
3. 旧仓不能让任何要求 `PartAbility.STEAM` 的结构成型；新仓能让 GTCEu 蒸汽烤炉、蒸汽碾磨机和本模组对应结构正常成型与取汽。
4. 空的新仓最多输入 `32,000 mB` GTCEu 蒸汽，第 `32,001 mB` 被拒绝；其他流体和非标准蒸汽始终被拒绝。
5. 物品提示、GUI、Jade/探针和能力查询均显示实际 `32,000 mB`，普通流体仓、ME 流体仓、锅炉、管道及其他容器容量不受影响。
6. 已放置旧仓、旧仓物品和超过新上限的旧仓存量分别完成无丢失、无复制迁移；重复加载同一区块不会再次转换或重复掉落封面。

## 已定案：蒸汽流体输入/输出仓

本文档定义 Greg Steam Expansion 为蒸汽时代多方块机器新增的配方流体接口。它们与 GTCEu 现有蒸汽输入/输出总线处于同一科技阶段，分别把流体交给配方系统或接收配方产出的流体；它们不负责向机器提供作为能源的蒸汽。

### 设计目标

- 让明确支持流体槽的蒸汽时代多方块机器能够在进入 LV 之前执行含流体输入或输出的配方。
- 保持 GTCEu 的接口分工：物品使用蒸汽总线，配方流体使用本设计的新仓，能源蒸汽使用[蒸汽供给仓](machines-and-hatches.md#已定案蒸汽供给仓)。
- 以 GTCEu 7.5.3 的蒸汽总线和 LV 单流体仓为基准，不引入多流体巨型缓存、无限流量或流体转换能力。
- 只有机器规格和配方类型都声明支持流体时，新仓才产生作用；注册新仓不能暗中扩大已有配方类型的输入、输出语义。

### 上游基准与取值

GTCEu 7.5.3 没有蒸汽时代的通用配方流体仓。现有 `SteamItemBusPartMachine` 固定以 tier `1` 构造，因此蒸汽输入/输出总线各有 `(1 + 1)² = 4` 个物品槽；现有单槽 `FluidHatchPartMachine` 的容量公式为 `8,000 << tier` mB，因此 LV（tier `1`）单流体仓容量为 `16,000 mB`。

本设计沿用这两个尺度：新仓是蒸汽总线的流体对应物，但容量采用同阶段 LV 单流体仓的 `16,000 mB`，不采用能源蒸汽仓的 `32,000 mB`。容量只是缓存上限，不改变配方耗液量和产液量。

### 注册身份

| 字段 | 蒸汽流体输入仓 | 蒸汽流体输出仓 |
| --- | --- | --- |
| 状态 | 已定案，尚未实现 | 已定案，尚未实现 |
| 英文名 | Steam Fluid Input Hatch | Steam Fluid Output Hatch |
| 资源 ID | `gregsteamexpansion:steam_fluid_input_hatch` | `gregsteamexpansion:steam_fluid_output_hatch` |
| Java 注册字段 | `GSEMachines.STEAM_FLUID_IMPORT_HATCH` | `GSEMachines.STEAM_FLUID_EXPORT_HATCH` |
| Java 实现类 | `SteamFluidHatchPartMachine`，`IO.IN` | `SteamFluidHatchPartMachine`，`IO.OUT` |
| 结构能力 | `GSEPartAbilities.STEAM_IMPORT_FLUIDS` | `GSEPartAbilities.STEAM_EXPORT_FLUIDS` |
| 配方能力 | `RecipeCapability.FLUID` 输入 | `RecipeCapability.FLUID` 输出 |
| 储罐 | `1` 个 | `1` 个 |
| 固定容量 | `16,000 mB` | `16,000 mB` |
| 科技阶段 | 蒸汽时代 | 蒸汽时代 |

- 两个仓都是本模组独立注册的完整机器部件，不覆盖 GTCEu 任意电压等级的普通流体仓，也不修改 `FluidHatchPartMachine` 的全局行为。
- 两个自定义结构能力只登记对应的新仓，不把普通 LV 流体仓、蒸汽供给仓或第三方储罐批量登记进来。
- 新仓不能登记到 `PartAbility.STEAM`。即使输入仓中装有 `gtceu:steam`，它也只是一份候选配方流体，不能形成供汽要求、推进机器进度或绕过供汽流量限制。
- 新仓不登记到通用 `PartAbility.IMPORT_FLUIDS` 或 `PartAbility.EXPORT_FLUIDS`。电力多方块不能把廉价蒸汽仓当作普通电压流体仓；需要兼容时必须由具体控制器显式同时接受两类结构能力。

### 储罐与流体语义

- 每个仓只有一个独立储罐，同一时刻只能保存一种具有相同流体与附加 NBT 数据的 `FluidStack`。不同流体不会在仓内混合、转换或自动替换。
- 输入仓可以保存任意已注册流体；能否用于加工仍由当前配方的流体原料、数量、附加 NBT 数据和配方条件决定。仓本身不建立“水”“润滑剂”或“蒸汽”等白名单。
- 输出仓可以接收当前配方声明的任意流体产物。仓不把气体自动放空，不把高温流体转为冷却流体，也不把蒸汽变为冷凝水。
- 首版不增加温度、压力、腐蚀性或材料相容性判定。高阶流体即使能够存入，也不会让只允许蒸汽时代或 LV 配方的控制器越级执行配方。
- `16,000 mB` 是每个仓的固定容量，Easy、Normal、Expert 完全相同，不读取全局工作强度倍率。
- 新仓没有机器侧固定 `mB/t` 流量上限。外部搬运速度由相邻管道、覆盖板和调用方决定；配方系统只在开始批次时检查完整输入量和完整输出空间。
- 需要同时容纳多种流体时，玩家必须安装多个仓。单个仓不会因为配方类型声明多个流体槽而动态变成多槽仓。

### 外部交互与方向

- 输入仓的自动化方向固定为外部输入、配方消耗：允许相邻流体管道和容器向仓内填充，不主动向外部管道输出。
- 输出仓的自动化方向固定为配方产出、外部输出：允许相邻流体管道从仓内抽取，可启用主动输出，不接受外部自动填充。
- GUI 中的手持容器交互允许玩家安全取回仓内流体；手动取回不改变仓的自动化方向，也不能把输出仓作为外部管网的输入端。
- 面向机器外侧的正面允许安装 GTCEu 兼容覆盖板。覆盖板过滤、流体锁定和自动输入/输出开关沿用标准流体仓语义，但不能把仓切换成能源蒸汽接口。
- GUI 提供一个流体槽、流体锁定、自动输入或自动输出开关、当前存量/容量和玩家物品栏；不提供编程电路槽。需要编程电路的蒸汽机器继续使用蒸汽物品输入总线的幽灵电路位。
- 两个仓都支持与蒸汽总线一致的 I/O 对调操作。在世界中用螺丝刀执行 `swapIO()` 时，输入仓与输出仓互换，必须原样保留流体、朝向、染色、可兼容覆盖板和流体锁定；任一状态无法完整迁移时拒绝对调，不得清空或掉落部分内容。

### 配方匹配与原子性

- 控制器通过 GTCEu 标准 `RecipeCapability.FLUID` 读取新仓的配方处理器，不为蒸汽时代另建一种流体配方格式。
- 同方向的多个仓由控制器按 GTCEu 标准处理器列表参与配方模拟。配方允许从多个输入仓合计取得同一种流体，也允许不同仓分别提供不同流体。
- 开始批次前必须先模拟全部物品输入、流体输入、物品输出空间、流体输出空间和能源蒸汽；任一条件不足时整批不启动。
- 输入只在整批模拟成功后一次性提交。不得出现物品已扣除但流体未扣除、流体已扣除但蒸汽不足，或多个输入仓只扣除一部分后失败的状态。
- 流体输出在开始时预留完整空间。输出仓容量不足、流体锁定不匹配，或已有流体与产物不兼容时不得启动；完成时不得截断、销毁、掉落到世界或回填输入仓。
- 同一种流体同时作为配方输入和输出时，输入仓与输出仓仍按两个方向分别结算，不使用“净消耗量”绕过输出空间预检。
- 区块卸载、结构失效、手动停机或排气受阻时，已启动批次的处理遵循具体控制器的暂停与持久化规则；新仓本身不重放扣取，也不独立推进配方。

### 机器与配方类型接入

- 控制器的结构谓词必须显式接受 `GSEPartAbilities.STEAM_IMPORT_FLUIDS` 和/或 `GSEPartAbilities.STEAM_EXPORT_FLUIDS`，并分别规定最少数量、最多数量和合法替换位置。仅注册仓体不会修改任何现有结构。
- 配方类型必须显式声明大于 `0` 的最大流体输入或输出槽数。仓的存在不能让声明 `0` 槽的配方类型携带隐藏流体，也不能让控制器执行未注册的其他配方类型。
- 某一方向没有流体需求时，控制器可以不要求对应仓；若结构允许可选空仓，空仓只占一个合法接口位置，不提供速度、并行、效率或产量加成。
- 本模组不能全局修改 GTCEu 的蒸汽烤炉、蒸汽碾磨机或其他上游控制器来接受新仓。以后若要让某台既有机器运行含流体配方，必须在该机器的独立规格中同时审查结构、配方类型、平衡和兼容性。
- 普通 LV 及更高等级流体仓不会自动成为蒸汽机器的合法接口。是否在进入电力时代后允许它们作为替代件，由每台机器的结构规格决定，而不是由本通用仓规格决定。

#### 与矿石粉碎的边界

[矿石粉碎配方类型](ore-crushing.md)首版仍是干式破碎：最多 `1` 个物品输入、`4` 个物品输出，流体输入和输出均为 `0`。本设计不会改变其配方迁移条件，也不会给矿石粉碎机器添加“注水增产”等隐藏行为。

若以后需要“矿石 + 水/化学液体”的湿式处理，应使用洗矿、化学浸洗或另一种语义明确的独立配方类型；不能仅因蒸汽流体仓已经存在，就把流体原料塞入 `gregsteamexpansion:ore_crushing`。

### 获取方式

两个仓都必须在蒸汽时代无需电力即可制作。基础路线直接使用青铜板、青铜流体管、青铜桶和青铜转子组装完整接口，不消耗蒸汽物品总线，也不使用锻造锤、扳手、螺丝刀等任何 GTCEu 工具位。


输出仓把中央纵向管路与转子的位置上下对调：

```text
P R P
T D T
P T P
```

| --- | --- |
| `P` ×4 | GTCEu 青铜板（`plate / Bronze`） |

| `R` ×1 | GTCEu 青铜转子（`rotor / Bronze`） |

- 两份配方不开启上下镜像；输入仓的单根纵向管位于上方，输出仓的单根纵向管位于下方。普通的水平镜像不改变图案，也不会使两份配方冲突。
- 每份配方固定产出 `1` 个对应仓，不读取工作强度的通用方块产量倍率，也不读取 `machines.steelSteamMultiblocks`。
- 不注册工作台上的输入仓/输出仓相互转换配方，避免为了转换引入螺丝刀工具位或产生方块实体数据丢失路径。已经放置的仓仍可通过世界中的 `swapIO()` 安全对调。
- 不允许用蒸汽输入/输出总线、蒸汽供给仓、普通 LV 流体仓或任意储罐进行无损替换。

#### 组装机配方

进入 LV 后提供材料成本相同的自动化路线。两种方向使用编程电路配置区分，不消耗编程电路：

- 两条组装机配方不接受蒸汽总线或已经制成的任意仓作为输入，也不使用任何 GTCEu 工具。
- 手工和组装机配方在 Easy、Normal、Expert 下使用相同材料并固定产出 `1` 个；能耗、持续时间与编程电路配置同样不随工作强度改变。

### 模型、界面与提示

- 方块具有六向朝向并使用与蒸汽总线相同的蒸汽机械外壳选择规则；`machines.steelSteamMultiblocks` 只改变青铜/钢制底壳外观，不改变配方、容量、能力或科技阶段。
- 正面覆盖层使用流体仓法兰和粗管轮廓。输入仓使用朝向机器内部汇聚的箭头，输出仓使用向外扩散的箭头；图形轮廓必须可区分，不能只依赖颜色。
- GUI 使用蒸汽风格背景和标准流体槽组件。物品提示、GUI、Jade/探针和流体能力查询必须一致显示 `16,000 mB`。
- 两个仓的默认提示都包含 `流体容量：16,000 mB`。输入仓说明为 `向蒸汽多方块机器提供配方流体。`，输出仓说明为 `接收蒸汽多方块机器产出的配方流体。`
- 提示额外使用醒目但非警告色的一行说明：`不能为机器提供能源蒸汽。`，避免与蒸汽供给仓混淆。

### 明确不包含的功能

- 不生产、加热、冷却、压缩、稀释或转换任何流体。
- 不充当蒸汽供给仓、锅炉、排气仓、消声仓、泵仓、储罐控制器或流体直通仓。
- 不提供多槽、ME 网络、远程供液、量子存储、无限水、自动销毁或冷凝水回收。
- 不根据仓的数量提升并行、速度、能源蒸汽效率或配方产量。
- 不自动把含流体配方降到蒸汽时代；控制器仍必须遵守其允许的配方类型、功率、温度和其他阶段限制。

### 实现验收

1. 两个新仓以独立 ID 注册，分别只登记自定义的蒸汽配方流体输入/输出结构能力；它们不登记 `PartAbility.STEAM` 或通用流体仓能力。
2. 每仓恰好有 `1` 个 `16,000 mB` 储罐，三档容量一致；第 `16,001 mB` 被拒绝，存量不会因重载、拆装或 I/O 对调丢失或复制。
3. 输入仓允许外部填充并可被配方消耗，输出仓可接收配方产物并被外部抽取；反方向自动化操作被拒绝。
4. 两种流体输入、两种流体输出的测试配方在安装足够仓时能够完成，缺少任一流体或输出空间时完全不启动且不发生部分扣取。
5. 输入仓装满 `gtceu:steam` 仍不能满足任何 `PartAbility.STEAM` 要求；蒸汽供给仓也不能被配方当作普通流体输入仓读取。
6. `swapIO()` 完整保留流体、朝向、染色、兼容覆盖板和锁定设置；有任一数据无法迁移时原方块保持不变。
7. 两份手工配方都不消耗蒸汽总线或任何 GTCEu 工具，各使用 `4` 个青铜板、`3` 个普通青铜流体管、`1` 个青铜桶和 `1` 个青铜转子，在蒸汽时代固定产出 `1` 个对应仓。
8. 两份组装机配方分别使用编程电路配置 `1` 和 `2`，均以 `16 EU/t` 执行 `100 tick` 并固定产出 `1` 个；输入材料与对应手工配方完全相同。
9. 工作台中不存在两个仓的相互转换配方；世界内 `swapIO()` 仍按完整状态迁移规则安全工作。
10. `gregsteamexpansion:ore_crushing` 仍以 `0` 个流体输入和输出槽注册，迁移后的矿石粉碎配方不因新仓存在而改变。


## 已定案：蒸汽进气室

### 注册身份与职责

| 字段 | 设计 |
| --- | --- |
| 状态 | 已定案，尚未实现 |
| 类型 | GTCEu 多方块机器部件、环境空气采集接口 |
| 中文名 | 蒸汽进气室 |
| 英文名 | Steam Air Intake Hatch |
| 资源 ID | `gregsteamexpansion:steam_air_intake_hatch` |
| Java 注册字段 | `GSEMachines.STEAM_AIR_INTAKE_HATCH` |
| Java 实现类 | `SteamAirIntakeHatchPartMachine` |
| 结构能力 | `GSEPartAbilities.STEAM_AIR_INTAKE` |
| 配方能力 | `RecipeCapability.FLUID` 输入，仅提供仓内的 GTCEu 标准空气 |
| 科技阶段 | 蒸汽时代 |
| 核心用途 | 作为后续蒸汽多方块结构的专用成型部件，周期性采集并缓存空气供所属结构内部消耗 |
| 方块物品 | 与方块同名、同 ID，最大堆叠 64，不保存拆除前的空气 |

- 名称中的“蒸汽”表示科技阶段和适用结构，不表示进气室消耗、生产或储存能源蒸汽。
- 进气室使用独立结构能力；只有在自身结构规格中显式接受 `GSEPartAbilities.STEAM_AIR_INTAKE` 的控制器才能用它成型，并由控制器分别规定最少数量、最多数量和合法替换位置。
- 进气室不登记 `PartAbility.STEAM`、`PartAbility.IMPORT_FLUIDS`、`GSEPartAbilities.STEAM_IMPORT_FLUIDS` 或其他通用流体仓能力，不能替代蒸汽供给仓、蒸汽流体输入仓或任意电压等级的普通流体输入仓。
- GTCEu 7.5.3 已注册标准空气材料 `GTMaterials.Air`，本设计直接缓存其对应流体，不新增“蒸汽空气”、压缩空气或另一份同义流体。

### 采集速率与缓存

进气室创建 `1` 个只读来源的内部流体槽，固定容量为 `64 B`（`64,000 mB`），槽内只允许存在 GTCEu 标准空气。设计基准为 GTCEu 7.5.3 气体收集器在主世界中以 `16 EU/t`、`200 tick` 产出 `10,000 mB` 空气的配方；进气室使用较长的内部采集配方周期，并同比提高单次产量，使平均产出速率保持一致：

| 项目 | 设计值 |
| --- | ---: |
| 采集周期 | `80 tick`（4 秒） |
| 每周期采集量 | `4,000 mB` |
| 平均采集速率 | `50 mB/t` |
| 固定缓存容量 | `64 B`（`64,000 mB`） |
| 从空仓到满仓 | `1,280 tick`（64 秒） |

- 每次周期完成时实际写入量为 `min(4,000 mB, 剩余容量)`；剩余空间不足 `4,000 mB` 时只补满空余部分，不溢出、不排放，也不把超额部分记到下一周期。
- 采集不消耗蒸汽、EU、物品、耐久或其他流体。其限制来自专用结构资格、环境检查、固定速率以及不能向结构外输出空气。
- `64,000 mB` 容量、`80 tick` 周期和 `4,000 mB` 单次采集量在 Easy、Normal、Expert 下完全相同，不读取全局工作强度倍率、锅炉缓存倍率或普通方块配方产量倍率。
- 仓满时停止推进采集计时；空气被所属多方块消耗并产生空间后，必须重新经过一个完整的 `80 tick` 周期才会写入下一批空气。

### 成型、环境与计时规则

只有同时满足以下条件时，进气室才推进服务端采集计时：

1. 进气室已经属于一个有效成型的多方块结构；
2. 所在维度为 `minecraft:overworld`；
3. 从进气室正面相邻位置开始的第 `1` 格通过严格方块空气判定；
4. 内部空气存量低于 `64,000 mB`。

- 严格空气判定接受普通空气、洞穴空气和虚空空气；积雪层、火焰、植物、藤蔓、蜘蛛网、无碰撞方块和流体都视为阻塞。进气室不会破坏、替换或自动清理正面的方块。
- 正面阻塞、维度不符或仓满不会单独使已经成型的结构失效，但会停止采集并立即清零本轮未完成的计时。条件恢复后计时固定回到 `80 tick`，不能保留停止前的部分周期进度。
- 结构失效时立即清零本轮未完成的采集计时，但保留已经写入内部槽的空气；重新成型后必须重新等待完整的 `80 tick`。
- 区块卸载期间不推进计时，也不按离线时间补发空气。已经完成的空气存量必须持久化，未完成的周期进度不持久化；重新加载仍满足全部条件时，从完整的 `80 tick` 周期起点开始计时。
- 计时、环境检查和流体写入只在逻辑服务端执行。客户端只接收显示所需的存量、阻塞状态和剩余周期，不得独立生成空气。

### 流体访问边界

- 进气室不接受相邻管道、覆盖板、手持容器或其他机器填充任何流体，也不向这些外部对象暴露可抽取的 Forge 流体能力。
- 已成型控制器可以把进气室的内部槽作为 `RecipeCapability.FLUID` 输入处理器读取和消耗，但只能取得实际已经缓存的空气；结构能力本身不等于无限空气，也不能允许配方透支下一周期的产出。
- 多个进气室可以分别采集和缓存空气；是否允许安装多个、配方能否合计消耗多个仓的存量以及每台机器的空气需求，全部由具体控制器规格决定。
- 配方扣取必须沿用控制器对全部物品、流体、能源蒸汽和输出空间的原子模拟规则。完整条件不足时不得只扣除进气室中的空气。
- 未成型时 GUI、Jade/探针可以显示已有存量，但控制器之外的配方系统和外部自动化不能消费该存量。拆除方块时空气直接散失，掉落的方块物品不携带流体数据。
- `swapIO()` 固定返回不允许切换；进气室不能改造成空气输出仓、普通流体输出仓或能源蒸汽接口。

### 获取方式

进气室必须能够在纯蒸汽阶段手工制作。青铜板形成外壳，普通青铜流体管形成内部风道，青铜桶形成缓存腔，青铜转子充当被动叶轮，青铜构件固定叶轮与风道：

```text
P R P
T D T
P C P
```

| 符号 | 输入 |
| --- | --- |
| `P` ×4 | GTCEu 青铜板（`plate / Bronze`） |
| `T` ×2 | GTCEu 普通青铜流体管（`pipeNormalFluid / Bronze`） |
| `D` ×1 | GTCEu 青铜桶（`gtceu:bronze_drum`） |
| `R` ×1 | GTCEu 青铜转子（`rotor / Bronze`） |
| `C` ×1 | 本模组青铜构件（`gregsteamexpansion:bronze_component`） |

- 手工配方资源 ID 为 `gregsteamexpansion:shaped/steam_air_intake_hatch`，固定产出 `1` 个，不读取工作强度的普通方块产量倍率或 `machines.steelSteamMultiblocks`。
- 配方不开启上下镜像；水平镜像不改变图案。它与蒸汽流体输入/输出仓的配方都不相同，不允许三类仓在工作台中无损互转。
- 进入 LV 后提供材料成本相同的组装机路线，使用编程电路配置 `3`，以 `16 EU/t` 执行 `100 tick`，总耗能 `1,600 EU`，固定产出 `1` 个。
- 手工和组装机路线都不接受蒸汽供给仓、蒸汽流体仓、普通流体仓、气体收集器或任意储罐作为替代输入。

### 方块、界面与提示

- 方块具有六向朝向，使用 GTCEu 蒸汽机器部件的标准物理属性、扳手旋转、正确工具采集、掉落自身和染色行为；面向外界的一面固定为进气正面。
- 进气正面不允许安装覆盖板，避免格栅在视觉上被封闭但仍通过相邻空气判定；其他面可以沿用 GTCEu 机器部件的覆盖板安装规则，但覆盖板不能取得进气室未暴露的填充、抽取或 I/O 切换能力。
- 模型使用与 `machines.steelSteamMultiblocks` 当前配置一致的青铜或钢制蒸汽外壳底纹；正面覆盖层表现大面积百叶格栅、中心青铜叶轮和向内汇聚的空气箭头，轮廓上必须与流体法兰和蒸汽供给阀区分。
- 首版不播放持续叶轮动画、不发光、不产生粒子；每次成功采集也不单独播放声音，避免多个进气室按固定周期形成同步噪声。
- GUI 只提供只读空气槽、当前存量/`64,000 mB`、距离下次采集的 tick 数和当前状态，不提供容器交互槽、自动输入/输出开关、流体锁定或编程电路槽。
- 状态固定区分 `采集中`、`缓存已满`、`进气口阻塞`、`维度不支持` 和 `结构未成型`；多个条件同时成立时按 `结构未成型` > `维度不支持` > `进气口阻塞` > `缓存已满` > `采集中` 的顺序显示。GUI 与 Jade/探针必须使用同一服务端状态来源。
- 默认提示包含 `空气容量：64 B（64,000 mB）`、`采集速率：每 80 tick 4,000 mB` 和灰色说明 `为已成型的蒸汽多方块机器采集空气。`；另加醒目说明 `不能向管道或容器输出空气。`

### 明确不包含的功能

- 不采集下界空气、末地空气、液态空气、氧气、氮气或任意第三方空气变体，也不依据生物群系、海拔、天气或污染状态改变产量。
- 不充当气体收集器、空气压缩机、储罐、通用无限流体源、蒸汽供给仓、配方流体输入仓或排气仓。
- 不根据进气室数量直接提供并行、速度、效率、温度、压力或产量加成；机器只能消费各仓实际缓存的空气。
- 不为 GTCEu 上游多方块全局增加结构资格。任何现有或未来控制器都必须显式接入专用能力后才能接受该部件。

### 实现验收

1. `gregsteamexpansion:steam_air_intake_hatch` 独立注册，并且只登记 `GSEPartAbilities.STEAM_AIR_INTAKE`；它不能满足能源蒸汽、蒸汽配方流体或通用流体输入仓要求。
2. 在主世界、结构已成型、正面为空气且缓存未满时，每 `80 tick` 恰好加入最多 `4,000 mB` GTCEu 标准空气；连续 `1,280 tick` 后空仓恰好达到 `64 B`（`64,000 mB`）。
3. 正面阻塞、维度不符、结构失效、缓存已满或区块卸载时不产生空气并清除未完成的周期进度；恢复条件或重新加载后必须重新等待完整的 `80 tick`，离线时间不补发。
4. 外部管道和容器既不能填充也不能抽取；所属成型控制器可以按标准流体配方规则消费实际空气存量，条件不足时不发生部分扣取。
5. Easy、Normal、Expert 下的容量、周期、单次采集量和配方产出完全一致；手工与组装机配方分别按本文材料和编程电路配置 `3` 固定产出 `1` 个。
6. 存量在保存、退出和区块重载后不丢失、不复制；拆除时存量清空且掉落物不携带空气，重复放置不能复制内部流体。
7. GUI、Jade/探针与服务端逻辑一致显示存量、容量、周期和五种状态，并在多个异常同时存在时遵循固定优先级；客户端不能单独推进计时或写入空气。
8. 进气正面拒绝安装覆盖板；其他面的覆盖板不能填充或抽取空气，也不能改变进气室的 I/O 方向。

## 当前结论

- 当前阶段有 **4 个已定案的机器部件**；其余机器与机器部件不参与统计。
- GTCEu 现有 `gtceu:steam_input_hatch` 只保留用于旧存档迁移，正常配方、物品入口和 `PartAbility.STEAM` 结构资格全部禁用；本模组新注册 `gregsteamexpansion:steam_supply_hatch` 作为唯一标准蒸汽供给仓，缓存固定为 `32,000 mB`，三档均由固定青铜配方产出 `1` 个。
- 本模组另注册一对固定 `16,000 mB` 的蒸汽流体输入/输出仓，只处理配方流体并使用专用结构能力；二者都不能提供能源蒸汽，也不改变矿石粉碎的干式配方语义。
- 蒸汽进气室作为第四个机器部件已经定案：只在主世界、所属多方块已成型且正面未阻塞时，每 `80 tick` 采集 `4,000 mB` GTCEu 标准空气，缓存固定为 `64 B`（`64,000 mB`）；它使用专用结构能力，空气只能由所属结构内部消费，不能向管道或容器输出。
