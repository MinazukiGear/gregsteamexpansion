# 全局工作强度（难度）机制设计

本文档记录 Greg Steam Expansion 的全局“工作强度”机制。该机制的英文名称与代码语义为“难度”（`Difficulty`），用于统一管理本模组的玩法设置，并允许按明确的兼容清单调整部分上游模组设置。

本文档主体只记录已经由用户确认的规则。全局档位、启动期配置与配方联动已实现，入口为 `difficulty/`；后续内容的数值设计与运行核验见文末“尚未处理的问题”，不将待核验状态视为已验收。

## 设计定位

- 工作强度是整个模组的全局玩法设置，不属于某一台机器、物品、方块或配方的私有选项。
- 工作强度影响本模组全部会改变玩法、材料成本、产量、处理速度、能耗、结构能力或兼容行为的设置。
- 工作强度还可以修改部分上游模组设置；只有在本文档明确列入兼容清单的上游设置才允许被修改，不能按名称模糊匹配或批量覆盖未知配置。
- 各内容的独立设计文档负责说明“该内容的哪些数值受工作强度影响”；本文档负责定义档位、全局生效规则、设置优先级和跨模组覆盖边界。
- 当前已有的大型蓄热蒸汽熔炉工作强度方案作为首个基准实现，后续内容在此基础上逐项纳入全局机制。

## 术语与命名

- 面向中文玩家统一使用“工作强度”。
- 英文显示名统一使用 `Difficulty`，配置键使用 `difficulty`。
- Java 枚举名使用 `Difficulty`，三档枚举常量为 `EASY`、`NORMAL`、`EXPERT`。
- 配置与同步字段使用 `difficulty`；需要记录最后应用档位的机器仍可使用 `lastAppliedDifficulty`。
- Java 代码、配置和同步字段不再使用 `WorkIntensity` 或 `workIntensity` 命名。
- 本地化键使用 `config.gregsteamexpansion.difficulty.*` 前缀。

## 档位定义

工作强度分为三个有序档位：

| 英文难度 | Java 常量 | 中文显示名 | 顺序 |
| --- | --- | --- | ---: |
| `Easy` | `EASY` | 摸鱼 | 0 |
| `Normal` | `NORMAL` | 舒适 | 1 |
| `Expert` | `EXPERT` | 压榨 | 2 |

- 难度顺序固定为 `Easy < Normal < Expert`。
- 默认档位为 `Normal`，即“舒适”。
- 现有设计文档中未特别标注工作强度的已确定数值，暂以 `Normal` 作为基准档位；Easy 与 Expert 的具体差异必须在对应内容完成平衡设计后写入本文档或对应规格。
- 档位名称、顺序和默认值属于配置兼容数据，发布后不得仅因显示文案调整而修改枚举常量或顺序语义。

## 启动期权威性

- 工作强度是进程级启动设置，同一客户端进程或专用服务端进程中的所有世界共享同一个档位；存档不再保存或决定档位。
- 唯一权威来源是 `config/gregsteamexpansion-common.toml` 中的 `difficulty`，合法值为 `EASY`、`NORMAL`、`EXPERT`，默认 `NORMAL`。旧配置中的 `ASK` 已移除，读取时按 Forge 配置校验回退到默认值。
- Forge 首次加载本模组配置时捕获档位，随即写入本模组全局状态并应用 GTCEu 启动期配方难度预设。第一次数据包与配方加载直接读取该档位，不等待世界或存档创建。
- 运行中通过 Mods 配置界面或直接编辑文件只修改磁盘配置；文件监视器触发的重载事件仅记录重启提示，不改变本次进程的档位、GTCEu 开关或已加载配方。
- 客户端在游戏内修改后必须完整退出并重启客户端。单人游戏的集成服务端随客户端一起重启；仅退出世界再进入不会生效。
- 专用服务端修改后必须停止并重新启动服务端进程。`/reload`、重进世界或在同一进程切换存档都不会改变档位。
- 重启后允许在三个档位之间任意切换；已有物品、流体和世界方块不追溯换算，各机器按自身规格处理已启动批次或持久化状态。
- 已废弃的 `gregsteamexpansion_difficulty.dat` 即使仍留在旧存档中也不再读取或写入，不影响启动配置。

### 客户端进入校验

- 客户端在完成登录、进入世界的第一时间（首个游戏阶段网络包）声明本地启动档位；服务端与自己的启动档位精确比较。
- 声明不一致时服务端立即断开客户端，并在提示中同时显示客户端与服务端档位。客户端修改本地配置并完整重启后才能重新连接。
- 连接校验只判断兼容性，不修改任一侧配置或运行状态；恶意、缺失或无效的档位值一律按不匹配处理。
- 专用服务端对每个客户端执行该校验。单人游戏的客户端与集成服务端共用同一个启动配置，仍走相同的声明与同步路径。
- 校验通过后服务端把档位同步给客户端，用于客户端机器构造、窗口标题与显示；同步不构成运行中切换。
- 该校验只比较工作强度档位，不要求客户端与服务端的其他无关配置逐项完全一致。

## 全局设置接入规则

- 每一项由本模组提供的玩法设置都必须声明其 `Easy`、`Normal`、`Expert` 三档行为；三个档位允许暂时使用相同值，但必须显式记录，而不能因为尚未平衡就绕过全局工作强度。
- 新增机器、普通物品、方块、配方、数据包规则或兼容模块时，对应设计规格必须列出受工作强度影响的字段及三档值。
- 工作强度只决定预先定义的档位参数，不允许把任意配置值直接拼接成资源 ID、注册名、类名或存档字段名。
- 同一进程内捕获的档位参数保持不变。所有需要在启动时生成、替换或选择的配方与兼容设置都使用该启动档位。
- 首版范围决定：除本文档已给出三档数值的字段外，本模组其余所有已实装内容与其余受控字段在三档全部同值，此处显式记录为“三档一致”，不因尚未平衡而绕过工作强度接入；后续新增内容设计时再逐项决定是否差异化。
- 重启并切换档位后，各子系统必须分别定义已有状态的迁移规则，明确哪些进度保留、哪些按新档位重算、哪些积累清零；不能以统一清空机器、物品或玩家进度作为默认处理方式。
- 不受难度影响的纯表现资源仍须正常提供，例如模型、纹理、语言文本和不携带玩法差异的声音；工作强度不得通过替换资源 ID 制造不兼容的三套注册对象。

## 已确定的实现机制

以下机制决定由用户确认，属于正式设计。

### 配方加载机制

- 三档配方通过携带自定义条件 `gregsteamexpansion:difficulty` 的数据包配方实现：静态配方以 `Normal` 为基线书写，`Easy` 与 `Expert` 变体分别携带仅在其档位为真的条件；同一内容的多个档位变体各自占用独立的配方资源 ID。
- 条件在每次配方数据包加载时读取已经捕获的进程启动档位。首次加载即可选择正确变体，不再执行开服后的补偿性数据包重载。
- 玩家手动 `/reload` 会重新求值条件，但档位本身保持为启动值，因此不会借此切换难度。
- 客户端的配方集合来自服务端同步，客户端不单独求值条件。
- `casingsPerCraft` 与 GTCEu 配方加难开关在首次数据包加载前已覆盖。GTCEu `7.5.3` 每次数据包加载时在运行时生成相关配方并读取这些字段，jar 内不携带对应静态配方 JSON。

### 上游启动预设生命周期

- 上游覆盖在本模组首次配置加载时应用，并保持到整个客户端或专用服务端进程退出；停止单个世界或集成服务端时不撤销。
- 同一进程中新建、退出或切换存档始终使用同一启动档位。只有完整重启进程才会重新读取配置并生成另一套上游预设。
- 覆盖范围按本文档“已确认的上游覆盖白名单”执行，其中 GTCEu `RecipeConfigs` 的 19 个配方难度布尔项按档位成组设置。

### 配置、日志与玩家说明

- 配置文件为 `config/gregsteamexpansion-common.toml` 的 `difficulty` 项，取值 `EASY`、`NORMAL`（默认）、`EXPERT`。游戏内保存后必须完整重启客户端；专用服务端编辑后必须完整重启服务端。
- 首版不提供任何查询或修改档位的命令；档位状态通过服务端日志与配置文件注释说明。
- 启动日志必须记录已捕获档位、GTCEu 预设类别与 `casingsPerCraft`；运行中重载配置时输出“本次进程忽略、重启后生效”的警告。
- 客户端与服务端档位不匹配的断开提示使用本地化键 `config.gregsteamexpansion.difficulty.mismatch`，文本包含两侧档位，并说明需要修改本地配置后重启客户端。

## 当前内容接入基线

### 普通物品、方块与配方

普通物品与非机器方块的当前清单及 `Normal` 基线见[物品与方块总体设计](items-and-blocks.md)。当前纳入后续难度展开的内容包括：

| 内容 | 当前来源 | 可能受工作强度控制的现有字段 | 当前状态 |
| --- | --- | --- | --- |
| 工业蒸汽机械方块补充配方 | GTCEu 上游方块、本模组补充配方 | 手工材料、组装机材料、产出数量、组装时间与 EU 消耗 | 仅产出数量按 `2 / 1 / 1` 变化，其他方面三档一致 |
| 青铜构件 | 本模组物品 | 手工材料与产量、组装机材料与产量、组装时间与 EU 消耗 | 仅 Expert 将青铜板替换为等数量青铜双层板，其他方面三档一致 |
| 蒸汽碾磨方块 | 本模组方块 | 手工材料与产量、组装机材料与产量、组装时间与 EU 消耗 | 产量按 `2 / 1 / 1` 变化，仅 Expert 将青铜小齿轮替换为等数量青铜齿轮，其他方面一致 |
| 蒸汽装配方块 | 本模组方块 | 手工材料与产量、组装机材料与产量、组装时间与 EU 消耗 | 产量按 `2 / 1 / 1` 变化，仅 Expert 将一半青铜板替换为青铜双层板，其他方面一致 |
| 蒸汽电路装配方块 | 本模组方块 | 手工材料与产量、组装机材料与产量、组装时间与 EU 消耗 | 下方板材改为橡胶，Expert 升级剩余青铜板；组装机使用等量液态橡胶，产量按 `2 / 1 / 1` |
| 所有本模组新增仓室 | 本模组机器部件 | 手工材料与产量、组装机材料与产量、容量、组装时间与 EU 消耗 | 所有获取路线在三档均固定产出 `1` 个；各仓室的材料、容量和其他数值由自身规格定义 |
| 矿石粉碎配方类型 | 本模组配方类型、迁移 GTCEu 上游配方 | 主产物、概率副产物、功率与持续时间 | 基础产量为矿石方块主产物 `4×`、粗矿主产物 `1×`，再按三档对所有主产物乘 `2× / 1.5× / 1×`；概率副产物和功率保持上游原值，蒸汽机器（粉碎机双机）三档均执行 `600 tick` 且只接受 ≤LV 配方；电力粉碎机（LV–UV 单方块）按配方基准功率付费并标准超频，产量随同一配方池 |
| 合成站与合成站竖半砖 | 本模组方块 | 手工材料与产量 | 产量三档固定 `1` 个，材料与图案三档一致（通用方块产量显式例外） |

- `items-and-blocks.md` 继续负责记录物品和方块本身的名称、资源 ID、行为、材料语义及 `Normal` 基线配方。
- 本文档不把同一内容注册成三套物品或方块。难度差异应作用于配方选择、材料、产量、时间、能耗或其他设置值，而不是改变物品与方块身份。
- 工作强度不得破坏已经确定的科技阶段边界。蒸汽阶段的基础制作路线在任何档位下都不能被电路、马达、EU 机器或其他电力时代产物完全取代。
- 上游方块 `gtceu:industrial_steam_casing` 的所有权始终属于 GTCEu；即使工作强度改变本模组补充的获取方式，也不得重复注册该方块。
- 工业蒸汽机械方块的手工与组装机补充配方继续读取 GTCEu 的机械方块产量参数，因此其产量随全局工作强度分别变为 Easy `2` 个、Normal `1` 个、Expert `1` 个。
- 除产出数量外，工业蒸汽机械方块的三档配方完全一致。手工配方的黄铜板、青铜框架和工具需求不变；组装机配方的黄铜板、青铜框架、编程电路配置、`16 EU/t`、`50 tick` 与 `800 EU` 总耗能均不随工作强度改变。
- 三档均保留蒸汽阶段手工路线和低电压组装机路线，配方资源 ID、科技阶段、注册所有权、材料语义及上游兼容边界也保持一致。

### 青铜构件

青铜构件不读取通用方块产量，三档均固定产出 `1` 个。只有 Expert 的青铜板种类发生变化：

| 配方路线 | Easy | Normal | Expert |
| --- | --- | --- | --- |
| 手工配方板材 | `4` 个青铜板（`plate / Bronze`） | `4` 个青铜板（`plate / Bronze`） | `4` 个青铜双层板（`plateDouble / Bronze`） |
| 组装机配方板材 | `3` 个青铜板（`plate / Bronze`） | `3` 个青铜板（`plate / Bronze`） | `3` 个青铜双层板（`plateDouble / Bronze`） |
| 产出 | `1` 个青铜构件 | `1` 个青铜构件 | `1` 个青铜构件 |

- Expert 只以等数量青铜双层板替换两条配方中的普通青铜板，不改变配方槽位、图案或其他输入数量。
- 手工配方中的 `2` 个铜弹簧、`1` 个青铜框架、锻造锤和扳手在三档保持一致。
- 组装机配方中的 `1` 个铜弹簧、`1` 个青铜框架、编程电路配置 `6`、`16 EU/t`、`50 tick` 与 `800 EU` 总耗能在三档保持一致。
- 物品行为、堆叠上限、科技阶段、配方资源 ID、手工与组装机路线是否存在以及组装机相对手工路线节省的弹簧数量均不随工作强度改变。

### 本模组新增非控制器方块的通用产量

除多方块控制器和各自规格显式排除的机器部件外，本模组注册的方块接入与 GTCEu `recipes.casingsPerCraft` 相同的有效产量值：

| 英文难度 | 中文显示名 | 每份非控制器方块配方产量 |
| --- | --- | ---: |
| `Easy` | 摸鱼 | `2` 个 |
| `Normal` | 舒适 | `1` 个 |
| `Expert` | 压榨 | `1` 个 |

- 凡配方的主产物是由 `gregsteamexpansion` 注册的非控制器方块，其输出堆叠数量原则上读取该通用产量，包括普通结构方块、未另设规则且不属于仓室的机器部件，以及以后新增的同类方块。
- 同一方块存在手工、组装机或其他多条获取配方时，所有直接产出该方块的配方均使用同一档位产量；不能只提高 Easy 的手工产量而让自动化路线保持 `1` 个。
- 当前的蒸汽碾磨方块、蒸汽装配方块、蒸汽电路装配方块和蒸汽搅拌方块因此均在 Easy 下每份配方产出 `2` 个，在 Normal 与 Expert 下产出 `1` 个。
- 所有由本模组新增的仓室均由下述仓室通则排除在本规则之外；它们在三档下固定产出 `1` 个，不读取通用方块产量。
- 该参数只控制获得方块的配方主产物数量，不改变方块被挖掘、拆除、爆炸或战利品表处理时的掉落数量，也不复制配方副产物。
- 不可放置的独立物品不因本规则改变产量。青铜构件仍按其独立难度设计处理，不能因为参与方块配方而读取通用方块产量。
- 修改档位并完整重启后，重新加载的方块配方使用新产量；已经合成并存在于物品栏、容器或世界中的方块不追溯增减。

### 所有多方块控制器固定产量

- 本模组所有当前与未来的多方块控制器配方在 Easy、Normal、Expert 下都固定产出 `1` 个控制器，不读取非控制器方块的 `2 / 1 / 1` 通用产量，也不读取 GTCEu `recipes.casingsPerCraft`。
- 该规则适用于蒸汽粉碎机、大型蒸汽粉碎机、大型蓄热蒸汽熔炉以及以后新增的全部多方块控制器；机器规格不能仅以 Easy 奖励为理由把控制器产量提高到多个。
- 同一控制器存在工作台、组装机或其他获取路线时，每条路线都必须固定产出 `1` 个。工作强度仍可在对应规格明确改变材料、时间或能耗，但不能改变控制器产量。
- 该规则不影响普通结构方块和其他非控制器机器部件的通用产量，也不取代下述仓室固定产量通则；控制器被挖掘、拆除或破坏时的正常单方块掉落语义同样不变。

### 所有本模组新增仓室固定产量

- 所有由 `gregsteamexpansion` 新增并注册的当前及未来仓室，在 Easy、Normal、Expert 下每份配方都固定产出 `1` 个，不读取非控制器方块的 `2 / 1 / 1` 通用产量，也不读取 GTCEu `recipes.casingsPerCraft`。
- 本规则包括蒸汽供给仓、蒸汽流体输入仓、蒸汽流体输出仓、蒸汽进气室、蒸汽排气仓，以及以后新增的物品仓、流体仓、能源仓、维护仓、消声仓或其他以多方块接口仓室身份注册的部件。
- 同一仓室存在工作台、组装机或其他多条获取路线时，每条路线都必须固定产出 `1` 个；不能用 Easy 奖励、自动化路线或批量制造为理由提高单份配方产量。

### 专用蒸汽锅炉的全局产量与单方块缓存

所有主要功能为生产蒸汽的锅炉，其实际蒸汽产量统一乘以下列工作强度倍率：

| 英文难度 | 中文显示名 | 蒸汽产量倍率 | 单方块锅炉蒸汽缓存倍率 |
| --- | --- | ---: | ---: |
| `Easy` | 摸鱼 | `5×` | `2×` |
| `Normal` | 舒适 | `5×` | `1×` |
| `Expert` | 压榨 | `2×` | `1×` |

```text
实际蒸汽产量 = 锅炉默认蒸汽产量 × 当前工作强度倍率
单方块锅炉实际蒸汽缓存容量 = 默认蒸汽缓存容量 × 当前工作强度缓存倍率
```

- “默认蒸汽产量”指同一锅炉在不应用本模组工作强度倍率时，按照自身类型、压力等级、燃料模式、温度、效率和其他既有状态计算出的本 tick 基础产量；倍率在该基础计算完成后统一应用。
- 规则覆盖本模组锅炉、GTCEu 锅炉以及以后通过明确兼容适配登记的其他上游专用蒸汽锅炉，包括单方块和多方块锅炉。
- 规则只覆盖以生产蒸汽为主要职责的锅炉。配方副产少量蒸汽的机器、消耗蒸汽的机器、蒸汽涡轮、热交换器以及仅在名称或说明中出现“锅炉”的非产汽方块不自动套用。
- 不允许仅按注册名包含 `boiler` 或输出流体恰好为蒸汽进行模糊识别；上游锅炉必须由精确注册白名单、类型适配器或兼容模块显式接入。
- 温度比例、模式加成和上游自身效率先参与默认产量计算，因此这些锅炉原有的相对产量关系保持不变；Easy 与 Normal 具有相同的 `5×` 产汽倍率，Expert 使用 `2×`。
- 只有单方块专用蒸汽锅炉的内部蒸汽缓存容量受缓存倍率影响：Easy 为默认容量的 `2×`，Normal 与 Expert 保持默认容量。多方块锅炉的内部缓存、大型蓄热蒸汽熔炉供汽仓、蒸汽管道、外部储罐和网络存储均不读取该倍率。
- “默认蒸汽缓存容量”指同一单方块锅炉在不应用本模组工作强度时提供的内部蒸汽输出槽容量。倍率只扩大可用容量，不复制、补满或按比例增加其中已有蒸汽。
- 实际耗水量继续按照锅炉原有的水与蒸汽换算关系由放大后的实际蒸汽量计算。燃料消耗、燃烧时间、升温、冷却、最高温度、启动温度、主动输出频率、堵塞和泄压规则不因产量或缓存倍率自动改变。
- GUI、Jade、悬浮提示和诊断信息中的当前蒸汽产量与缓存容量必须显示应用倍率后的实际值；设计文档可以保留倍率前默认值，但必须明确标为“默认”或“倍率前”。
- 修改档位并完整重启后，锅炉从首次继续产汽时使用新倍率；已经储存在锅炉、管道、容器或网络中的蒸汽不追溯增减。

### 大型蓄热蒸汽熔炉

大型蓄热蒸汽熔炉的完整机器规则见[大型蓄热蒸汽熔炉开发指导](large-heat-storage-steam-furnace.md)。当前已经确认的首个三档数值如下：

| 英文难度 | 中文显示名 | 预热总消耗倍率 | 最大升温速率 | 加工蒸汽消耗倍率 |
| --- | --- | ---: | ---: | ---: |
| `Easy` | 摸鱼 | `0.4×` | 每 2 tick 升高 `1°C` | `0.5×` |
| `Normal` | 舒适 | `1.0×` | 每 5 tick 升高 `1°C` | `1.0×` |
| `Expert` | 压榨 | `2.2×` | 每 10 tick 升高 `1°C` | `1.0×` |

最终预热蒸汽总消耗为：

```text
预热蒸汽总消耗 = (宽² − 4) × 高 × 2 × 温度增量 × 工作强度倍率 mB
```

- 该机器把预热蒸汽成本、最大升温速率和加工蒸汽消耗接入工作强度。加工蒸汽先按机器自身的能量、并行和体积减免公式计算，再由 Easy 乘 `0.5×`；Normal 与 Expert 不追加加工减免。
- 配方启动时锁定加工蒸汽倍率、加工蒸汽总量和每刻需求。重启并改变档位不改写已启动批次的锁定消耗，下一批才读取新的启动档位。
- 重启后机器保留当前温度、冷却计时、当前批次、待输出产物和批次锁定参数；当新档位低于机器记录档位时，未满 `1°C` 的预热蒸汽积累与升温计时清零。
- 每台机器持久化 `lastAppliedDifficulty`。未加载区块以后加载时按启动档位执行一次必要迁移并更新记录；同一档位不得重复迁移。
- 控制器界面和 Jade 不显示或修改全局工作强度。

## 上游模组设置覆盖

- 工作强度可以覆盖部分上游模组设置，但每一项覆盖都必须记录上游模组 ID、适用版本、配置键或注册对象、三档目标值、生效阶段、冲突处理和取消覆盖后的兼容策略。
- 上游覆盖必须使用精确白名单。未列入白名单的上游配置保持上游或整合包设定，不得因为属于相同配置分类而被一并修改。
- 对上游设置的覆盖不能改变上游对象的资源 ID、注册所有权或存档身份。
- 当上游版本移除、改名或改变目标设置语义时，兼容层必须安全跳过并给出诊断信息，不能因工作强度覆盖失败而阻止世界加载。

### 已确认的上游覆盖白名单

| 上游模组 | 适用版本 | 配置键或覆盖对象 | Easy | Normal | Expert | 覆盖方式 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| GTCEu | `7.5.3` | `recipes.casingsPerCraft` | `2` | `1` | `1` | 启动期强制使用对应整数值 |
| GTCEu | `7.5.3` | 19 个 `RecipeConfigs` 配方难度布尔项 | 全部关闭 | 上游默认组合 | 全部开启 | 启动期成组写入，详见下表 |
| GTCEu | `7.5.3` | 专用蒸汽锅炉的实际蒸汽产出 | `5×` | `5×` | `2×` | 在锅炉默认产量计算完成后乘以对应倍率 |
| GTCEu | `7.5.3` | 单方块专用蒸汽锅炉的内部蒸汽缓存容量 | `2×` | `1×` | `1×` | 在锅炉默认蒸汽缓存容量上乘以对应倍率 |
| GTCEu | `7.5.3` | `primitive_blast_furnace` 配方类型（新增 `3` 条纯粉锻铁配方） | 一致 | 一致 | 一致 | 数据生成向该类型追加 add-only 配方 JSON（`data/gregsteamexpansion/recipes/primitive_blast_furnace/`），不删除、不修改任何上游配方 |

- `recipes.casingsPerCraft` 是 GTCEu 的机械方块配方产量参数，合法范围为 `1–3`，GTCEu 默认值为 `2`。Easy 使用上游默认值 `2`，Normal 与 Expert 均使用 `1`；工作强度机制不使用允许范围内的 `3`。
- 该覆盖作用于 GTCEu 读取此参数的全部机械方块配方，也作用于本模组所有明确复用此参数的补充配方，不能只为工业蒸汽机械方块建立一份例外产量。
- 本模组启动配置是该参数的最终权威来源。GTCEu 配置中单独填写的 `recipes.casingsPerCraft` 值会在本模组配置首次加载时被当前档位的 `2` 或 `1` 覆盖。
- 参数在本次进程第一次配方集合确定前完成覆盖；客户端接收的配方产量与服务端最终值一致，不依赖开服后数据包重载。
- 修改档位只在完整重启后生效。重启后新加载的配方使用新产量，已经存在于物品栏、容器或世界中的机械方块不追溯增减。
- 如果目标 GTCEu 版本不存在该配置、合法范围不再包含 `1–3` 或配置语义不再表示机械方块配方产量，则跳过覆盖并记录明确的兼容警告，不得猜测替代键。

GTCEu 配方难度布尔项按两组映射。Easy 将两组全部设为 `false`；Normal 保持 GTCEu 7.5.3 的默认组合；Expert 将两组全部设为 `true`。这些字段在 `config/gtceu.yaml` 中的单独取值会被启动档位覆盖。

| Normal 值 | GTCEu `recipes` 字段 |
| --- | --- |
| `true` | `disableManualCompression`、`harderRods`、`hardIronRecipes`、`hardGlassRecipes`、`nerfPaperCrafting`、`hardAdvancedIronRecipes`、`harderCharcoalRecipe`、`flintAndSteelRequireSteel`、`removeVanillaTNTRecipe` |
| `false` | `harderBrickRecipes`、`nerfWoodCrafting`、`hardWoodRecipes`、`hardRedstoneRecipes`、`hardToolArmorRecipes`、`hardMiscRecipes`、`hardDyeRecipes`、`removeVanillaBlockRecipes`、`harderCircuitRecipes`、`hardMultiRecipes` |

- 该预设只覆盖表中 19 个配方难度项；`generateLowQualityGems`、`enchantedTools`、回收开关与回收产率等其他 GTCEu 配置保持原配置值。
- 这些字段与 `casingsPerCraft` 同时在本模组配置首次加载时写入，确保 GTCEu 的运行时配方生成器读取一致档位。
- GTCEu 锅炉覆盖必须逐项核验 7.5.3 中所有专用产汽锅炉的注册对象或共用产汽逻辑；若某个锅炉绕过共用逻辑，兼容层仍须显式接入，不能因其实现不同而静默保留 `1×`。
- 单方块缓存覆盖还必须逐项确认目标确实是锅炉自身的蒸汽输出缓存，不能扩大水槽、燃料槽、其他流体槽或多方块结构中的仓容量。
- `primitive_blast_furnace` 配方注入的覆盖理由：上游 7.5.3 蒸汽时代没有任何锻铁产出配方（熔炉铁粉出铁锭，锻铁仅电弧炉 LV+/HV EBF），而锻铁板是钢级蒸汽单方块机器、砖砌锻铁外壳（大型蓄热蒸汽熔炉结构方块）与 ULV 机械外壳的必需材料，纯蒸汽存档进度断链；注入为 add-only，不改变上游对象的资源 ID、注册所有权或既有配方语义（large-steam-blast-furnace.md《锻铁获取注入》）。若上游版本在蒸汽时代补入锻铁获取途径，应评估移除本组配方并恢复上游原状。
- 铁粒 → 锻铁粒为上游既有配方（`gtceu:wrought_iron_nugget`，`CraftingRecipeLoader` 注册），2026-09-09 用户裁定本模组不重复添加；初版曾注入的同名配方已移除。
