# 终极终端

> 状态：2026-09-18 已实现首版；依赖 AE2 与 GTM Things 同时存在。本文记录本轮已定案并落地的行为，客户端实际观感与大型整合环境仍待游戏内验收。

## 定位与启用条件

终极终端是 GTM Things 高级终端的结构工程上位物，不替代后者。模组本体不把 AE2 或 GTM Things 设为硬前置：缺少任意一个依赖时 GSE 继续加载，物品不加入创造标签，条件配方不加载，已有物品只显示依赖缺失并拒绝使用。

终端直接按运行时类型支持 GTCEu 的 `IMultiController`，不检查控制器注册名的命名空间，也不维护机器白名单。因此 GTCEu 原生、GSE 以及第三方附属模组注册的控制器使用同一条目标选择、实时 `BlockPattern` 解析、队列和拆除路径；附属模组无需向 GSE 额外登记。玩家手持终端右击已放置且定向完成的控制器加入工程，Shift 右击移除；同一玩家最多保存 `16` 个同维度目标。对空气使用终端打开工程界面。

## 工程参数与模式

- `构建`与`修复`从控制器的实时 `BlockPattern` 解析缺失位置，并保留已经满足候选的现有方块；若目标格被不兼容且不可替换的方块占用，预检失败而不扣材料。
- `升级`除补齐缺失位置外，还会把图案内已有线圈或配置选材信道方块换成下拉栏所选方块。被换下的方块进入返还事务；未知占位方块、控制器、仓室和其他含方块实体的部件绝不自动替换。
- `拆除`优先从控制器当前已成型的真实图案与实际重复层数生成清单；结构尚未成型或已经损坏时，改用终端所选结构尺寸与重复层作为蓝图，只拆其中仍匹配合法候选的普通方块。冲突方块、控制器及含方块实体的仓室或机器始终保留。
- 可变结构允许选择重复层数 `0–64`；`0` 表示使用图案最小值，实际值始终夹在图案声明的最小值与最大值之间。
- 内置“结构尺寸”信道直接选择控制器公开的几何图案：大型蓄热蒸汽熔炉提供 `7×7 / 11×11 / 15×15`，大型蒸汽罐提供 `3×3 / 5×5 / 7×7 / 9×9`。重复层仍独立控制所选宽度图案的高度。
- 内置“外挂模块”信道显示当前控制器已经实装并向终端公开的模块；`-1` 表示不安装，模块按机器实现返回的稳定顺序占用 `0–63`，后续只能在尾部追加，避免已有存档中的信道值改变含义。选择模块后，普通方块合并进材料统计、全息与施工队列，严格空气位参与蓝图冲突预检与全息标记。当前值 `0` 分别对应大型蒸汽高炉的双塔热风炉组和锅炉房的给水软化塔。
- 全局 `externalModulesEnabled=false` 时，规划器对所有控制器统一返回空模块选项，不显示“外挂模块”信道，也不把任何模块方块或严格空气位加入计划；已有终端配置中的模块选择值保留，重新开启后按原稳定顺序重新解释。
- 线圈和通用选材信道均使用下拉栏显示实际方块名称与物品图标；可直接选择“自动”或对应方块，不显示数字档位。下拉栏展开时使用独占选择面板，隐藏其余信道行并提供关闭与选项翻页，避免控件和点击区域重叠。升级模式可把同信道已有方块替换为所选方块。内部以 `-1` 表示自动，实际条目统一使用零基索引。
- 通用选材信道由 `gregsteamexpansion-terminal.toml` 的 `ultimateTerminalSelectionChannels` 声明，格式为 `信道ID=方块ID,方块ID,...`。终端只显示当前结构至少包含两个合法候选的信道。默认提供玻璃信道，服主最多可定义 32 个信道、每个信道最多 64 个方块，对应信道值严格为 `0–63`；`coil`、`module` 与 `structure_size` 名称由内置信道保留。旧存档中的 `1–64` 选择值读取时自动迁移为 `0–63`。
- 客户端模组列表的 GSE“配置”页面提供“终极终端”子页面；每刻操作数在基础页编辑，结构选材信道进入独立页面。信道列表逐个折叠，展开后每个条目独占一行并明确显示 `0–63 → 方块 ID` 映射，可分别新增、删除和修改信道及条目；非法格式、重复 ID、少于 2 项、超过 64 项或超过 32 个信道时禁止保存。该页面编辑的是本机服务端配置，专用服务器仍须修改服务器侧 `gregsteamexpansion-terminal.toml`。
- 终极终端固定为无仓室模式：机器方块候选不会进入计划、材料统计、候选计数或选材信道。终端完成普通结构方块后即结束任务，玩家再手动安装结构要求的输入、输出、供能、排气等仓室并使机器成型。

## 材料、事务与队列

启动任务前先对全部目标生成确定性方案并汇总材料。生存模式下，系统完整模拟可用数量，确认足够后才从玩家物品栏提取；AE 开关开启时，余量从玩家物品栏内已绑定且可访问的 AE2 无线终端所连接网络提取。所有材料进入随世界保存的托管清单，避免进行中退出或服务器重启造成丢失或重复。创造模式玩家启动的构建、修复和升级任务固定使用无限材料，不检查或扣取背包与 AE 网络中的方块；该属性随任务保存，材料页明确显示创造模式无限材料，且失败回滚或完成时不会生成虚构的托管余料。

任务默认使用全服 `32` 方块/刻预算，可在 `gregsteamexpansion-terminal.toml` 的 `ultimateTerminalBlocksPerTick` 调整为 `1–256`；同一文件还可修改通用选材信道。玩家离线、离开目标维度或目标区块没有自然加载时任务进入暂停，不强加载区块；条件恢复后继续。进行中与暂停中的任务都锁定目标清单，不能由新任务覆盖。

每个目标完成后逐项核对本任务计划的普通方块。放置失败或计划方块被外部改动时，只回滚本次为该目标新放置且不含方块实体的方块，并退还托管余料；由于固定无仓室模式，任务完成不要求控制器立即成型。退还和拆除所得优先进入玩家物品栏，其次写回 AE 网络；仍无法容纳的物品进入持久待领取清单，可在界面再次领取。

## 全息规划与方块配额

终端界面分为目标、预览、材料、信道和方块配额五页。目标页选择当前控制器；预览页控制建造模式、重复层、机器类型模板或当前目标覆盖，以及全息显示方式；材料页可在当前目标与整个批次之间切换，分别显示需求、玩家背包、AE 网络和缺口；信道页集中显示结构尺寸、外挂模块、线圈与配置选材下拉栏；方块配额页从所选 `BlockPattern` 动态列出可互换位置的普通方块候选并为每种候选设置结构内目标总数，已存在的同类方块计入配额。线圈、洁净室过滤器、变电站电池等要求同一结构内统一选材的候选由对应信道或 GTCEu 图案约束管理，不进入方块配额；仓室等机器方块同样不在此列。

关闭界面后，只要玩家任一只手继续持有终端，当前目标的世界内全息仍会显示。默认“仅差异”模式隐藏已满足方块；也可以切换完整结构或单层模式。预期方块使用半透明真实方块模型，状态轮廓为：缺失白色、冲突红色、升级黄色、拆除蓝色、区块未加载灰色。终端不强加载区块，未加载位置只作状态提示且禁止启动任务。

规划完全由服务端生成并校验。全量快照最多包含 `8,192` 个结构格、`256` 种候选和 `256` 种材料，超过部分被截断；客户端的配额加减请求只携带注册名和增减方向，服务端按实时图案重新计算候选位置上限。持有终端时每 `10 tick` 检查一次：目标、坐标或预期方块变化时发送新全量快照，仅状态与材料数量变化时发送增量更新。配置按控制器方块注册名保存为机器类型模板，也可为单个目标建立独立覆盖；旧版工程参数在读取时迁移到默认配置。

## 配方与美术

配方严格沿用 GTM Things 高级终端的 `SGS / PBP / PWP` 布局，只做用户指定的两项替换：中心书本 `B` 改为 `gtmthings:advanced_terminal`，所有钢零件改为 GTCEu 琥珀金零件。最终布局为：

```text
琥珀金螺丝 / 玻璃板 / 琥珀金螺丝
琥珀金板   / 高级终端 / 琥珀金板
琥珀金板   / 锡单导线 / 琥珀金板
```

贴图逐像素派生自 GTM Things 1.6.0 的高级终端：尺寸、轮廓、透明度、明暗、动画帧数和 `6 tick` 帧时完全保留，仅把有色像素的色相换为琥珀金金色。来源与 LGPL-3.0 例外记录在 `CREDITS.txt` 和 `LICENSE-ASSETS.txt`，生成过程由 `tools/gen_ultimate_terminal_texture.py` 固定。

## 验收边界

- 自动门禁：Java 编译、条件配方数据生成、程序化贴图逐像素新鲜度、双语键集合、精确九宫格配方，以及配置 NBT 往返、蓝图状态、已成型/未成型结构拆除、结构尺寸与外挂模块选择、无仓室计划、创造模式无限材料和非 GSE 注册控制器通用路径 GameTest。
- 待游戏内核对：五页界面、信道页的结构尺寸与选材下拉栏、三种全息显示、模板/目标覆盖、候选计数、四种任务模式、AE 网络提取/退还、离线与跨重启续作、碰撞回滚、待领取物，以及大型结构的默认 `32` 方块/刻节流表现。
- 本轮不提供跨维度工程、AE 自动合成、团队共享、强加载区块、配置导入导出或未知占位方块替换；未成型拆除以当前选定的尺寸与重复层蓝图为边界，并保留控制器、冲突方块与全部含方块实体的部件。
