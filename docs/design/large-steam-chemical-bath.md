### 分工边界（议题 2）

（用户 2026-09-07 确认）

- 与 GCYM 大型化学浸洗机（`large_chemical_bath`，电力多方块，同时执行 `chemical_bath` 与 `ore_washer` 两类型）：按能源形态分层共存，保持上游原样、互不修改；本机是浸洗能力在蒸汽阶段的唯一入口。
- 与电力单方块浸洗机（LV–UV）：沿用 S1 确立的“越级使用、以蒸汽消耗为平衡代价、不限配方”结论。
- 与 S1 洗矿厂：洗矿 → 浸洗推进链顺序不变，两者配方类型互不越界（已预先裁定）。
- 与 A4 研磨厂：浸洗（粉碎矿 → 纯净粉碎矿）与研磨（粉碎矿 → 粉尘）是粉碎矿的两条互斥去向，本机不接管研磨。

### 配方执行细节（议题 3）

（用户 2026-09-07 确认）

- 全配方开放：矿石浸洗（粉碎矿 + 浸洗液 → 纯净粉碎矿 + `70%` 概率副产粉尘 + `40%` 石粉）、造纸、处理木板、装饰/杂项配方及外部模组加入 `gtceu:chemical_bath` 的配方自动可用。
- 流体按配方声明原样兼容（浸洗液由各材料 `OreProperty` 决定，不限于水），不设白名单或过滤。
- 类型无默认耗时、默认 `EU/t = 32`：本机不修改配方基准数值，越级平衡只通过机器侧蒸汽消耗实现。
- **无流体输出仓的连带后果**：本机不安装蒸汽流体输出仓，凡产生流体输出的配方（上游原版暂无，外部模组配方可能存在）因流体产物无出口而在开工预检中失败，不能在本机执行；物品输出不受影响。

### 结构与外观（议题 4）

（用户 2026-09-07 确认；方块数量为推导核算）

#### 固定结构

- 固定单套结构，包围盒为“宽 `3`（左右）× 深 `4`（前后）× 高 `3`”，正面为 `3×3` 的面（用户 2026-09-07 确认正面朝向口径）；只允许四个水平朝向，不保留其他尺寸变体。
- 外壳全部使用工业蒸汽机械方块（`gtceu:industrial_steam_casing`）；内部 `2` 格（中列 × 中两排 × 中层）固定空气。
- 结构无专用内部结构方块。

- 仓室合计（含排气仓）最多 `8` 个（用户 2026-09-07 确认），即外壳至少保留 `26` 个工业蒸汽机械方块；多仓室不提供任何性能加成。
- 结构共用：沿用 S1/A4 口径——不设结构独占与间距排斥，同一方块可被多座结构计数，可贴靠共用墙体，失效互不影响。

### 动力与蒸汽消耗（议题 5）

（用户 2026-09-07 确认）

- 仅接受 GTCEu 标准蒸汽，不消耗 EU；蒸汽换算率 `2 mB = 1 EU`。
- 执行时长为配方基准耗时乘固定倍率 `1.5×`：`max(1, ceil(基准耗时 × 1.5))` tick；单份总耗汽 = `配方 EU/t × 执行时长 × 2` mB（配方未声明 `EU/t` 时取类型默认 `32`）。

| 配方族 | 基准 | 执行时长 | 单份总耗汽 | 并行 `P` 时每刻需求 |
| --- | ---: | ---: | ---: | ---: |
| 矿石浸洗（`200 tick`、`32 EU/t`） | `6,400 EU` | `300 tick` | `19,200 mB` | `64 × P mB/t` |
| 其他自带耗时的配方（造纸、处理木板等） | 按配方 | `ceil(基准 × 1.5)` | `EU/t × 执行时长 × 2` | 总耗汽 ÷ 执行时长 |

- 断供蒸汽：进度回退至 `1 tick`（S1 口径），恢复后续跑原批次；排气受阻按通用排气仓规则冻结进度，与缺气回退明确区分。
- 多供给仓不提高并行或效率；满并行 `8` 矿石浸洗每刻需求 `512 mB/t`，单供给仓即可满足。

### 并行与吞吐（议题 6）

（用户 2026-09-07 确认）

- 最大并行固定 `8`，与蒸汽粉碎机同级；不由接口数量或环境动态计算。
- 实际并行 = `min(8, 可用输入份数, 最坏情况输出可容纳份数)`；公式小于 `1` 不开工、不扣取；批次开始后锁定。
- 耗时不随并行倍增；批次总耗汽与每刻需求按 `P` 线性放大。
- 配方选择沿用“最近成功配方优先”（首扫按输入槽编号，多匹配按资源 ID 字典序；偏好配方持久化，缺输入重扫、输出不足等待不改选）。

### 内部库存与批处理原子性（议题 7）

（用户 2026-09-07 确认）

- 沿用 S1 口径：控制器缓存仅待输出结果，无内部物品槽与内部流体罐；全部库存由仓室直接承载。
- 开工预检跨全部总线与流体输入仓聚合执行：物品输入、浸洗液份数与最坏情况输出（最多 `6` 个物品输出位，概率副产按全命中预留）一次预检；通过后原子扣取全部输入（含浸洗液）。
- 产物提交：批次完成时物品写入物品输出总线；因不安装流体输出仓，带流体输出的配方在预检阶段即被排除（议题 3 连带后果），不存在运行中流体无处提交的路径。
- 待输出保险沿用（异常时完整物品结果持久化于控制器，空间恢复后整体重试）。

### 运行控制与失效（议题 8）

（用户 2026-09-07 确认）

- 标准 GTCEu 启停控制：软锤 + GUI 电源按钮；暂停期间不取汽、不推进，批次参数保留。
- 一般结构失效：进度回退 `1 tick`，修复后续跑原批次。
- 无特殊清空关键部位；控制器被拆除仅损失偏好配方 ID 与待输出结果（物品掉落）。
- 区块卸载持久化续跑，不补算离线进度；新注册机器无旧存档迁移问题。

### 表现与信息（议题 9）

（用户 2026-09-07 确认）

- GUI/Jade 整体沿用粉碎机已实现骨架：主状态、配方与进度、实际并行 / `8`、蒸汽合计存量与容量、每刻需求、待输出摘要；服务端权威同步。
- 进度条与声效沿用类型自带的浸洗样式（`BATH` 声，与 S1 同源）；配方实际推进时在浸洗腔位置叠加气泡/泡沫粒子。
- 控制器正面空闲/工作两态纹理走 `steamMultiblockModel` 的 `addTextureOverride` 模式。
- 两级物品提示（默认摘要 + Shift 完整说明）；文本优先复用既有资源，中英双语。

### 上游浸洗配方族（已核对源码）

| 配方族 | 输入 → 输出 | 基准 |
| --- | --- | --- |
| `bathe_<材料>_crushed_ore_to_purified_ore` | `1` 粉碎矿 + 浸洗液（`OreProperty.getWashedIn()` 决定流体与用量） → 纯净粉碎矿 + `70%` 概率副产粉尘 + `40%` 石粉 | `200 tick` / `32 EU/t`，挂 `ORE_BATHING` 分类 |

| 处理木板（`ChemicalBathRecipes`） | 木板 + 杂酚油 `100 mB` → 处理木板 | 配方自带耗时 |
| 装饰、电路、杂项等散布配方 | 各类浸洗处理（`DecorationRecipes`、`CircuitRecipes`、`MiscRecipeLoader`、`VanillaStandardRecipes` 等） | 配方自带 |

- 矿石浸洗的副产概率（`70%` / `40%`）高于洗矿（`1/3` + 石粉）与研磨（`14%`），是浸洗路线的核心收益。
- 上游原版配方当前**不产生流体输出**（类型声明 `1` 个流体输出槽，供外部模组配方使用）。

### 上游执行该类型的机器

| 机器 | 形态 | 说明 |
| --- | --- | --- |
| 化学浸洗机（`CHEMICAL_BATH`） | LV–UV 单方块电力机器 | 全配方 |
| 大型化学浸洗机（GCYM `LARGE_CHEMICAL_BATH`，ID `large_chemical_bath`） | **电力多方块**（水密外壳），可并行 | 同时执行 `chemical_bath` **与 `ore_washer`** 两种配方类型 |
| 蒸汽浸洗机器 | **不存在** | 上游蒸汽机器仅有锅炉 ×3、提取机、研磨机、压缩机等，无浸洗 |

## 立项前提

1. **定位：补空白（同 S1 模式）**。上游没有蒸汽浸洗机器，本机是蒸汽阶段首次获得化学浸洗能力的入口；与 A4（上游已有蒸汽研磨机，定位为规模化上位）不同。
2. **与 GCYM 大型化学浸洗机按能源形态分层**：该机为电力多方块、保持上游原样；其同时执行 `ore_washer` 类型的事实说明上游把“洗矿 + 浸洗”视为推进链，S1 → 本机的模组内顺序与之呼应。
3. **孤儿消化（按用户裁定收窄）**：蒸汽流体输入仓为本机流体输入的合法选项（非强制——GTCEu 标准流体输入仓亦可，二者可选或混用）；**蒸汽流体输出仓不被本机消化**（用户裁定不安装），该孤儿继续保留在候选清单待后续机器认领。
4. **越级模式**：化学浸洗机在上游属 LV 电力机器；本机沿用 S1 议题 2 确立的“越级使用、以蒸汽消耗为平衡代价”模式。

## 验收清单（由用户执行）

**结构与成型**

- [ ] 宽 `3` × 深 `4` × 高 `3` 结构按逐层图成型（正面 `3×3`，控制器居正面底层正中）：外壳 34 工业蒸汽机械方块、内部 2 格空气。
- [ ] 蒸汽流体输出仓不可参与结构；流体输入仓可为蒸汽流体输入仓或 GTCEu 标准流体输入仓（可选或混用）；仓室合计 ≤ `8`；排气仓缺省、多余或正面 `3` 格空气受阻时按既定规则处理。
