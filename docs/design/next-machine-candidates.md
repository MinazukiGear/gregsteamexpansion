# 后续机器候选建议清单

本文档是**建议清单**，不是已定案设计。文中所有机器名、数值与边界都处于"构想 / 讨论中"状态，只有经用户逐项确认、并另立独立规格后，才能进入 `machines-and-hatches.md` 或各机器规格的已确认正文。

本清单的目标：为"下一步设计什么机器"提供尽量完整的候选面与优先级依据，而不是替代任何一台机器的独立规格设计。

## 一、判断依据

### 1.1 孤儿资产（已定案或已注册，但没有任何机器消费）

| 资产 | 类型 | 现状 | 文档约束 |
| --- | --- | --- | --- |
| 蒸汽流体输入/输出仓 | 机器部件 | 已实现 | 被蒸汽粉碎机、大型蒸汽粉碎机、大型焦炉、大型蓄热蒸汽熔炉明确排除；`ore-crushing.md` 要求"以后若设计湿式矿物处理，应使用洗矿、化学浸洗或独立的新配方类型" |
| 蒸汽进气室 | 机器部件 | 已实现 | 同上四台机器全部排除；规格要求"供所属结构内部消耗" |
| 蒸汽搅拌方块 | 结构方块 | 已注册 | `items-and-blocks.md` 硬性要求：至少一个多方块结构必须明确要求该方块，不得只作装饰性换皮 |
| 蒸汽装配方块 | 结构方块 | 已注册 | 同上 |

| 工业蒸汽机械方块 | 上游外壳（本模组补配方） | 已补配方 | "哪些机器使用它"被明确推迟到机器设计阶段 |

### 1.2 产汽端缺口（量级不匹配）

| 项目 | 每刻需求 / 产量 |
| --- | ---: |
| 大型蓄热蒸汽熔炉 `15×15×18` 满温（Normal/Expert） | `12,800 mB/t` |
| 大型蓄热蒸汽熔炉 `7×7×6` 满温（Normal/Expert） | 约 `1,529 mB/t` |
| 大型蒸汽粉碎机 `64` 并行 | `256 mB/t` |
| 高压混合燃料锅炉协同燃烧（Normal） | `300 mB/t` |
| 高压混合燃料锅炉协同燃烧（Expert） | `120 mB/t` |

即：喂满一台 `7×7×6` 熔炉约需 5 台高压协同燃烧锅炉，喂满 `15×15×18` 约需 43 台。产汽端目前只有单方块锅炉，缺少与"大型耗汽机器"同量级的供汽设施。

### 1.3 排序权重

1. **消化孤儿资产数量**（`items-and-blocks.md` 的准入条件是硬约束，权重最高）；
2. **是否填补文档已经预告或预留的扩展点**（如 `ore-crushing.md` 的湿式处理、`large-heat-storage-steam-furnace.md` 的未来专用蒸汽仓接口）；
3. **能否复用已实现代码**（`AbstractSteamCrusherMachine` 的并行、原子扣取、逐 tick 取汽、最坏情况输出预检、排气仓、GUI/Jade 骨架）；
4. **科技阶段越级风险**（组装机、洗矿机、混合机、蒸馏在 GTCEu 中分别属 LV/MV，需要界定配方子集）；
5. **与 GTCEu 上游重复定位的风险**（需核验上游是否已有同语义机器）。

## 三、候选说明

### S1 大型蒸汽洗矿厂（湿式矿物处理多方块）

- 定位：矿石粉碎机的下一环，把粉碎矿用水洗成纯净产物，取代玩家在 LV 之前无法使用的洗矿机路线。
- 依据：`ore-crushing.md` 明确写下"以后若设计湿式矿物处理，应使用洗矿、化学浸洗或另一种语义明确的独立配方类型"，这是唯一被文档预告过的下一个内容。
- 消化：**蒸汽流体输入仓（水）+ 蒸汽流体输出仓（废液/产出流体）+ 蒸汽搅拌方块（水洗翻滚语义）**，外壳可用工业蒸汽机械方块。
- 复用度最高：结构与并行逻辑可直接继承 `AbstractSteamCrusherMachine` 的思路，GUI/Jade、排气仓、原子取汽、最坏情况输出预检全部现成。
- 待定：新配方类型 ID 与槽位（建议 `1` 物品输入 + `1` 流体输入 + `2–4` 物品输出 + `0–1` 流体输出）；是否只接受粉碎矿与纯净产物；是否要求蒸汽排气仓。

### S2 大型混合燃料蒸汽锅炉

- 定位：单方块混合燃料锅炉的上位机，把"液体燃料 + 助燃粉料协同燃烧"这条本模组独有语义放大到多方块量级，给大型熔炉与大型粉碎机供汽。
- 消化：**工业蒸汽机械方块（黄铜工业外壳，蒸汽时代中后期，正好对口）+ 蒸汽进气室（助燃空气，平均 `50 mB/t`）+ 蒸汽流体输入仓（给水）**。
- 待定：蒸汽由哪个接口输出（需核验 GTCEu 7.5.3 大型锅炉的蒸汽输出接口，若上游已有则复用，否则需新增一个"蒸汽输出仓"部件）；是否沿用 `5× / 5× / 2×` 锅炉产量倍率；燃烧是否真的消耗进气室空气（否则进气室只作成型部件，语义变弱）。

### A1 蒸汽过热器 + 过热蒸汽仓

- 依据：`large-heat-storage-steam-furnace.md` 的"首版范围与未来蒸汽仓扩展接口"已经为过热蒸汽预留了显式扩展点（蒸汽类型 ID、热值换算、每刻流量或无限流、供汽优先级、能力解锁集合），并预留了"允许单批多种配方"能力标识。
- 价值：这是文档级明确的下一步，而且能一次性把"未来专用蒸汽仓"扩展接口从纸面变成有提供者的实现。
- 风险：会改动熔炉已经实现的取汽与批次锁定逻辑，建议在熔炉通过用户验收之后再启动。

### A2 大型蒸汽蓄汽罐（蓄热器）

- 定位：多方块蒸汽缓冲设施，把锅炉的平稳产出与熔炉的脉冲式高瞬时需求解耦。
- 消化：工业蒸汽机械方块（承压外壳）+ 蒸汽流体输入/输出仓（作为蒸汽进出的配方/流体接口，或直接复用蒸汽供给仓语义）。
- 待定：必须与既有原则划清——"缓存不提供并行、速度、效率加成"，蓄汽罐只能平滑瞬时流量，不能让机器突破每仓 `1,200 mB/t` 的机器侧上限；否则会与供给仓规格冲突。

### A3 贝塞麦转炉（大型蒸汽炼钢炉）

- 定位：铁/生铁 + 空气 → 钢的蒸汽时代炼钢设施。
- 消化：**蒸汽进气室（吹炼空气，这是"消耗空气"最经典的工业语义）** + 工业蒸汽机械方块（高温炉衬外壳）。
- 待定：GTCEu 7.5.3 的钢、锻铁在蒸汽阶段的实际位置（钢在蒸汽时代已可通过高炉/焦炉链取得）；若钢已可稳定获得，需改为产出"更高吞吐"或"减少焦炭消耗"的收益，而不是解锁新材料。

### A4 大型蒸汽研磨厂（球磨）

- 定位：接在洗矿厂之后，把纯净粉碎矿磨成粉尘，取代 LV 研磨机在蒸汽阶段的角色。
- 消化：蒸汽搅拌方块（研磨/翻滚）+ 蒸汽流体输入仓（可选湿磨）。
- 待定：必须与 S1、以及迁移后仍保留的 GTCEu 研磨机三者划清边界——`ore-crushing.md` 已明确研磨机继续处理"粉碎矿到含杂矿粉、纯净/离心粉碎矿到粉尘"，本机若接管会重复。

### A5 蒸汽煤气发生炉（气化炉）

- 定位：煤/焦炭 + 空气 + 蒸汽 → 发生炉煤气，为锅炉与熔炉提供燃料气，与已有的焦炉构成煤化工的另一半。
- 消化：**蒸汽进气室 + 蒸汽流体输入仓（蒸汽/水）+ 蒸汽流体输出仓（煤气）**。
- 待定：产出气体如何进入"液体燃料锅炉"的燃料语义（当前锅炉只接受液体燃料与助燃粉料），可能需要同时扩展锅炉燃料白名单，属于跨机器变更。

### B1 / B2 蒸汽装配机与大型蒸汽精密装配机

- 定位：消化**蒸汽装配方块**与**蒸汽电路装配方块**两个孤儿；精密型可处理含流体（液态橡胶、焊锡类）的装配配方。
- 风险最高：组装机在 GTCEu 属 LV，而本模组几乎所有方块都是"蒸汽阶段手工 + LV 组装机"双路线，蒸汽时代再放一台装配机容易与电力时代打架。
- 建议：等 S1、S2 落地、LV 边界讨论清楚后再单独立规格；若先做，只做普通型并严格限定为"蒸汽相关与编程电路配置子集"。

### B3 大型蒸汽搅拌机 / 混合机

- 定位：消化**蒸汽搅拌方块**的备选归属。
- 取舍：如果 S1 洗矿厂已经要求蒸汽搅拌方块，本机就不必单独存在（`items-and-blocks.md` 只要求"至少一个结构要求它"）。建议优先让 S1 消化，本机降为备选。
- 风险：混合机在 GTCEu 属 MV，越级风险高于洗矿机。

### B4 蒸汽化学浸洗厂

- 定位：与 S1 并列被 `ore-crushing.md` 点名的湿式方向（洗矿 / 化学浸洗）。
- 取舍：与 S1 属同一生态位，建议先做 S1，本机作为后续扩展（处理洗矿之后的化学提纯）。

### B5 蒸汽抽水站

- 定位：为锅炉与洗矿厂稳定供水，解决"水"这个被所有新机器共同需要的输入。
- 消化：工业蒸汽机械方块 + 蒸汽流体输出仓。
- 待定：必须明确不是无限水源（与仓规格里"不提供无限水"的精神一致），应是从水源抽取并受维度/生物群系/流量限制的取水设施。

### B6 大型蒸汽锻压厂

- 定位：板材、杆件与零件的大批量蒸汽加工（落锤/锻压语义）。
- 消化：蒸汽装配方块（夹持与传动）+ 工业蒸汽机械方块。
- 待定：需先核验 GTCEu 7.5.3 是否已有蒸汽锻造锤或同类机器，避免重复。

## 四、建议设计顺序

1. **第一批（低风险、高消化）**：S1 大型蒸汽洗矿厂 → S2 大型混合燃料蒸汽锅炉。
2. **第二批（需要先决条件）**：熔炉通过用户验收后做 A1 过热蒸汽仓扩展；材料链确认后做 A3 转炉或 A5 气化炉。
3. **第三批（边界谈判）**：B1/B2 装配系列、B4 化学浸洗、A4 研磨厂，都需要先与上游 LV/MV 机器划清边界。
4. **远期**：C 档全部；C6 高级终端按既有决定继续留在首版之外。

三条需要用户先拍板的选择题：

- **蒸汽搅拌方块归谁**：洗矿厂（推荐）还是单独的大型蒸汽搅拌机？
- **蒸汽进气室归谁**：锅炉助燃（推荐）、转炉吹炼，还是气化炉？
- **湿式处理先做哪一条**：洗矿（推荐）还是化学浸洗？

## 五、不推荐的候选

| 候选 | 不推荐原因 |
| --- | --- |
| 蒸汽发电、任何 EU 相关机器 | 违反"蒸汽是唯一动力、机器不得使用电力"的技术路线 |
| 冷凝水回收 / 省煤器 | 与"当前机器不产生可回收的排气副产物""冷凝水或废气容器不注册"两条既有决定冲突，需先推翻决定才能讨论 |
| 高炉 / 原始高炉 | 与 GTCEu 上游同语义机器重复 |
| 多方块储罐 | 上游已有同语义结构 |
| 无限水源类机器 | 与本模组一贯拒绝"无限水"的边界冲突 |
| 蒸汽涡轮机 / 动力机械 | 本模组不产出 EU，缺少消费端；`difficulty.md` 已把蒸汽涡轮排除在锅炉倍率之外 |

## 六、任何一台机器立项时必须补齐的内容

按 `items-and-blocks.md` 的"新条目准入条件"与 `difficulty.md` 的"全局设置接入规则"，每台新机器在转入已确认状态前必须写明：

1. 中文名、英文名、资源 ID、注册字段、机器类、科技阶段；
2. 配方类型与槽位（物品/流体输入与输出各几槽）；
3. 结构尺寸、固定核心位置、可替换接口及各接口的精确数量上下限；
4. 并行公式、处理时间、蒸汽换算率与每刻需求；
5. 至少要求哪些孤儿资产，以及为什么不能复用 GTCEu 现有内容；
6. `Easy / Normal / Expert` 三档中受控字段的具体值（控制器恒为 `1` 个产出）；
7. 与已实现机器的复用关系（是否继承抽象基类）；
8. 验收清单（由用户执行，不得由助手代跑）。
