# 大型蒸汽高炉设计

本文档是「大型蒸汽高炉」的设计文档。机器定位承接 `next-machine-candidates.md` 第三节暂缓项「高炉大型上位变体」，并修复蒸汽时代的大宗锻铁获取缺口。结构定稿为 `13×13` 底 × `15` 高的三段收分巨塔、普通批次最大并行 `96`；2026-09-20 将固定 `0.4×` 耗时改为按连续同配方完成份数成长的四档生产熟练度，并增加由主控制器管理、无独立控制器的可选双塔热风炉组。2026-09-21 又定案顶部 `BF-T-10` 高位加料塔，以连续两批、固定资源峰值和复位债务换取临时最高 `192` 并行。2026-09-11 取消墙体高炉砖最低数量及其派生仓室上限，固定炉床、工艺核心和功能接口规则保持不变。

## 上游事实核查：锻铁与钢（已核对源码）

> 用户立项指令要求"注意检查得到锻铁的现有配方"。以下为 GTCEu Modern `7.5.3` 源码逐项核查结论（2026-09-09）。

**锻铁（Wrought Iron）产出配方盘点：**

| 途径 | 配方 | 时代门控 | 蒸汽时代可用 |
| --- | --- | --- | --- |
| 熔炉 | `smelt_dust_iron_to_ingot`：铁粉 → **铁锭**（非锻铁；`MaterialRecipeHandler#processDust` 直接取 `ChemicalHelper.get(ingot, Iron)`，`IngotProperty.smeltingInto` 不参与熔炉配方生成） | 无 | ✅ 但产出是铁 |
| 熔炉 | 铁矿石/粗铁直烧 → 铁锭（`MaterialFlagAddition` 设铁矿石 directSmeltResult = Iron） | 无 | ✅ 但产出是铁 |
| **熔炉（铁粒）** | `gtceu:wrought_iron_nugget`：铁粒 → 锻铁粒（`forge:nuggets/iron` 标签，`CraftingRecipeLoader` 注册；锻铁粒 ×9 可经上游既有配方合回锻铁锭） | 无 | ✅ 零散路线 |
| 电弧炉 | `ArcFurnaceLogic` 按 `arcSmeltingInto` 动态生成：铁锭/铁粉/铁质工具 + 氧气 → 锻铁 | LV 电力 | ❌ |
| 电力高炉 | `rutile_from_ilmenite`：钛铁矿 + 碳 → 锻铁副产（HV，`TitaniumRecipes`） | HV | ❌ |

**结论（2026-09-09 二次核定修正）**：上游蒸汽时代锻铁产出仅有一条**零散路线**——铁粒烧锻铁粒（早期核查按材质名搜索漏检了 `CraftingRecipeLoader` 的这条注册，用户 2026-09-09 指正）；铁粉/铁矿石/铁锭直烧路线均不产锻铁，`Iron.INGOT.setSmeltingInto(WroughtIron)` 字段在 7.5.3 中仅被回收配方（RecyclingRecipes）用于电压倍率判定；上游刻意"de-wrought"（issue #792/#1179：阻止锻铁↔铁双向转换），锻铁锭的规模产出仍被定位为电弧炉产物。粒锭九转一 + 每粒一烧的换算成本，使该零散路线无法承担模组大型结构（数百锻铁板）的吞吐需求——**大宗锻铁缺口成立**。

**锻铁消费端（蒸汽时代真实存在）：**

| 消费方 | 锻铁需求 |
| --- | --- |
| 钢级蒸汽单方块机器 ×6（研磨机/锻造锤/提取机/压缩机/合金炉/岩石破碎机的钢版工作台配方） | 各 `3` 锻铁板 |
| 砖砌锻铁外壳 `gtceu:steel_brick_casing`（本模组大型蓄热蒸汽熔炉结构方块） | 每个 `5` 锻铁板 + `3` 砖 |
| ULV 机械外壳 `casing_ulv`（LV 时代门槛） | 每个 `8` 锻铁板 |
| 锻铁环/螺丝/杆等杂项 | 少量 |

即：**仅靠上游的铁粒零散路线，本模组大型蓄热蒸汽熔炉（需要砖砌锻铁外壳）与钢级蒸汽机器的锻铁需求将陷入极低效的九转一换算，进度体验严重受损。**这是立项的直接动因。

**钢的获取（蒸汽时代既有途径）：原始高炉 PBF（`gtceu:primitive_blast_furnace`，单机多块形态、无并行）。**

| 配方 | 输入 | 输出 | 时长 |
| --- | --- | --- | --- |
| `steel_from_coal_gem/_dust` | 铁锭 + `2` 煤（块/粒形态均可） | 钢 + `2` 小撮黑灰 | `1800t` |
| `steel_from_charcoal_gem/_dust` | 铁锭 + `2` 木炭 | 钢 + `2` 小撮黑灰 | `1800t` |
| `steel_from_coke_gem/_dust` | 铁锭 + `1` 焦炭 | 钢 + `1/9` 灰（机会） | `1500t` |
| `steel_from_*_wrought` 系列 | **锻铁锭** + 同上燃料表 | 钢 + 同上副产 | `800t`（煤/木炭）/ `600t`（焦炭） |
| 块版本 `steel_from_*_block*` | 铁块/锻铁块 + `2` 燃料块 / `1` 焦炭块 | 钢块 + 灰 | `16200/13500/7200/5400t` |

PBF 接受铁锭或锻铁作为铁源——**但蒸汽时代没有锻铁来源，`800/600t` 快速线在上游是死内容**。本机修复该断链。

### 分工边界（议题 2）

- 执行 `gtceu:primitive_blast_furnace`（原始高炉）配方类型**全类型**（本模组注入的 `3` 条锻铁配方 + 上游 `18` 条炼钢配方，含 `steel_from_*_wrought` 锻铁 → 钢）；与上游 PBF 同语义规模化，无类型新设。
- **锻铁获取注入**（见专节）：`3` 条"铁粉 + 燃料粉 → 锻铁"配方加入上游 `primitive_blast_furnace` 类型（add-only），PBF 与本机共用——补足大宗锻铁路线；铁粒烧锻铁粒为上游既有零散路线（`gtceu:wrought_iron_nugget`），2026-09-09 用户裁定本模组不加入。
- 与暂缓项的关系：`next-machine-candidates.md` 第三节"高炉大型上位变体（原 A3 转炉）"于 2026-09-09 由用户点名激活，本项目即其落地形态；"高炉 / 原始高炉不推荐"条款保持——本机是上位变体而非上游同语义重复。
- 与大型蓄热蒸汽熔炉的分工：熔炉运行熔炉/合金炉配方（铁粉 → 铁锭、合金），高炉运行原始高炉配方（铁粉 → 锻铁、铁/锻铁 → 钢）；两条精炼链在配方类型上零重叠。
- **与上游 PBF 的关系**：本机是上游 PBF 同语义的规模化上位（最高 `96` 并行、熟练度决定耗时），上游能做的本机都能做；上游 PBF 自身保留全部 `18` 条钢配方（见《机器侧口径》）。
- 电力高炉（EBF，MV+）与 `gtceu:blast_furnace` 类型原样保留，本机不触及。

### 机器侧口径（2026-09-09 裁定：单侧切开共用配方类型）

本模组的 `3` 条锻铁配方以 add-only 方式注入**上游既有类型** `gtceu:primitive_blast_furnace`，该类型由本机与上游 PBF 共用。裁定只在**上游那一侧**切开，配方数据本身不动：

| 机器 | 口径 | 实现 |
| --- | --- | --- |
| 大型蒸汽高炉（本机） | **全类型执行**：本模组 `3` 条铁粉 → 锻铁 + 上游 `18` 条炼钢配方（铁锭/铁块 → 钢、`steel_from_*_wrought` 锻铁 → 钢） | 不覆写 `acceptsRecipe()`，保持家族默认 |
| 上游原始高炉 PBF | 🚫 不执行 `gregsteamexpansion:` 命名空间的配方（保留其全部 `18` 条钢配方） | `RecipeLogicMixin` 在 `searchRecipe()` 上按机器类型过滤候选迭代器 |

**为什么只切一侧**：本机是上游 PBF 的规模化上位，上游能做的本机都能做——包括全部炼钢配方，高炉产钢是应有之义。需要堵的只是**反向串味**：上游 PBF 若能用 `800t` 的铁粉配方白捡锻铁（比它自己的 `1800t` 钢路线还快），本机的存在意义就被架空了。因此过滤只加在上游 PBF 的候选迭代器上。

🚩 **锻铁定位（用户 2026-09-09 裁定）**：*锻铁不是钢的中间体，而是重要的资源*。锻铁板是钢级蒸汽单方块机器、砖砌锻铁外壳（大型蓄热蒸汽熔炉结构方块）与 ULV 机械外壳的必需材料，自身需求量巨大——把它读成"炼钢的过渡品"是误读。语义上锻铁与钢是两条并重的产物线；实现上 `steel_from_*_wrought`（锻铁 → 钢）仍作为**玩家的自由选择**保留（富余锻铁可以烧成钢），并非强制流向。

**已知偏差**：JEI/REI 的 `primitive_blast_furnace` 配方分类是按类型而非按机器展示的，所以上游 PBF 的分类页面仍会列出本模组的 `3` 条锻铁配方；过滤只作用于**实际执行**。如需页面级一致，后续可对分类做客户端过滤（未做）。

### 配方执行细节（议题 3）

- 全配方开放：`gtceu:primitive_blast_furnace` 类型全部配方（`3` 条锻铁 + `18` 条钢）；基准数值不修改。
- **无 EU 配方类型**：PBF 配方不带 EU/t（能量即配方内的固体燃料）。家族的"电压门"对本机退化为：带 EU/t 的配方（外部模组可能加入）仍按家族口径限 `≤ LV`，无 EU 配方直接放行。
- 纯干式：`1–2` 物品入 / `1` 物品出 + `≤1` 机会产出；无流体槽，流体仓（两个家族）一律不可装入。

### 结构与外观（议题 4）

（2026-09-09 用户三次裁定：极高造价与极大的结构换取极高效率；结构不要四四方方，占地更大；**结构主体以高炉砖块为主**——最终定稿为三段收分塔形，墙体主体为高炉砖（`gtceu:firebricks`，耐火砖块，与原始高炉同款材质），工业蒸汽机械方块退居环框/角柱/炉喉盖/烟囱冠）

#### 固定结构

- 包围盒"宽 `13` × 深 `13` × 高 `15`"**三段收分塔**：13×13 炉缸/鼓风段 → 11×11 炉身 → 9×9 炉喉盖 → 5×5 烟囱冠，逐段内收缩出真实高炉轮廓；只允许四个水平朝向。
- 材质分区：
  - **层 `1`（炉缸）**：外环 `48` 格工业蒸汽机械方块（`gtceu:industrial_steam_casing`，含正面正中控制器），内部 `11×11 = 121` 格**焦炭砖炉床**（`gtceu:coke_bricks`——炉内焦炭床，呼应焦炉→高炉燃料链）。
  - **层 `2`（鼓风层）**：`13×13` 环——四角工业蒸汽机械方块（`4`）+ `44` 格**高炉砖**（`gtceu:firebricks`，仓室可替换位）；内部 `11×11` 严格空气。鼓风口与仓室的主装配层。
  - **层 `3`–`11`（炉身，`9` 层）**：`11×11` 环（内缩 `1` 格）——四角工业蒸汽机械方块（`36`）+ `36` 格/层高炉砖（`324`）；内部 `9×9` 严格空气（`729`）。
  - **层 `12`（炉喉盖）**：`9×9` 实心工业蒸汽机械方块（`81`，内缩 `2` 格）。
  - **层 `13`–`15`（烟囱冠）**：`5×5` 实心工业蒸汽机械方块（`75`，内缩 `4` 格，冠外不校验）。
- 控制器位于正面底层水平正中。

- **复位债务**：每个高装料批次在**开工时**立刻增加 `ceil(锁定耗时 × max(0, P - 96) / 96)` 个复位 tick；批次后来中止也不撤销。第 2 批完成后进入复位阶段，每个成功复位 tick 原子消耗 `19,200 mB` 蒸汽与 `384 mB` 空气，不产出物品、不推进配方、不增加熟练度。资源顺序与正常批次一致：先模拟空气，再扣蒸汽，最后实际扣空气。
- **复位冻结**：缺汽、缺空气、玩家暂停、主体失效或排气受阻都只冻结剩余债务，不清零、不倒退，也不消耗资源；条件恢复后继续。债务归零才解除周期并恢复普通配方搜索与热风循环。
- **模块故障**：控制器仍加载时，模块损坏、归属冲突或模块单独卸载会立即丢弃正在运行的高装料批次；已经扣除的输入和逐 tick 资源不返还，不生成输出，已在开工时锁入的全部债务保留并立刻转入复位。若故障发生在两批之间，则不再等待第 2 批，直接复位第 1 批债务。拆除模块不能清除债务。
- **保存与拆除**：正常整体卸载或服务器重启保留当前批次、周期阶段与债务，重载后先等待模块重新校验，不能把尚未加载误判为损坏。拆除控制器沿用既有生命周期清理，连同批次、周期与债务全部清除。
