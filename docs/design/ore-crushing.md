# 矿石粉碎配方类型设计

本文档定义 Greg Steam Expansion 新增的“矿石粉碎”配方类型，以及它与 GTCEu 7.5.3 研磨机配方的迁移边界。该配方类型只表达从矿石或粗矿得到粉碎矿的第一段矿物处理，不负责定义具体机器的结构、蒸汽消耗、并行数或超频规则。

## 设计目标

- 把“破碎大块矿物”和“把中间产物研磨成粉”拆成两个明确工序。
- 让以后使用蒸汽碾磨方块的专用多方块机器只接收矿石粉碎配方，而不自动获得研磨机的回收、工具拆解和通用磨粉能力。
- 只有以宿主岩石中的矿石方块为输入时，粉碎矿基础主产物提高为对应 GTCEu 原配方的 `4×`，作为专用大型矿石粉碎设备处理整块矿石的明确收益；粗矿配方的基础主产物与全部概率副产物的数量均保持上游原值。在此基础上，所有矿石粉碎配方的主产物再读取工作强度倍率 `2× / 1.5× / 1×`。
- 迁移后的配方在配方查看器中只出现一次，研磨机与矿石粉碎分类之间不能同时保留等价路线。

## 基本定义

| 字段 | 设计 |
| --- | --- |
| 状态 | 配方语义、迁移范围与基准数值已确定，尚未实现 |
| 中文名 | 矿石粉碎 |
| 英文名 | Ore Crushing |
| 配方类型 ID | `gregsteamexpansion:ore_crushing` |
| Java 注册字段 | `GSERecipeTypes.ORE_CRUSHING_RECIPES` |
| 配方组 | `multiblock` |
| 物品输入 | 最多 `1` 槽 |
| 物品输出 | 最多 `4` 槽 |
| 流体输入与输出 | 均为 `0` 槽 |
| 能量方向 | 输入 |
| 基准功率 | `2 EU/t` |
| 基准持续时间 | `400 tick`（20 秒） |
| 基准总能量 | `800 EU` |
| 蒸汽机器执行时间 | `600 tick`（30 秒，基准持续时间的 `1.5×`） |
| 蒸汽机器等效总能量 | `1,200 EU`（实际蒸汽量由机器换算率决定） |
| 基础物品产量倍率 | 矿石方块配方的粉碎矿主产物为上游原值的 `4×`；粗矿配方的主产物与全部概率副产物为 `1×` |
| 主产物工作强度倍率 | Easy `2×`、Normal `1.5×`、Expert `1×` |

- 配方仍以 `2 EU/t`、`400 tick` 记录基准功率和时间，使 GTCEu 的通用配方逻辑、配方查看器与机器修饰器能够识别它；蒸汽机器执行时以 `600 tick` 作为实际基础时长。蒸汽机器怎样把 `1,200 EU` 等效总能量换算成蒸汽属于机器规格，不写入配方类型。
- `4` 个输出槽用于容纳粉碎矿主产物、矿石第一副产物以及矿石宿主材料带来的概率副产物；空槽不生成占位物品。
- 该类型不挂接 GTCEu 研磨机的动态工具或涡轮转子拆解逻辑，也不复用 `MaceratorLogic`。只有显式登记的静态矿石粉碎配方可以运行。
- 即使机器结构安装了[蒸汽流体输入/输出仓](machines-and-hatches.md#已定案蒸汽流体输入输出仓)，本类型仍保持 `0` 个流体输入和输出槽。新仓只服务于明确声明流体槽的其他配方类型，不给干式矿石粉碎附加注水增产或隐藏流体条件。

## 输入与输出语义

### 纳入范围

矿石粉碎只接受下列两类单物品输入：

1. GTCEu `TagPrefix.ORES` 中实际生成的矿石形态，包括普通石头、深板岩、下界岩、末地石以及其他已登记宿主岩石中的矿石方块；
2. GTCEu `TagPrefix.rawOre` 表示的粗矿物品。

两类输入的必需主产物都是同一材料的 `TagPrefix.crushed` 粉碎矿。配方必须遵守对应材料的 `OreProperty`；没有粉碎矿形态、无法解析主材料或输入与输出材料不一致时，不得生成或迁移配方。

### 明确排除

- `TagPrefix.rawOreBlock` 粗矿块不直接进入矿石粉碎。它继续先按既有无序合成或锻造锤路线拆成 `9` 个粗矿，避免新增一条上游不存在的整块处理收益。
- 粉碎矿、纯净粉碎矿、离心粉碎矿、含杂矿粉、纯净矿粉和普通粉尘不是本类型的输入；它们继续由洗矿、离心、热离心、研磨机等既有后续工序处理。
- 锭、宝石、板、齿轮、工具、涡轮转子、机器零件和回收物不因最终能够产出粉尘而成为矿石粉碎输入。
- 配方不能接收流体、编程电路、催化剂或研磨头物品。研磨头属于机器结构成本，不是逐次消耗的配方材料。

## GTCEu 7.5.3 基准配方

GTCEu 7.5.3 当前把目标配方登记在 `GTRecipeTypes.MACERATOR_RECIPES` 中，并使用 `GTRecipeCategories.ORE_CRUSHING` 子分类。迁移会改变配方类型、所属分类与资源 ID，并先只把矿石方块配方的粉碎矿基础主产物数量乘 `4`；粗矿配方的基础主产物以及所有概率副产物的数量、概率与概率提升参数均保持不变，输入、输出种类、配方记录的基准功率与基准持续时间、配方条件也保持不变。完成基础数量计算后，再对矿石与粗矿配方的主产物统一应用工作强度倍率；蒸汽机器运行时另行应用 `600 tick` 执行规则。

### 宿主岩石中的矿石

| 项目 | 基准规则 |
| --- | --- |
| 输入 | `1` 个对应矿石方块 |
| 粉碎矿基础主产物 | 工作强度前为 `4 × (2 × OreProperty.oreMultiplier × OreType.doubleDrops)`，即 `8 × OreProperty.oreMultiplier × OreType.doubleDrops` 个 |
| 第一矿物副产物 | 保持上游原值：`14%` 概率产出原数量的第一副产物宝石，无宝石形态时使用对应粉尘 |
| 宿主材料副产物 | 保持上游原值：对该矿石前缀的每份可生成粉尘的 `secondaryMaterials`，分别以 `67%` 概率产出原数量的等价宝石/粉尘堆叠 |
| 功率与时间 | 配方基准为 `2 EU/t`、`400 tick`；蒸汽机器实际执行 `600 tick` |

`OreType.doubleDrops` 在上游标记为双倍掉落的矿石宿主上取 `2`，否则取 `1`。迁移不得把这个倍率重复应用到粗矿，亦不得把宿主材料副产物添加给没有宿主岩石的粗矿物品。

### 粗矿

| 项目 | 基准规则 |
| --- | --- |
| 输入 | `1` 个对应粗矿 |
| 粉碎矿基础主产物 | 工作强度前保持上游原值：`2 × OreProperty.oreMultiplier` 个 |
| 第一矿物副产物 | 保持上游原值：`14%` 概率产出原数量的第一副产物宝石，无宝石形态时使用对应粉尘 |
| 宿主材料副产物 | 无 |
| 功率与时间 | 配方基准为 `2 EU/t`、`400 tick`；蒸汽机器实际执行 `600 tick` |

- 所有概率值继续使用 GTCEu 配方系统的万分比语义：`14% = 1400 / 10000`，`67% = 6700 / 10000`。
- `4×` 基础倍率只作用于矿石方块配方的必需粉碎矿主产物，不作用于粗矿配方，也不作用于任何概率副产物。工作强度倍率则作用于矿石与粗矿配方的主产物，但同样不作用于概率副产物。
- `14%`、`67%`、概率提升参数和命中后的副产物堆叠数量在三个工作强度下全部保持上游原值。
- 倍率不把粉碎矿复制成四个配方输出项。若放大后的逻辑数量超过该物品的单组堆叠上限，执行机器必须在启动前确认输出空间能够容纳全部数量，并在完成时拆分到多个实际槽位；空间不足时不得截断、掉落或只输出一部分。
- 原配方的概率提升参数、配方条件、输入标签或精确物品约束若存在，迁移时必须逐项原样复制；除矿石方块配方的粉碎矿主产物数量外，未在本节列出的数据不能静默改变或丢弃。
- 三档均先使用矿石主产物基础 `4×`、粗矿主产物基础 `1×` 和概率副产物 `1×`，再只对主产物应用 Easy `2×`、Normal `1.5×`、Expert `1×`。概率、功率和时间不读取该倍率。

## 从研磨机迁移

### 目标识别

迁移目标按配方语义识别，不仅依赖显示名称或字符串包含关系。一份配方必须同时满足以下条件才可以自动迁移：

1. 当前类型为 `GTRecipeTypes.MACERATOR_RECIPES`；
2. 当前分类为 `GTRecipeCategories.ORE_CRUSHING`；
3. 恰好消耗一种矿石或粗矿输入；
4. 必需主产物为同一材料的粉碎矿；
5. 没有流体输入、流体输出或与矿石粉碎无关的额外消耗品。

- 不能仅按配方 ID 包含 `macerate`、输入名称包含 `ore` 或输出名称包含 `crushed` 批量迁移。
- 满足部分条件但无法确认材料对应关系的配方必须保留原状并记录包含配方 ID 的错误；在受支持的 GTCEu 7.5.3 基准集合中出现这种状态时应阻止完成配方加载，不能留下只迁移一部分矿石的世界。
- 其他模组可以显式向新类型登记配方。未知命名空间中的自定义研磨机配方只有通过同一完整语义校验后才允许自动迁移，避免截获作者有意保留的特殊加工。

### 迁移动作

对每份确认目标执行一个不可分割的“复制后移除”操作：

1. 将原输入、输出种类与数量、概率输出、概率提升、持续时间、EU/t 和配方条件复制到 `gregsteamexpansion:ore_crushing`；仅当输入属于 `TagPrefix.ORES` 时，先把同材料 `TagPrefix.crushed` 必需主产物的基础数量乘 `4`，再对矿石与粗矿配方的主产物统一应用当前工作强度的 `2× / 1.5× / 1×`，全部概率输出不应用任何产量倍率；
2. 新资源 ID 使用 `gregsteamexpansion:ore_crushing/<原命名空间>/<原路径>`，保留来源以便诊断并避免不同模组同路径冲突；
3. 新配方成功登记后，从研磨机配方数据库及其 `ORE_CRUSHING` 分类索引中移除原配方；
4. 在服务端配方同步和 EMI/JEI/REI 建立索引前完成迁移，使客户端永远不会同时看到新旧两份路线。

- 若目标 ID 冲突、复制字段失败或旧配方无法从两个索引中同时移除，则整份迁移回滚并终止配方加载。
- 每次数据重载都从本次加载得到的原始配方集合重新执行，不得在上一轮已经迁移的内存结果上再次套用，以免资源 ID 嵌套或产物翻倍。
- 服务端记录迁移总数；完成后必须校验“新类型新增数 = 研磨机移除数”，并确认研磨机中不存在仍满足目标识别条件的配方。

### 保留的上游路线

- 锻造锤把矿石或粗矿变为粉碎矿的 `ORE_FORGING` 配方保持不变。新类型只取代研磨机路线，不移除较低收益或较低自动化程度的替代工序。
- 研磨机继续处理粉碎矿到含杂矿粉、纯净/离心粉碎矿到粉尘、材料磨粉、回收和动态工具拆解。
- GTCEu 现有低压、高压蒸汽研磨机以及各电压研磨机不自动获得新配方类型，因此迁移完成后不能再直接处理矿石或粗矿。

## 机器接入边界

- 只有明确声明 `GSERecipeTypes.ORE_CRUSHING_RECIPES` 的机器能够执行该类型；不能通过同时声明整个研磨机配方类型来间接获得它。
- 第一台正常玩法可获得的矿石粉碎机器必须与配方迁移在同一功能版本启用。若没有任何已注册且可获取的配方消费者，启动时不得移除研磨机中的原配方，避免矿物处理链暂时断裂。
- 任何以蒸汽作为该配方能量来源的机器，都必须把配方基准 `400 tick` 乘以固定时长倍率 `1.5×`，以 `600 tick` 作为实际基础执行时间；不得按注册名中是否包含 `steam` 模糊识别，必须由机器的蒸汽能量处理器或显式机器类型声明触发。
- 蒸汽执行期间等效功率保持 `2 EU/t`，所以单份配方的等效总能量为 `2 × 600 = 1,200 EU`。实际总蒸汽消耗等于 `1,200 EU × 该机器规定的蒸汽换算率`；不能仍按 `800 EU` 换算后只把进度空转到 `600 tick`。
- 非蒸汽消费者仍使用配方记录的 `400 tick`、`800 EU` 基准。以后某台机器若具有额外速度修饰，必须以对应能源类型的 `600 tick` 或 `400 tick` 为起点，并在该机器规格中明确计算顺序。
- [蒸汽碾磨方块](items-and-blocks.md#蒸汽碾磨方块)只作为候选多方块结构组件。它自身没有库存、GUI 或执行配方的能力，也不因新配方类型存在而变成单方块机器。
- 通用[蒸汽流体输入/输出仓](machines-and-hatches.md#已定案蒸汽流体输入输出仓)不能扩大本类型的流体槽数量；以后若设计湿式矿物处理，应使用洗矿、化学浸洗或独立的新配方类型。
- 除本节统一规定的蒸汽机器基础时长外，具体控制器、结构尺寸、蒸汽供给、额外速度修饰、并行、堵塞和输出空间规则应在对应机器规格中决定；本类型不为这些行为提供其他隐含默认值。

## 配方查看器与表现

- EMI/JEI/REI 使用独立的“矿石粉碎 / Ore Crushing”类别，不再把迁移后的配方显示在“研磨机 / Macerator”页面下。
- 页面固定显示 `1` 个输入位和最多 `4` 个输出位，主产物位与概率副产物位必须有明确区分，并沿用 GTCEu 对概率和概率提升的标准提示。
- 首版可以复用 GTCEu 的粉碎矿槽位覆盖层、研磨进度条填充方向和研磨声音；配方类型名称与分类身份必须独立，不能只把原研磨机页面换一个标题。
- 配方查看器必须同时标明“配方基准：`400 tick`”与“蒸汽机器：`600 tick`”，或者在从具体蒸汽机器查看用途时直接显示修饰后的 `600 tick`；不能只显示 `400 tick` 而让玩家误认为蒸汽机器也使用该时间。
- 类别图标应使用首个实际接入该类型的机器控制器。消费者尚未完成时不注册一个仅供查看、无法执行的空类别。

## 工作强度

本类型接入[全局工作强度机制](difficulty.md)。主产物工作强度倍率在基础主产物数量计算完成后应用：

```text
最终主产物数量 = 基础主产物数量 × 当前工作强度倍率
```

| 字段 | Easy | Normal | Expert |
| --- | ---: | ---: | ---: |
| 主产物工作强度倍率 | `2×` | `1.5×` | `1×` |
| 矿石方块配方的最终主产物 | 上游原值的 `8×` | 上游原值的 `6×` | 上游原值的 `4×` |
| 粗矿配方的最终主产物 | 上游原值的 `2×` | 上游原值的 `1.5×` | 上游原值 |
| 概率副产物数量 | 上游原值 | 上游原值 | 上游原值 |
| 副产物概率与概率提升 | 上游原值 | 上游原值 | 上游原值 |
| 功率 | `2 EU/t` | `2 EU/t` | `2 EU/t` |
| 配方基准持续时间 | `400 tick` | `400 tick` | `400 tick` |
| 蒸汽机器实际基础时长 | `600 tick` | `600 tick` | `600 tick` |
| 蒸汽机器等效总能量 | `1,200 EU` | `1,200 EU` | `1,200 EU` |

- 工作强度不改变哪些上游配方会被迁移，也不允许 Expert 把同一配方留在研磨机而 Easy 移入新类型。
- Normal 的 `1.5×` 必须按精确有理数 `3 / 2` 计算，不能使用浮点数后取整。GTCEu 基准配方的基础主产物数量均为偶数，因此结果始终为整数；其他模组显式登记的配方若无法在三档下得到整数主产物数量，应拒绝登记并报告配方 ID，不能向上或向下取整。
- 配方迁移与服务端同步使用存档实际工作强度，在同一会话中只生成当前档位对应的主产物数量，不注册三个可同时执行的配方副本。
- 每个加工批次在启动时锁定最终主产物数量和能源类型对应的基础时长。合法降档并完整重启后，已经启动的批次保持原锁定数量与时长，下一批才读取降低后的新档位；物品栏、容器和世界中已经存在的产物不追溯增减。

## 实现验收

1. `gregsteamexpansion:ore_crushing` 以 `1` 个物品输入、最多 `4` 个物品输出、无流体输入或输出槽、能量方向为输入完成注册，中英文名称完整。
2. GTCEu 7.5.3 所有“矿石/粗矿 → 粉碎矿”的研磨机配方各自只迁移一次，新旧配方条目数量守恒，研磨机中不再存在目标语义配方。
3. 逐项抽查普通矿石、双倍掉落宿主矿石和粗矿：矿石方块的最终粉碎矿主产物分别为迁移前的 `8× / 6× / 4×`，粗矿分别为 `2× / 1.5× / 1×`；每项概率副产物的数量保持迁移前原值，第一副产物仍为 `14%`，宿主副产物仍为 `67%`，基准功率与时间仍为 `2 EU/t`、`400 tick`。
4. 粗矿不获得宿主岩石副产物，粗矿块、粉碎矿、工具和回收物不能进入新类型。
5. 锻造锤路线和粉碎矿之后的全部矿物处理链保持可用；现有蒸汽及电力研磨机不能再直接处理矿石或粗矿。
