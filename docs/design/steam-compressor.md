### 分工边界（议题 2）

（用户 2026-09-07 确认）

- 仅执行 `gtceu:compressor` 配方类型；与 GCYM 电力多方块对照物按能源形态分层共存，保持上游原样。
- 与蒸汽压缩机单方块（青铜低压 + 钢高压蒸汽机器）：规模化上位关系（A4/C0/C1b 模式），单方块保留不动。
- 越级模式沿用：压缩机属 LV 电力机器，越级使用、以蒸汽消耗为平衡代价、电力路线原样保留。

### 配方执行细节（议题 3）

（用户 2026-09-07 确认）

- 执行 `gtceu:compressor` 类型全部配方（外部模组新增配方同规则），基准数值不修改（类型默认 `200 tick`、`2 EU/t`，配方可覆盖）。
- **LV 电压门：仅可执行电压等级 ≤ LV 的配方**（含 ULV；同 C0/C1b 与上游蒸汽单方块行为），MV 及以上被拒绝。
- 纯干式类型：无流体接口、无编程电路要求——全家族最简输入输出面（`1` 物品入 / `1` 物品出）。

### 结构与外观（议题 4）

（用户 2026-09-07 确认，方块数量为推导核算）

- 固定单套结构，包围盒 `3×3×3`；只允许四个水平朝向。
- **青铜框架核心**：内部唯一 `1` 格（正中）为青铜框架（`gtceu:bronze_frame`）——压缩腔。
- **背面中心活塞**：背面墙体正中 `1` 格为原版活塞（`minecraft:piston`）——推压语义，活塞的推进方向指向内部青铜框架（**建议成型判定要求该朝向且未伸出；若实现时判定过严可放宽为任意朝向，待复核**）。
- 其余外壳 `24` 格全部使用青铜蒸汽机械方块（`gtceu:steam_machine_casing`），为仓室可替换位置；控制器位于正面底层正中。
- 结构无空气格；无流体接口、无专用核心方块之外的其他结构方块。

第 `1` 层（底层）：

```text
BCB  ← 正面（控制器位于正面底层正中）
BBB
BBB
```

第 `2` 层（中层）：

```text
BBB  ← 正面
BFB
BPB  ← 背面（活塞位于背面中心，推进方向指向框架）
```

第 `3` 层（顶层）：

```text
BBB
BBB
BBB
```

符号：`B` 青铜蒸汽机械方块（仓室可替换位置）、`F` 青铜框架（压缩腔核心，不可替换）、`P` 原版活塞（背面中心，不可替换）、`C` 控制器。

- 校验：体积 `27` 格 = 外壳 `26`（`24` 青铜蒸汽机械方块 + 活塞 `1` + 控制器 `1`）+ 青铜框架 `1`。
- 仓室：物品输入/输出总线 ≥`1`、蒸汽供给仓 ≥`1`；**无任何流体仓**（类型纯干式）；**不使用排气仓**（2026-09-07 全模组裁定：非大型蒸汽多方块不使用排气仓），本机无排气受阻判定。
- 仓室合计最多 `8` 个，即青铜蒸汽机械方块可替换位置 `24` 个中至少保留 `16` 个。
- 结构共用：沿用全模组口径——不设结构独占与间距排斥。

### 动力与蒸汽消耗（议题 5）

（用户 2026-09-07 确认）

- 仅接受 GTCEu 标准蒸汽，不消耗 EU；蒸汽换算率 `2 mB = 1 EU`。
- 执行时长为配方基准耗时乘固定倍率 `1.5×`：`max(1, ceil(基准耗时 × 1.5))` tick；单份总耗汽 = `配方 EU/t × 执行时长 × 2` mB（默认基准 `200 tick`、`2 EU/t` 即 `300 tick`、`1,200 mB`）。
- 能耗口径沿用 C1b/C0 的**固定线性**：批次总耗汽与每刻需求按实际并行 `P` 线性放大。
- 断供蒸汽：进度回退至 `1 tick`，恢复后续跑原批次（本机不使用排气仓，无排气受阻判定）。
- 多供给仓不提高并行或效率；每仓 `1,200 mB/t` 上限沿用。

### 并行与吞吐（议题 6）

（用户 2026-09-07 确认）

- 最大并行固定 `8`（对照 C1b/C0 小型机）。
- 实际并行 = `min(8, 可用输入份数, 最坏情况输出可容纳份数)`（输出预检含 `1` 物品位）；公式小于 `1` 不开工、不扣取；批次开始后锁定。
- 耗时不随并行倍增；批次总耗汽与每刻需求按 `P` 线性放大（满并行 `8` 默认基准每刻 `48 mB/t`，单供给仓即可）。
- 配方选择沿用“最近成功配方优先”。

### 内部库存与批处理原子性（议题 7）

（用户 2026-09-07 确认）

- 沿用 C1b 口径：控制器缓存仅待输出结果，无内部物品槽；全部库存由仓室直接承载（类型无流体）。
- 开工预检跨全部总线聚合执行（`1` 物品输入份数 + `1` 物品输出位）；通过后一次原子扣取输入。
- 产物提交：一次性写入物品输出总线（跨总线/槽拆分堆叠）；待输出保险沿用。

### 运行控制与失效（议题 8）

（用户 2026-09-07 确认）

- 标准 GTCEu 启停控制：软锤 + GUI 电源按钮；暂停期间不取汽、不推进，批次参数保留。
- 一般结构失效：进度回退 `1 tick`，修复后续跑原批次。
- 无特殊清空关键部位；控制器被拆除仅损失偏好配方 ID 与待输出结果（物品掉落）。
- 区块卸载持久化续跑，不补算离线进度；新注册机器无旧存档迁移问题。

### 表现与信息（议题 9）

（用户 2026-09-07 确认）

- GUI/Jade 整体沿用粉碎机已实现骨架：主状态、配方与进度、实际并行与上限（`x / 8`）、蒸汽合计存量与容量、每刻需求、待输出摘要；服务端权威同步。
- 进度条与声效沿用类型自带样式（压缩进度条与压缩声效）；配方实际推进时在活塞位置叠加推压粒子。
- 控制器正面空闲/工作两态纹理走 `steamMultiblockModel` 的 `addTextureOverride` 模式。
- 两级物品提示（默认摘要 + Shift 完整说明）；文本优先复用既有资源，中英双语。

### 获取配方（议题 10）

（用户 2026-09-07 确认）

- 配方**含原版活塞 ×1 作为核心**（压缩推压语义；用户裁定以活塞替代蒸汽装配方块）；不含任何仓室；纯蒸汽时代材料。
- 固定有序工作台配方，每次恒产 `1` 个控制器，三档相同；配方 ID `gregsteamexpansion:shaped/steam_compressor`。图案已确认（2026-09-07 用户确认，C1b 同款骨架换核心）：

```text
P P P
P X P
P G P
```

| 符号 | 输入 | 数量 |
| --- | --- | ---: |
| `X` | 原版活塞（`minecraft:piston`，压缩推压核心，居中） | `1` |
| `G` | 青铜小齿轮（`gearSmall / Bronze`，底部传动） | `1` |
| `P` | 青铜板（`plate / Bronze`） | `7` |

- 图案沿用家族骨架（核心居中 + 底部传动 + 板包覆），与小型离心机/提取机配方同形、以中心物品区分；左右对称无需序列化器；九项材料恰好占满 `3×3`。
- 轻量口径延续：折算约 1 小齿轮 + 1 活塞 + 11 板，与 C1b 同为全模组最轻档控制器。

### 工作强度三档（议题 11）

（用户 2026-09-07 确认）

- 三档机器数值完全相同：并行、耗时、耗汽、产率、结构、接口、GUI/Jade 均不分档。
- 工作强度只通过结构方块合成成本自然生效；控制器配方三档恒产 `1`；档位切换对已成型机器无实际影响。

## 上游基准（已核对源码）

### 配方类型定义（`GTRecipeTypes.COMPRESSOR_RECIPES`）

| 字段 | 上游值 |
| --- | --- |
| 配方类型 ID | `gtceu:compressor` |
| 能量方向 | 输入（`ELECTRIC`，`IO.IN`） |
| 物品输入/输出槽 | 最多 `1 / 1` |
| 流体输入/输出槽 | `0 / 0` |
| 构建器默认值 | 默认 `200 tick`、`2 EU/t`（配方可覆盖） |
| 进度条 / 声效 | 压缩进度条 |

### 配方特点

- 压缩配方是通用“粉末/物品压块”工序：压块、雪块、木板类、各类材料致密化等，`MiscRecipeLoader`、`VanillaStandardRecipes` 等广泛生成。
- 纯干式类型，输入输出面为全类型最简（`1 / 1`）。

### 上游执行机器

| 机器 | 形态 | 与本机的关系 |
| --- | --- | --- |
| 压缩机（`COMPRESSOR`） | LV–UV 单方块电力机器 | 同类型越级对照 |
| 蒸汽压缩机（`STEAM_COMPRESSOR`） | 青铜低压 + 钢高压单方块蒸汽机器 | 规模化上位的直接对照物（保留不动） |
| GCYM 大型压缩类机器 | 电力多方块 | 电力对照物，分层共存 |

## 立项前提

1. **定位：规模化上位**（蒸汽压缩机已存在，A4/C0/C1b 模式）。
2. **与 C1b 成对**：蒸汽提取机 + 蒸汽压缩机同族小型配套双机，骨架、口径与轻量配方语言完全复用。
3. **纯干式类型**：无流体接口、无电路——仓室仅物品总线 + 供给。
4. **越级模式沿用**：压缩机属 LV 电力机器，越级使用、以蒸汽消耗为平衡代价。

**结构与成型**
