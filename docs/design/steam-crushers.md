# 蒸汽粉碎机与大型蒸汽粉碎机设计

本文档逐步记录 Greg Steam Expansion 的“蒸汽粉碎机”与“大型蒸汽粉碎机”多方块结构。正文只收录已经确认的设计；未决定内容保留在文末，不提前补全结构、接口或控制器配方。后续未决项先以建议方案讨论，只有用户明确同意后才移入已确认正文。

## 当前状态

- 状态：设计已定案，尚未实现。
- 两台机器为明确的上下位关系。
- 两台机器只执行[矿石粉碎配方](ore-crushing.md)。
- 控制器身份与配方、方块物理及交互属性、拆除与爆炸规则、双语物品提示、共同运行规则、控制器界面信息规范、控制器美术与工作反馈、两台机器的完整结构规则、结构预览与终端自动搭建代表布局、可选 AE2 兼容、配方迁移启用保护以及由用户亲自执行测试的验收边界均已确定。

## 控制器注册身份

- 两个资源 ID 分别表示可放置的多方块控制器及其对应方块物品，不为物品形态增加 `_item` 后缀。

### 共用机器基类

- 新增抽象基类 `AbstractSteamCrusherMachine`，由 `SteamCrusherMachine` 与 `LargeSteamCrusherMachine` 共同继承。
- 共用基类负责矿石粉碎配方批次、单配方并行、输入原子扣取、逐 tick 原子取汽、最坏情况输出预检、待输出持久化、工作控制、进度回退、区块重载和控制器拆除状态清理。
- 两个具体机器类分别提供结构图案、固定并行上限、合法接口集合、接口数量约束和是否要求蒸汽排气仓等机器专属规则。
- 共用基类不能默认要求排气仓、多个输出总线或多个蒸汽供给仓，避免把大型蒸汽粉碎机的结构资格泄漏给蒸汽粉碎机。
- 共用行为的修复应优先落在基类；只有确属单台机器差异的代码才能在具体类覆盖，且覆盖不得改变已经确认的共同产物、时间与单位配方耗汽语义。

### 蒸汽粉碎机控制器配方：已确认核心

- 控制器的有序合成配方必须消耗 `1` 台 GTCEu 高压蒸汽研磨机（`gtceu:hp_steam_macerator`）作为控制与传动核心。
- 高压蒸汽研磨机在合成时被永久装入并正常消耗；拆除或破坏控制器时只掉落控制器自身，不返还内部机器。
- 低压蒸汽研磨机、电力研磨机、普通研磨头、蒸汽碾磨方块或标签等价物不能替代该核心槽位。
- 配方不使用青铜构件（`gregsteamexpansion:bronze_component`）。
- 配方另行消耗 `2` 个 GTCEu 青铜转子（`rotor / Bronze`）和 `1` 个 GTCEu 钻石研磨头（`gtceu:diamond_grinding_head`）。
- 配方使用 `4` 块 GTCEu 青铜板（`plate / Bronze`）作为控制器外壳。
- 配方不使用扳手、锻造锤或其他工具位，也不加入占位材料来填满九宫格；已确认的八个材料输入占据八个槽位，保留一个空槽。
- 钻石研磨头在合成时被永久装入并正常消耗，不接受普通钻石、钻石板、研钵、砂轮、其他等级研磨头或标签等价物替代。
- 控制器使用以下有序工作台配方：

```text
P D P
R M R
P . P
```

| 符号 | 输入 |
| --- | --- |
| `P` ×4 | GTCEu 青铜板（`plate / Bronze`） |
| `D` ×1 | GTCEu 钻石研磨头（`gtceu:diamond_grinding_head`） |
| `R` ×2 | GTCEu 青铜转子（`rotor / Bronze`） |
| `M` ×1 | GTCEu 高压蒸汽研磨机（`gtceu:hp_steam_macerator`） |
| `.` | 空槽 |

- 配方固定将下方中央留空，不接受任意物品填入该位置。
- 配方资源 ID 为 `gregsteamexpansion:shaped/steam_crusher`。
- 配方在 Easy、Normal、Expert 下均固定产出 `1` 个蒸汽粉碎机控制器。它遵守[所有多方块控制器固定产量](difficulty.md#所有多方块控制器固定产量)，不读取非控制器方块的 `2 / 1 / 1` 通用产量。

### 大型蒸汽粉碎机控制器配方：已确认核心

- 大型蒸汽粉碎机控制器的合成配方必须消耗 `1` 个本模组蒸汽粉碎机控制器（`gregsteamexpansion:steam_crusher`）作为升级核心。
- 配方使用 `4` 块 GTCEu 钢双层板（`plateDouble / Steel`）作为大型控制器的加固外壳。
- 配方使用 `2` 个 GTCEu 黄铜齿轮（`gear / Brass`）、`1` 个 GTCEu 黄铜转子（`rotor / Brass`）和 `1` 个 GTCEu 钢圆锯锯片（`TagPrefix.toolHeadBuzzSaw`，`buzzSawBlade / Steel`）。
- 上述材料与下位控制器合计占据九个材料槽位；配方不需要工具位或额外占位材料。
- 蒸汽粉碎机控制器在合成时被永久装入并正常消耗；拆除或破坏大型控制器时只掉落大型控制器自身，不返还下位控制器。
- 高压蒸汽研磨机、其他多方块控制器、蒸汽碾磨方块或标签等价物不能替代该核心槽位。
- 大型控制器使用以下有序工作台配方：

```text
D G D
R S B
D G D
```

| 符号 | 输入 |
| --- | --- |
| `D` ×4 | GTCEu 钢双层板（`plateDouble / Steel`） |
| `G` ×2 | GTCEu 黄铜齿轮（`gear / Brass`） |
| `R` ×1 | GTCEu 黄铜转子（`rotor / Brass`） |
| `S` ×1 | 本模组蒸汽粉碎机控制器（`gregsteamexpansion:steam_crusher`） |
| `B` ×1 | GTCEu 钢圆锯锯片（`TagPrefix.toolHeadBuzzSaw`，`buzzSawBlade / Steel`） |

- 大型控制器配方不接受水平镜像：黄铜转子必须位于中层左侧，钢圆锯锯片必须位于中层右侧，交换二者位置不能合成。
- 如果 GTCEu 或 Minecraft 的普通有序配方注册方式默认接受水平镜像，实现必须改用能够强制精确方向的配方类型或匹配逻辑，不能因上游默认行为放宽本规则。
- 蒸汽粉碎机控制器配方同样不额外启用镜像匹配，但其材料排列本身左右对称，因此水平镜像与原图案完全相同，不存在可区分的第二种排列。
- 配方资源 ID 为 `gregsteamexpansion:shaped/large_steam_crusher`。
- 配方在 Easy、Normal、Expert 下均固定产出 `1` 个大型蒸汽粉碎机控制器，并遵守[所有多方块控制器固定产量](difficulty.md#所有多方块控制器固定产量)。

### 控制器方块行为与物理属性

- 两种控制器都使用完整方块碰撞箱和选择箱，不含水、不受重力影响、不可燃且不被流体冲毁；方块本身不提供物品、流体、蒸汽或 EU 存储能力，所有物流与供汽能力均来自已成型结构中的合法接口。
- 两种控制器统一使用硬度 `5.0`、爆炸抗性 `6.0` 和金属声音类型，不发光且不需要精准采集。注册时必须显式设置这些属性，不能意外继承为石质声音或其他默认机器方块数值。
- 正确工具为镐或 GTCEu 兼容扳手，并要求正确工具才能取得掉落。正常采集只掉落控制器自身，不返还配方中永久装入的高压蒸汽研磨机、下位控制器、研磨头、转子、齿轮或其他材料。
- 两种控制器都只允许四个水平方向，使用 GTCEu `RotationState.NON_Y_AXIS`；放置时正面朝向玩家，不能朝上或朝下。扳手只能在四个水平方向间旋转控制器，旋转后结构必须按新正面重新校验。
- 控制器不增加 `waterlogged`、原版 `powered`、并行档位或配方模式等方块状态。成型、工作、暂停和故障表现使用机器模型属性与服务端同步状态，不在运行中反复替换世界方块状态。
- 控制器正面固定用于专用覆盖纹理、玩家交互和结构朝向，禁止安装覆盖板；其余五面沿用 GTCEu 7.5.3 的标准覆盖板兼容与能力判定，不建立本模组专属覆盖板白名单。
- 兼容机器控制覆盖板可以安装在非正面并读写与 GUI 电源按钮、软锤相同的工作启用状态。物品、流体、能源及其他覆盖板不能让控制器获得其本身未提供的库存、储罐、EU 输入或结构接口能力。
- 覆盖板、染色和朝向属于已放置控制器的普通机器数据；控制器被正常采集后仍只生成不携带机器运行状态的普通控制器物品，具体状态清理继续服从“控制器拆除”规则。

## 上下位关系

- 蒸汽粉碎机与大型蒸汽粉碎机执行完全相同的矿石粉碎配方，输入资格、基础主产物、工作强度主产物倍率、概率副产物及其概率均由同一份配方决定。
- 大型蒸汽粉碎机作为上位机器，只通过更高并行数提高吞吐量；它不解锁额外配方，也不对单次配方应用机器专属产率倍率。
- 同一工作强度下，同一份输入按单次配方执行一次时，两台机器必须得到相同的主产物数量和相同的概率副产物规则。机器等级不能让主产物在矿石粉碎配方的 `2× / 1.5× / 1×` 工作强度倍率之外再次增产。

| 机器 | 并行上限 | 基础处理时间 |
| --- | ---: | ---: |
| 蒸汽粉碎机 | `8` | `600 tick` |
| 大型蒸汽粉碎机 | `64` | `600 tick` |

- 并行表示同一批次最多执行的配方次数。实际输入或输出空间不足时只能降低本批实际并行，不能为凑足并行上限而吞取不完整输入或丢弃产物。
- 两台机器的每个批次只能选择并重复执行同一张矿石粉碎配方。蒸汽粉碎机的 `8` 个并行位置和大型蒸汽粉碎机的 `64` 个并行位置都不能由不同矿石、粗矿或不同配方共同占用。
- 输入总线中同时存在多种可处理物品时，机器每批只选择其中一种配方；其余输入留在总线中等待后续批次，不能为了填满并行而混合加工。
- 配方搜索固定按唯一输入总线的槽位编号从小到大扫描，不使用 GTCEu 偶然遍历顺序，也不保存或轮换跨批次的轮询游标。
- 对每个槽位依次检查合法矿石粉碎配方、可用输入数量和最坏情况输出空间；数量不足以执行至少 `1` 次或连 `1` 并行的最坏情况输出都无法完整容纳时，跳过该槽位并继续扫描后续槽位。机器选择第一个当前能够启动的槽位及其配方，批次启动后再按既定规则锁定配方与实际并行。
- 两台机器启动批次前都必须按最坏情况模拟输出空间：必需主产物按当前工作强度下的完整数量计算，每一种概率副产物都按本次成功产生及其完整堆叠数量计算，并乘以候选并行数。
- 机器从结构并行上限与可用输入数量给出的候选值向下选择能够完整容纳最坏情况输出的最大实际并行数。输出检查不得假定某项概率副产物本批不会命中。
- 连 `1` 并行的最坏情况输出都无法完整插入时，机器不扣取输入、不消耗蒸汽、不启动批次，也不能通过截断主产物、删除副产物或掉落到世界来绕过检查。
- 批次启动前先完成配方选择、可用输入数量、并行上限与最坏情况输出空间检查，再确定本批实际并行。
- 机器以原子操作一次性扣取实际并行所需的全部输入；无法完整扣取时不移除任何物品，也不创建批次。
- 输入扣取成功时立即锁定配方 ID、输入来源、实际并行、处理时间、产物数量规则、总耗汽和每刻需求。运行过程中不再逐份消耗矿石，也不因输入总线内容变化而提高、降低或更换本批并行与配方。
- 配方完成时只进行一次概率判定并生成一次实际产物列表；该列表必须先持久化到控制器的待输出状态，再尝试写入输出总线。
- 若运行期间输出空间被外部物流或玩家占用，导致完成时无法容纳全部实际产物，机器进入“输出堵塞”并原样保留整份待输出列表。
- 输出堵塞期间不消耗蒸汽、不接取新配方，也不主动把可预测为无法完整接收的列表拆成部分产物插入。每次重试必须先模拟整份列表，只有所有物品都能完整接收时才按计划提交；ME 输出缓冲在模拟成功后违反结果的异常兜底单独服从“可选 AE2 与 ME 总线兼容”一节，不能借此把普通部分输出变成常规行为。
- 大型蒸汽粉碎机同时存在兼容 ME 输出总线与普通输出总线时，固定优先向 ME 输出总线模拟和写入，再由普通输出总线接收剩余产物。启动前最坏情况预检、完成时实际产物模拟以及最终提交必须使用相同的跨类型优先级。
- 同一类型存在多个大型机输出总线时，结构收集后按方块坐标形成稳定顺序并依次使用。区块或世界重载后必须从相同坐标集合得到相同顺序，不能依赖无序集合、注册顺序或偶然的遍历结果。
- 输出模拟必须生成包含目标总线和各自插入数量的完整分配计划；实际提交复用该计划，不能在模拟成功后重新排序或重新计算分配。正常完成提交时只有整份计划全部成功后才清空控制器待输出状态。
- 蒸汽粉碎机只有精确一个蒸汽物品输出总线，不需要跨输出类型排序。
- 区块卸载、世界重载、结构失效或重复输出尝试不能重新判定概率、改变产物数量、复制产物或丢弃待输出物品。
- 两台机器都使用矿石粉碎配方为蒸汽消费者规定的 `600 tick` 基础处理时间，不施加机器等级专属的加速或减速修饰。
- 相同配方在两台机器中的单次执行时间完全一致，上下位吞吐差异只来自 `8 / 64` 并行。

## 蒸汽消耗

- 两台机器都按 `2 mB GTCEu 标准蒸汽 = 1 EU` 换算矿石粉碎配方的 `1,200 EU` 蒸汽等效总能量，因此每次配方固定消耗 `2,400 mB` 蒸汽。
- 大型蒸汽粉碎机不提供单位配方蒸汽效率加成。
- 实际并行为 `P` 时，批次总耗汽为 `2,400 × P mB`；在固定 `600 tick` 内线性消耗时，每刻需求为 `4 × P mB/t`。
- 只有本 tick 的完整蒸汽需求能够取得时才能推进进度，不允许以较少供汽降低运行速度。
- 大型蒸汽粉碎机存在多个蒸汽供给仓时，结构收集后按方块坐标形成稳定取汽顺序，并以该顺序为本 tick 的完整需求生成跨仓分配计划。
- 只有全部供给仓合计能够满足本 tick 完整需求时才执行实际扣取；合计不足时不从任何仓扣取蒸汽。模拟成功后的提交必须复用同一来源顺序和分配量，不能重新排序或重新计算。
- 蒸汽粉碎机只有精确一个蒸汽供给仓，但同样先模拟完整需求再扣取，不能在供汽不足时部分消耗。
- 批次启动时不预扣、不冻结、也不在供给仓中预留完整 `600 tick` 所需的批次总蒸汽；输入原子扣取成功后，蒸汽仍按每个运行 tick 的需求实时取得。
- 外部管道、供给仓或网络中的蒸汽在批次运行期间可以被其他设备改变；机器不声称拥有尚未实际扣取的未来蒸汽。中途无法满足当刻需求时，立即执行既定的缺汽回退规则。
- 本 tick 无法取得完整蒸汽需求时，机器保留已经启动的批次及其锁定参数，并将当前进度直接回退至 `1 tick`；即使此前已经推进到更高进度，也不保留超出 `1 tick` 的部分。
- 蒸汽恢复后继续同一批次，不重新搜索配方、不重新扣取输入，也不改变已经锁定的实际并行、产物数量、处理时间或总耗汽。

### 工作控制与主动暂停

- 两台机器支持 GTCEu 标准工作控制：控制器界面的电源按钮、软锤操作和兼容机器控制覆盖板读写同一个工作启用状态。
- 新放置的两种控制器默认处于工作启用状态。结构成型后，只要存在合法输入、最坏情况输出检查通过并能取得本 tick 所需蒸汽，机器无需玩家再次开启即可自动接取并运行配方。
- 控制器不直接响应输入到方块上的原版红石信号；直接强充能或取消强充能都不会启用、暂停或重置机器。
- 红石自动启停只能通过兼容机器控制覆盖板实现；覆盖板、界面电源按钮和软锤操作必须读写同一个工作启用状态。
- 玩家或自动控制主动暂停时，机器不消耗蒸汽、不接取新配方，并冻结当前批次的原进度及全部锁定参数；主动暂停不会触发缺汽使用的进度回退至 `1 tick`。
- 重新启用后从暂停前的原进度继续同一批次，不重新搜索配方、不重新扣取输入，也不重新计算并行、产物或耗汽。

### 结构失效

- 控制器仍存在但其他固定结构方块、主体外壳或必需接口被破坏或移除时，机器进入结构失效状态，不消耗蒸汽、不推进配方，也不尝试输出尚未完成的批次。
- 结构失效时保留当前批次及其全部锁定参数，但将当前进度直接回退至 `1 tick`。
- 原控制器重新形成对应机器的合法结构后继续同一批次，不重新搜索配方、不重新扣取输入，也不重新计算并行、产物数量、处理时间或蒸汽消耗。
- 结构失效与主动暂停同时存在时仍执行结构失效的进度回退规则；主动暂停不能保护批次免于结构破坏造成的回退。

### 控制器拆除

- 控制器本身被破坏或拆除时，立即清除当前批次、进度、锁定参数、待输出产物和排气伤害计时；该状态不能通过控制器掉落物恢复。
- 已经由当前批次扣取的输入不返还，已经完成但仍处于输出堵塞状态的待输出物品也不掉落到世界或写入控制器物品。
- 控制器掉落物只保留普通控制器方块物品身份，不携带配方、物品、蒸汽、工作启用状态或其他机器运行数据。
- 重新放置原掉落物或另一个同类控制器后形成的是一台新机器，不恢复原机器的任何状态。
- 控制器被爆炸破坏时使用与正常拆除完全相同的机器状态清理入口；爆炸事件不能绕过批次、待输出物品或大型机排气伤害计时的清除。
- 爆炸掉落沿用 Minecraft / Forge 的普通方块爆炸战利品规则，本模组不保证控制器物品必定生成，也不额外补偿其合成材料。若本次爆炸生成控制器掉落，该物品仍服从上述无机器状态规则。
- 无论控制器物品是否在爆炸中幸存，内部高压蒸汽研磨机、下位蒸汽粉碎机控制器、钻石研磨头、转子、齿轮及其他配方材料都不单独掉落。

### 区块卸载与世界重载

- 控制器或机器所需区块未加载期间，两台机器都不推进配方、不消耗蒸汽、不搜索新配方、不尝试输出，也不按离线时间补算进度或产物。
- 控制器必须持久化工作启用状态、当前配方 ID、已扣输入对应的批次、实际并行、当前进度、处理时间、总耗汽、已耗汽、锁定产物参数、待输出物品和大型机排气伤害计时。
- 区块或世界重新加载后从保存的原进度和状态继续；重载不能触发缺汽或结构失效的 `1 tick` 回退，除非重新加载后实际检查发现对应故障。
- 已完成但输出堵塞的批次在重载后继续尝试输出原有待输出列表，不能重新判定概率或生成第二份产物。

### 维护与磨损

- 两台机器均不启用 GTCEu 维护机制，不需要维护仓，不产生维护问题，也不因缺少维护降低速度、并行、产率或蒸汽效率。
- 机器不产生随机机械故障、卡钻、转子损坏或其他概率停机事件。
- 结构中的蒸汽碾磨方块及其内部钻石研磨头没有运行耐久，不随加工次数磨损，也不需要现场更换、润滑或修复。
- 控制器配方中消耗的钻石研磨头、高压蒸汽研磨机、转子和其他部件同样不会在机器运行时作为可维护零件返还或替换。

## 控制器界面

- 蒸汽粉碎机与大型蒸汽粉碎机共用同一套控制器界面布局、组件位置、交互方式和状态语义。
- 界面根据控制器类型显示对应固定并行上限：蒸汽粉碎机显示 `8`，大型蒸汽粉碎机显示 `64`；当前批次实际并行另行显示，不能把上限误写成当前值。
- 大型机不因使用同一界面而增加额外配方模式、升级页或隐藏能力；两台机器始终只执行矿石粉碎配方。
- 两台控制器可以使用不同的外观底色、标题和机器图标，但不能因此改变界面布局或操作逻辑。
- 主界面固定显示当前配方与进度、当前实际并行与并行上限、全部蒸汽供给仓的合计存量与合计容量、当前每刻蒸汽需求，以及当前运行或故障状态。
- 蒸汽粉碎机的存量与容量来自唯一蒸汽供给仓；大型蒸汽粉碎机对结构内全部供给仓求和。合计显示不会让多个供给仓改变机器性能。
- 控制器状态按以下固定优先级选择唯一主状态；数字越小优先级越高：

| 优先级 | 主状态 | 适用机器 |
| ---: | --- | --- |
| 1 | 结构未成型 | 两台机器 |
| 2 | 蒸汽排气受阻 | 仅大型蒸汽粉碎机 |
| 3 | 输出堵塞 | 两台机器 |
| 4 | 主动暂停 | 两台机器 |
| 5 | 蒸汽不足 | 两台机器 |
| 6 | 运行中 | 两台机器 |
| 7 | 待机 / 无可用配方 | 两台机器 |

- 多个状态同时存在时，GUI、Jade/探针和控制器表现都使用同一个服务端权威状态源，并显示上表中优先级最高的一项；不同显示入口不能各自重新排序状态。
- 状态文字、按钮悬浮说明、结构错误、暂停、缺汽、输出受阻、运行和待机等提示，只要 GTCEu 已有语义完全一致的本地化键或标准组件，就优先直接复用上游内容，不在本模组命名空间复制一份近义文本。
- 只有 GTCEu 没有对应语义，或本机必须表达 `8 / 64` 并行、专用蒸汽供给仓、三格排气通道等特有信息时，才新增 `gregsteamexpansion` 本地化键。
- 实现时必须按目标版本 GTCEu 7.5.3 核验所复用键与组件的实际语义；不能仅因英文或中文字符串相似而复用含义不同的提示。

### 运行信息页布局与格式

- 控制器只使用一个可上下滚动的运行信息页，不拆分概览页与详细页，也不允许横向滚动。界面不提供内部物品槽或流体槽；矿石、产物和蒸汽仍只能通过已经成型的结构接口传递。
- 鼠标滚轮和可拖动的竖直滚动条均可控制页面位置；内容未超出可视区域时隐藏或禁用滚动条。
- 运行信息固定按以下顺序自上而下排列：当前主状态；当前配方与进度；本批实际并行与固定并行上限；蒸汽合计存量与合计容量；本批每刻蒸汽需求；待输出物品摘要。
- GTCEu 标准电源按钮固定在滚动区域之外，不随页面滚动。界面不增加配方模式、自动输出、产物销毁、蒸汽节流或并行手动限制控件。
- 不适用于当前状态的批次字段保留所在行并显示 `—`，避免批次开始、结束或恢复时其他信息行上下跳动。没有待输出物品时，“待输出”显示 `—`；没有已启动批次时，每刻蒸汽需求显示 `0 mB/t`。
- 当前配方行使用锁定输入物品的本地化显示名作为玩家可读名称，并在悬浮提示中显示完整配方资源 ID。待机且尚未锁定配方时，配方名与进度均显示 `—`。
- 进度显示一位小数百分比和精确 tick 数，格式为 `45.0%（270 / 600 tick）`。完成后尚未成功写出产物时固定显示 `100.0%（600 / 600 tick）`，不能因重试输出而回到 `0%`。
- 并行显示格式为 `本批实际并行 / 固定上限`，例如蒸汽粉碎机满并行为 `8 / 8`，大型蒸汽粉碎机部分并行为 `37 / 64`。没有已启动批次时，实际并行显示 `—`，上限仍显示对应机器的 `8` 或 `64`。
- 蒸汽显示结构内全部供给仓的 `合计存量 / 合计容量`，单位为 `mB`，数值使用千位分隔。结构未成型且当前无法取得合法供给仓集合时显示 `—`，不沿用上一次成型时的缓存容量冒充当前值。
- 已启动且尚未完成的批次始终显示其锁定每刻需求 `4 × P mB/t`。只有处于“运行中”且本 tick 已成功原子取汽时，该值表示当前实际消耗；主动暂停、蒸汽不足、排气受阻或结构未成型时仍显示锁定需求，并追加本地化说明“当前未消耗”。这几种状态不能改显为 `0 mB/t`，以免隐藏恢复运行所需的真实供汽能力。
- “输出堵塞”对应的批次已经完成，不再需要蒸汽，因此每刻需求显示 `0 mB/t`。待输出行显示 `物品总数（种类数种）`，例如 `128（3 种）`；悬浮该值时按控制器中持久化列表的稳定顺序完整列出每种物品的本地化名称与数量。
- 待输出列表只是只读显示，生成悬浮文本时不能重新判定副产物、重新合并产物或触发任何输出尝试。物品总数按所有堆叠数量求和，种类数按物品 ID 与组件数据完全相同的可合并物品计算。
- 主状态使用文字颜色区分：结构未成型、蒸汽排气受阻和输出堵塞为红色；主动暂停和蒸汽不足为黄色；运行中为绿色；待机 / 无可用配方为灰色。状态不能只靠颜色区分，始终同时显示完整本地化文字。
- 普通标签使用灰色，数值使用白色；蒸汽量、物品数和 tick 数使用千位分隔，百分比固定保留一位小数。所有单位只在数值后显示一次，不把单位写入可参与运算或同步的原始数值。

### Jade 信息与同步

- Jade 按以下固定顺序显示精简信息：当前主状态；当前配方与进度；本批实际并行 / 固定上限；蒸汽合计存量 / 合计容量；本批每刻蒸汽需求。仅在存在待输出物品时追加待输出物品总数与种类数，不在 Jade 面板展开完整物品列表。
- Jade 与控制器 GUI 使用同一个服务端权威状态快照、同一状态优先级和同一数值格式。客户端只负责本地化与绘制，不能自行扫描结构、读取相邻仓、推算并行或重新判断故障状态。

## 控制器模型、动画与声音

### 共用表现规则

- 两种控制器都使用固定的青铜蒸汽机械底壳，不读取 `machines.steelSteamMultiblocks` 将底壳替换为钢制外观。大型机的钢制加固只绘制在专用正面覆盖层中，不表示结构接受钢制外壳替换。
- 两种控制器都使用独立的 `16×16` 正面覆盖层；除正面外不绘制固定物品口、蒸汽口或排气口，避免暗示控制器自身具有这些能力。
- 控制器只有“静止”和“工作”两组视觉状态。只有机器在本 tick 成功取得完整蒸汽需求并实际推进配方时才使用工作状态；成型但待机、主动暂停、蒸汽不足、排气受阻、输出堵塞、结构未成型以及区块或世界卸载时都使用静止状态。
- 视觉状态由服务端同步的单一布尔工作属性驱动，只在取值变化时发送更新，不为动画的每一帧发送网络包，也不把工作状态写入永久世界方块状态。
- 两种控制器工作时都复用 GTCEu 7.5.3 的 `GTSoundEntries.MACERATOR` 循环研磨声，并服从 GTCEu 全局机器声音开关。声音的启停条件与工作纹理完全相同，客户端卸载控制器区块或移除控制器时必须立即停止对应循环声。
- 静止、主动暂停、缺汽、排气受阻、输出堵塞和结构失效都不播放研磨声。机器在供汽边缘反复成功与失败时允许声音随真实运行状态启停，不能在未取汽的 tick 继续伪装工作。
- 控制器、蒸汽碾磨方块、钻头和圆筒均不额外生成碎石、粉尘、烟雾或火花粒子。大型机既定的蒸汽排气仓云雾与排气声音保持独立，不能用控制器研磨反馈替代，也不能因关闭研磨声而取消排气危险。
- 自发光只改变贴图亮度，不产生实际方块光照，不增加动态光源，也不照亮相邻方块。所有非工作状态完全关闭自发光。
- 两种控制器的物品模型都引用各自静止方块模型，并固定展示正面覆盖层；物品模型不播放工作动画、不发光，也不显示排气粒子。

## 蒸汽粉碎机结构

### 尺寸与主体

- 蒸汽粉碎机采用固定 `3×3×3` 外接尺寸。
- 结构不允许伸缩、增加重复层或通过扩大结构提高并行。
- 主体外壳使用 GTCEu 青铜蒸汽机械方块（`gtceu:steam_machine_casing`）。
- 除固定核心位置外，其余 `21` 个位置全部采用同一种非固定候选规则，不再按正面、后面、顶面、底面或边角区分不同替换资格。
- 这 `21` 个位置只允许使用 GTCEu 青铜蒸汽机械方块、蒸汽物品输入总线、蒸汽物品输出总线和本模组蒸汽供给仓，不接受其他结构方块或机器接口。
- 蒸汽物品输入总线、蒸汽物品输出总线和蒸汽供给仓分别必须且只能安装 `1` 个，任意一种缺少或超过 `1` 个时结构都不能成型。
- 蒸汽粉碎机不需要且不接受蒸汽排气仓。蒸汽消耗不会生成需要由结构接口排出的冷凝水、废气流体或物品副产物。
- 除三种必需接口各 `1` 个外，其余 `18` 个非固定位置必须使用青铜蒸汽机械方块。因此完整结构固定包含 `18` 个青铜蒸汽机械方块，不使用“至少若干外壳”的浮动规则。

### 固定核心位置

- 结构固定使用 `4` 个[蒸汽碾磨方块](items-and-blocks.md#蒸汽碾磨方块)，分别位于上面、下面、左面和右面四个面的中心。
- “左、右”以控制器正面朝向为基准。前面与后面的中心不使用蒸汽碾磨方块。
- 蒸汽粉碎机控制器固定占据正面中心位置，并朝向结构外侧。
- 结构整体可以绕竖直轴旋转；旋转后控制器正面以及相对的左、右碾磨方块位置一同旋转。
- `3×3×3` 结构的正中心固定使用 GTCEu 青铜框架方块（`frameGt / Bronze`），不留空气。
- 青铜框架只表示内部承力与传动骨架，不提供额外并行、速度、产率或蒸汽效率。
- `4` 个蒸汽碾磨方块共同构成固定碾磨核心，不与 `8` 并行建立一方块对应一次并行的数量关系。
- 额外放置蒸汽碾磨方块不能提高并行，也不能满足其他结构位置。
- 后面中心与其他 `20` 个非固定位置使用完全相同的候选规则，不要求唯一指定方块，也不专门绑定任何接口或外壳。

## 大型蒸汽粉碎机结构

### 已确认的结构方向

- 不采用 `5×5×5` 结构。大型蒸汽粉碎机采用固定 `7×7×9` 外接尺寸：水平宽度与深度均为 `7` 格，垂直总高度为 `9` 格。
- 结构不允许伸缩、增加重复层或通过改变任一方向尺寸调整并行；`64` 并行不随实际方块数量动态变化。
- 结构不能直接使用容易让相邻机器共用整面方块的普通空心立方体外壳。
- 整体造型采用“圆筒主体 + 钻头端部”，不采用上下收窄、中部外扩的阶梯塔体。
- 圆筒和钻头共用一条竖直中心轴。钻头位于结构顶部，尖端朝下并钻入圆筒；圆筒位于钻头下方及其钻入方向上。
- 钻头固定占据连续 `5` 个高度层。以从上到下的顺序，其居中水平截面依次为 `5×5`、`3×3`、`3×3`、`1×1`、`1×1`，形成向下收窄的钻头轮廓。
- 圆筒占据结构底部连续 `6` 层，并与钻头最下方两个 `1×1` 层重叠。因此总体高度为 `5 + 6 - 2 = 9` 层。
- 圆筒顶部不封顶。圆筒最高一层只形成开放筒口，不能使用完整水平顶盖封闭内部；钻头从筒口中心向下伸入圆筒。
- 圆筒最底层完整填满 `7×7`，形成实心底座；第 2–6 层统一使用已确定的 `7×7` 空心圆环截面。
- 圆筒壁与底座位置默认使用 GTCEu 青铜蒸汽机械方块（`gtceu:steam_machine_casing`）；除下述固定控制器外，`W` 位置允许由本节确认的物品总线、蒸汽供给仓或蒸汽排气仓替换。
- 大型蒸汽粉碎机控制器固定在从下往上第 `3` 层的圆筒正面中心，并朝向结构外侧。这里的“中心”指正面圆筒壁在该层的水平中心，不是被中心轴占据的结构正中央。
- 控制器固定替换第 3 层正面圆环上的一个青铜蒸汽机械方块候选位置，不能移动到其他层、其他侧面、底座或钻头上。
- 与钻头共用同一竖直中心轴、但未被蒸汽碾磨方块占据的第 1–4 层中心位置，固定使用 GTCEu 青铜管道方块（`gtceu:bronze_pipe_casing`）。四个青铜管道方块与第 5–9 层的五个蒸汽碾磨方块组成连续九格中心轴。
- 四个青铜管道方块都是固定且不可替换的结构位置，不允许由控制器、仓、总线或普通青铜蒸汽机械方块代替。
- 钻头的 `5×5`、两个 `3×3` 和两个 `1×1` 截面均完整填满对应的居中方形区域，不使用空心截面。
- 钻头五层的正中心组成一条连续竖直中心柱，固定使用 `5` 个蒸汽碾磨方块。
- 钻头截面中除中心柱外的其他 `40` 个位置全部固定使用 GTCEu 青铜蒸汽机械方块（`gtceu:steam_machine_casing`）。
- 钻头的 `5` 个蒸汽碾磨方块与 `40` 个青铜蒸汽机械方块均不可由控制器、仓、总线或其他结构方块替换。
- 圆筒与钻头形成的不规则轮廓用于降低相邻机器共用完整平面结构方块的便利性。
- 大型蒸汽粉碎机不增加禁止共用结构方块的专用校验。结构方块和接口能否与其他多方块共用，继续沿用 GTCEu 7.5.3 的原有共用规则及相关全局设置。

- 剩余 `127` 个 `W` 位置统一允许使用青铜蒸汽机械方块、兼容物品输入总线、兼容物品输出总线、本模组蒸汽供给仓或蒸汽排气仓，不按底座、层数、方向或圆环位置设置不同的替换资格。
- 物品输入总线总数必须且只能为 `1` 个。该位置可以使用蒸汽时代物品输入总线、电力时代兼容物品输入总线，或安装 AE2 与对应 GTCEu 集成时可用的兼容 ME 物品输入总线；同时安装两种或更多输入总线不能成型。
- 物品输出总线总数至少为 `1` 个。普通、电力时代与兼容 ME 物品输出总线可以混合安装，全部计入同一个输出总线数量，并与蒸汽供给仓共同受下述合计上限约束。
- 蒸汽供给仓至少安装 `1` 个。多个供给仓可以共同提供实际已储存的 GTCEu 标准蒸汽，但不会提高或改变固定 `64` 并行、`600 tick` 处理时间、单位配方产物、`2,400 mB/次` 耗汽或任何工作强度规则；其数量与物品输出总线共同受下述合计上限约束。
- 圆筒的 `127` 个 `W` 位置中，至少 `110` 个必须使用青铜蒸汽机械方块，因此全部接口合计最多为 `17` 个。扣除必须且只能安装的 `1` 个物品输入总线和 `1` 个蒸汽排气仓后，若物品输出总线数为 `O`、蒸汽供给仓数为 `S`，则必须同时满足 `O >= 1`、`S >= 1` 和 `O + S <= 15`。`15` 是两类接口的合计上限，不是各自的独立上限。
- 上述最低 `110` 个青铜蒸汽机械方块只统计圆筒的 `W` 位置；钻头中固定的 `40` 个青铜蒸汽机械方块以及中心轴、控制器和蒸汽碾磨方块均不计入该数量。
- [蒸汽排气仓](large-heat-storage-steam-furnace.md#蒸汽排气仓注册与配方)必须且只能安装 `1` 个；缺少或安装多个时结构不能成型。
- 大型蒸汽粉碎机完整沿用通用蒸汽排气仓规则：从仓正面开始连续 `3` 格必须通过严格空气判定；任意一格阻塞时机器停止运行和消耗蒸汽，并冻结已启动批次的原进度而不回退至 `1 tick`；机器实际消耗蒸汽时每 `20 tick` 产生一次粒子与声音反馈，并以独立的 `200 tick` 周期对正前方第 `1` 格内的非创造、非旁观生物造成 `12` 点热伤害。
- 排气伤害周期按大型机累计“实际运行 tick”计时：只有机器成功取得本 tick 的完整蒸汽需求并推进配方时才加 `1`；待机、主动暂停、缺汽、排气受阻、输出堵塞、结构失效以及区块或世界卸载期间均冻结且不清零，也不按离线时间补算。
- 计时恢复后从原值继续，允许跨多个批次累计；累计达到 `200 tick` 时执行一次伤害判定并将本周期重新计时。该计时随控制器状态持久化，只有控制器本身被移除或破坏时才清除。
- 除上述物品输入/输出总线、蒸汽供给仓和蒸汽排气仓外，结构禁止其他所有接口，包括能源仓、维护仓、蒸汽进气室、配方流体输入/输出仓和任意未明确列出的结构能力部件。
- 电力时代总线和 ME 总线只提供物品物流能力，不能向机器输入 EU，也不能改变机器的纯蒸汽能源身份。
- 未安装 AE2 或对应集成时，只是不提供 ME 总线候选，不影响普通蒸汽或电力时代总线形成结构。
- 圆筒实际使用的青铜蒸汽机械方块数量允许在 `110–123` 个之间变化。使用最低接口数量时，`127` 个 `W` 中有 `1` 个输入总线、`1` 个输出总线、`1` 个蒸汽供给仓、`1` 个蒸汽排气仓和 `123` 个青铜蒸汽机械方块；使用最多 `17` 个接口时则保留 `110` 个青铜蒸汽机械方块。所有未被合法接口占据的 `W` 都必须使用青铜蒸汽机械方块；结构校验发现圆筒中的该方块少于 `110` 个时，即使各类接口分别满足最低数量，结构也不能成型。

## 可选 AE2 与 ME 总线兼容

### 加载与结构候选

- AE2 及其 GTCEu 集成始终是可选兼容，不成为本模组或两台粉碎机的必需前置。共用机器基类、普通结构图案、配方迁移和客户端基础资源不得直接引用 `appeng` 包中的类。
- ME 总线结构候选只能在 AE2 与对应 GTCEu 集成都实际可用时通过延迟或条件注册加入大型机图案；兼容不可用时不能触发类验证、静态初始化或缺类崩溃。
- AE2 未安装，或 AE2 已安装但对应 GTCEu 集成不可用时，大型机只移除 ME 输入与输出总线候选；普通蒸汽时代和正文允许的电力时代物品总线仍可正常成型，机器的纯蒸汽能源身份不变。
- 缺少兼容时，世界中无法解析、已经缺失或不再具有对应 GTCEu 结构能力的 ME 总线不能被当作普通总线替代。控制器按普通结构失效处理并显示结构未成型，不使用名称或方块 ID 猜测其能力。

### ME 输入

- 大型机仍必须且只能具有 `1` 个输入总线。选择 ME 输入总线后，配方搜索只读取该总线通过 GTCEu 暴露的物品输入能力，不绕过安全、频道、能源或网络在线状态直接访问 AE2 存储。
- ME 网络离线、无权限或无法提供输入时，未启动的机器视为没有可用输入并保持待机，不扣取蒸汽，也不改从结构中不存在的第二输入源搜索。
- 输入已经原子扣取并锁定批次后，ME 网络离线不取消该批次、不返还输入，也不改变并行、产物、时间或耗汽；批次继续只受实时供汽、结构和输出规则控制。

### ME 输出与内部缓冲

- 大型机只通过 GTCEu 7.5.3 ME 输出总线暴露的持久化内部输出缓冲写入产物，不从控制器直接调用 AE2 网络存储 API。产物完整进入该缓冲后即视为机器已经完成输出，由总线负责在网络可用时继续搬运。
- ME 网络离线本身不使完成批次进入输出堵塞。只要 ME 输出总线内部缓冲能够完整接收分配给它的产物，控制器就按既定计划提交；网络恢复后的转存行为沿用 GTCEu 总线实现。
- 启动前最坏情况预检、完成时实际产物模拟和提交都把 ME 总线内部缓冲视为目标，而不是把远端 AE 网络的瞬时剩余容量视为目标。不能在预检时检查网络、提交时却改写缓冲，或反向混用两种容量语义。
- ME 输出优先级保持不变：先按稳定坐标顺序模拟所有兼容 ME 输出总线，再把它们明确拒绝的剩余数量按稳定坐标顺序分配给普通输出总线。由于标准 ME 输出缓冲通常能够接收全部正常批次，存在可用 ME 输出总线时普通输出总线可能不会收到本批产物，这是优先级规则的预期结果。
- 模拟与提交在同一次服务端调用中连续执行，提交必须复用模拟生成的目标、物品键和数量，不能跨 tick 保存一个面向外部网络的过期容量结论。
- 若 ME 输出缓冲在模拟成功后异常返回剩余物，控制器立即停止本次计划的后续插入，按每个目标实际确认接收的数量从持久化待输出列表中精确扣除，并保留所有未接收数量后进入输出堵塞。已经进入 ME 缓冲的物品不得重新加入待输出列表，未接收物品也不得丢弃、改投普通总线或重新判定概率。
- 上述异常兜底允许保留一次已经发生且无法安全回滚的部分接收，只用于防止第三方能力违反模拟结果时复制或删除产物；正常路径仍必须先证明整份列表可接收，不能故意用该兜底实现分批输出。异常必须记录控制器坐标、总线坐标、物品键、计划数量、实际接收数量和剩余数量。
- ME 总线自身被拆除、破坏或跨版本迁移时，其内部缓冲如何保存或掉落沿用 GTCEu 的部件规则；控制器不得复制一份已经成功提交给总线的产物作为额外保险。

## 配方迁移启用保护

- 矿石粉碎配方迁移使用显式消费者登记表，不扫描机器显示名称、Java 类名或资源 ID 字符串来猜测消费者。蒸汽粉碎机注册时必须向该表登记机器定义 ID、控制器方块与物品、正常获取配方 ID 和精确配方类型。
- 自动移除 GTCEu 研磨机中的目标配方前，必须在本次数据加载候选集合中同时确认以下条件：
  1. `gregsteamexpansion:steam_crusher` 机器定义已经成功注册，且其实际机器类为 `SteamCrusherMachine`；
  2. 同 ID 的控制器方块与方块物品均可从注册表取得，创建出的控制器物品堆不为空；
  3. 机器明确声明能够执行 `gregsteamexpansion:ore_crushing`，而不是通过普通研磨机配方类型或名称相似间接匹配；
  4. `gregsteamexpansion:shaped/steam_crusher` 获取配方存在、输出精确 `1` 个蒸汽粉碎机控制器，并且配方未被配置或数据包条件禁用；
  5. 本次加载能够生成至少 `1` 张通过完整语义校验的矿石粉碎配方。
- 大型蒸汽粉碎机单独存在不能满足消费者检查，因为它的控制器获取配方永久依赖下位蒸汽粉碎机控制器；只有大型机注册成功时仍必须保留原研磨机路线。
- 任一条件失败时，本次数据加载不迁移任何目标配方、不从研磨机类型移除任何原路线，也不向配方查看器发布空的矿石粉碎类别。服务端只记录一次汇总错误，并逐项列出缺失或无效条件。
- 消费者检查通过后，迁移动作仍服从[矿石粉碎配方](ore-crushing.md#从研磨机迁移)的全量事务规则；目标 ID 冲突、字段复制失败、移除计数不一致或中途出现异常时整体回滚本次迁移，不能留下新旧集合各缺一部分的状态。
- 数据重载每次都重新验证消费者与本次原始配方集合，不能复用上次成功结果。某次重载因数据包移除控制器获取配方而验证失败时，该次加载必须恢复并保留原研磨机路线。
- 该保护只决定是否安全迁移配方，不改变控制器的注册、合成产量、结构、并行、耗汽或工作强度规则。

## 设计结论

- 蒸汽粉碎机与大型蒸汽粉碎机当前没有剩余的未决设计项。
- 本文档进入“设计已定案、尚未实现”状态；后续只有用户明确提出的新需求、实现过程中发现的上游硬约束或经用户批准的设计变更才能修改已确认规则。
- 实现不得以便利性为由自行改变结构、接口数量、配方选择、并行、耗时、耗汽、输出优先级、状态恢复、玩家提示、模型反馈、自动搭建、兼容降级或迁移保护语义。
