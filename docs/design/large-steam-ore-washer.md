### 已确认配方执行细节（议题 3）

（用户 2026-09-06 确认）

- 全配方开放：`gtceu:ore_washer` 类型的全部五条上游配方族（标准水洗、省水快速、蒸馏水洗、含杂矿粉洗涤、纯净矿粉洗涤）均可用，不排除任何一条，也不做配方子集限制。
- 编程电路仅通过 GTCEu 的仓室提供：电路作为普通配方输入经 GTCEu 输入总线进入并逐批扣取，不新增专用电路仓，也不提供免电路语义或封面等其他供给渠道；蒸馏水路线本就无电路输入，自然可用。
- 物品输入与流体输入的仓室约束（2026-09-06 用户更正，取代同日“两者不可同时使用蒸汽仓室”的初步口径）：物品输入可使用所有输入总线——GTCEu 蒸汽时代物品输入总线与各电压等级物品输入总线均可，不按能源形态限制，编程电路随所用物品输入总线进入；流体输入不可使用蒸汽仓室——包括本模组蒸汽流体输入仓，水的进入使用 GTCEu 标准流体输入仓。该约束意味着本机不消化“蒸汽流体输入仓”孤儿资产，议题 4 的接口方案已据此调整。
- 流体直接兼容：水与蒸馏水按配方自身声明原样兼容，机器不另设流体白名单、过滤或转换。
- 外部配方自动可用：其他模组或数据包成功注册到 `gtceu:ore_washer` 类型的合法配方自动可被本机执行，不按命名空间设置白名单或黑名单。
- 基准数值不修改：本机不修改上游配方的单份输入、产物数量、概率与配方记录的基准 `EU/t`、耗时；越级平衡只通过机器侧的蒸汽消耗实现，具体倍率与换算由议题 5 定案。

### 已确认动力与蒸汽消耗（议题 5）

（用户 2026-09-06 确认）

- 能源形态：仅接受 GTCEu 标准蒸汽，不消耗 EU，不设置能源仓；蒸汽供给仓要求见议题 4。
- 蒸汽换算率固定为 `2 mB 标准蒸汽 = 1 EU`，与蒸汽粉碎机、大型蒸汽粉碎机一致。
- 执行时长为配方基准耗时乘固定倍率 `1.5×`，即 `max(1, ceil(基准耗时 × 1.5))` tick：

| 配方族 | 基准耗时 | 执行耗时 | 单份等效总能量 | 单份总耗汽 | 并行 `P` 时每刻需求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 标准水洗 | `400 tick` | `600 tick` | `9,600 EU` | `19,200 mB` | `32 × P mB/t` |
| 蒸馏水洗 | `200 tick` | `300 tick` | `4,800 EU` | `9,600 mB` | `32 × P mB/t` |
| 省水快速 / 粉尘洗涤 | `8 tick` | `12 tick` | `48 EU` | `96 mB` | `8 × P mB/t` |

- 断供蒸汽：进度回退至 `1 tick`（标准蒸汽机行为，同粉碎机缺汽口径）；恢复供汽后从 `1 tick` 继续原批次，不重新搜索配方、不重新扣取输入、不重新计算产物。缺汽期间不推进进度、不消耗蒸汽。
- 排气受阻沿用通用蒸汽排气仓规则：停止取汽并冻结原进度，不执行缺汽的 `1 tick` 回退（与缺汽行为明确区分）。
- 多个蒸汽供给仓不提高并行或效率；每仓 `1,200 mB/t` 的机器侧供汽上限沿用既有规格。
- 上述换算率、单份耗汽与并行线性关系在 Easy、Normal、Expert 三档一致；三档受控字段细则由议题 11 定案。

### 已确认并行与吞吐（议题 6）

（用户 2026-09-06 确认）

- 最大并行固定为 `64`，与大型蒸汽粉碎机同级；不由接口数量、仓室数量、连续运行时间或环境条件动态计算。
- 实际并行按 `min(64, 可用输入份数, 最坏情况输出可容纳份数)` 计算；可用输入份数按配方全部输入项（粉碎矿、编程电路与水）的完整份数共同限制，概率输出按能够全部命中的最坏情况预留输出空间。
- 公式结果小于 `1` 时不开工、不扣取任何输入；结果为 `1–64` 时一次性锁定该批次实际并行，批次开始后不因库存变化提高、降低或更换。
- 耗时不随并行倍增：一批 `P` 份使用与单份相同的执行时长（标准 `600 tick`、蒸馏水 `300 tick`、快速/粉尘 `12 tick`）；批次总耗汽与每刻需求按 `P` 线性放大。
- 满并行核算（推导值）：`64` 并行标准水洗每刻需求 `2,048 mB/t`、单批总耗汽 `1,228,800 mB`、单批进水 `64,000 mB`；由于每仓 `1,200 mB/t` 供汽上限，满并行标准水洗至少需要 `2` 个蒸汽供给仓才能满足每刻需求。
- 配方选择沿用大型焦炉确认的“最近成功配方优先”：尚未保存偏好时，按输入槽编号从小到大扫描，由最小编号且能组成完整合法配方的输入槽决定首个候选配方（编程电路配置是配方组成的一部分）；同一输入匹配多条配方时按资源 ID 字典序取最前。首个批次成功开工后保存偏好配方资源 ID 并持久化，后续批次先尝试偏好配方；偏好配方缺少完整输入时重新扫描，偏好配方具有完整输入但输出不足时等待输出而不改选。

### 已确认内部库存与批处理原子性（议题 7）

（用户 2026-09-06 确认）

- 控制器缓存与粉碎机一致，仅为待输出（2026-09-06 用户修订，取代同日“控制器内无缓存”的初步表述）：控制器不设常规内部物品输入/输出槽与内部水罐，全部物品与流体库存由对应仓室直接承载；控制器内部唯一持有的库存是异常兜底的待输出结果，处理方式与蒸汽粉碎机、大型蒸汽粉碎机一致。
- 开工预检直接在仓室上执行：跨全部已安装物品输入总线聚合检查配方输入（粉碎矿与编程电路）的完整份数，跨全部流体输入仓检查水的份数，并按最坏情况跨全部物品输出总线检查输出容纳能力；任一不足则不开工、不扣取。
- 原子扣取：预检通过后以一次原子操作从输入总线与流体输入仓扣取本批次全部输入（含电路与水）；无法完整扣取时不移除任何物品或流体，也不创建批次。蒸汽仍随进度逐刻消耗（议题 5）。
- 产物提交：批次完成时按锁定的产物参数一次性写入物品输出总线，允许跨总线与槽位拆分堆叠；输出总线只能被外部提取、不能被外部插入，预检预留的输出空间不会因外部操作变小。
- 待输出保险沿用：异常导致结果无法整体写入时，完整结果作为“待输出”状态持久化于控制器，期间停止开始新批次，空间恢复后整体重试、不重复计算概率；该状态是异常兜底，不属于常规缓存。
- 满并行进水核算（推导值）：`64` 并行标准水洗单批进水 `64,000 mB`；按 GTCEu 标准流体输入仓默认容量（每仓 `16,000 mB`）计，满并行标准水洗需要至少 `4` 个流体输入仓（或引入更大容量仓室）方可一次扣足，此为不设内部水罐的直接后果。

### 已确认运行控制与失效（议题 8）

（用户 2026-09-06 确认）

- 启停控制：采用标准 GTCEu 启停控制（同大型焦炉 2026-09-06 变更后口径）——软锤切换“允许工作”状态，控制器 GUI 提供电源按钮；主动暂停期间不取汽、不推进进度，已锁定批次参数与进度保留。
- 一般结构失效：任一必要结构方块（外壳、搅拌方块十字、排气仓或仓室）被破坏或替换为不合法方块时，机器停止推进与取汽，进行中批次进度回退至 `1 tick`；结构重新合法后从 `1 tick` 继续原批次，不重新搜索配方、不重新扣取输入、不重新计算产物。
- 无特殊清空关键部位：本机不设类似焦炉底层中心砖的特殊清空位置。控制器被拆除时，因控制器缓存仅为待输出（议题 7），损失的仅有偏好配方 ID 与可能存在的待输出结果——待输出物品以物品实体掉落，无内部流体可丢失，不生成额外清算事件。
- 区块卸载与世界重载：不按离线时长补算进度；卸载前持久化工作启用状态、偏好配方 ID、锁定批次参数、当前进度与待输出结果，正常重载且结构合法时从保存进度继续原批次。
- 旧存档迁移：本机为新注册机器，不存在旧存档进行中批次的迁移问题。

- [ ] `11×11×6` 结构按确认图案成型：棱部 `96` 格（95 工业蒸汽机械方块 + 正面底棱中央控制器）、顶面玻璃 81、墙体与底面蒸汽机械方块 225、搅拌方块十字 17（第 2 层中央行 + 中央列）。
- [ ] 顶面玻璃位置接受任意种类的玻璃；棱与玻璃位置不被仓室替换；仓室仅占用墙体/底面蒸汽机械方块位置。
- [ ] 蒸汽排气仓缺省、多余或正面 `3` 格空气受阻时，结构不成型或按既定规则停止排气。
- [ ] 四个水平朝向均可成型；结构不可旋转至朝上/朝下。
- [ ] 控制器位于正面底层水平中心（正面底棱中央，两侧各 5 个工业方块）。
- [ ] 结构可共用：两座洗矿厂可贴靠建造、共用相邻墙体并各自成型；共用方块的结构之一失效不影响另一座；与粉碎机、焦炉等结构共用外壳方块不阻止成型。

**配方与仓室**

- [ ] 五条上游洗矿配方族（标准水洗、省水快速、蒸馏水、含杂矿粉、纯净矿粉）全部可执行；外部模组加入 `gtceu:ore_washer` 的配方自动可用。
- [ ] 编程电路随物品输入总线进入并逐批扣取；水仅经 GTCEu 标准流体输入仓进入，蒸汽流体输入/输出仓不可参与结构。
- [ ] 物品输入总线不限蒸汽/电力时代，均可驱动配方。

**动力与并行**

- [ ] 标准水洗 600 tick / 19,200 mB，蒸馏水洗 300 tick / 9,600 mB，快速与粉尘洗涤 12 tick / 96 mB；换算率 2 mB = 1 EU。
- [ ] 断汽时进度回退至 `1 tick`，恢复后续跑原批次；排气受阻时冻结进度（区分于缺汽回退）。
- [ ] 实际并行符合 `min(64, 输入份数, 输出容纳份数)`；耗时不随并行倍增；满并行标准水洗需 ≥2 个蒸汽供给仓、≥4 个流体输入仓方可满速。
- [ ] 配方选择遵循“最近成功配方优先”，偏好配方跨重载保持。

**库存与控制**

- [ ] 控制器无内部物品槽与水罐，唯一内部持有为待输出结果；待输出状态跨重载保留并在空间恢复后整体提交。
- [ ] 软锤与 GUI 电源按钮可正确启停；暂停期间不取汽、不推进。
- [ ] 一般结构失效回退 `1 tick` 后续跑；控制器拆除仅损失偏好配方与待输出（物品掉落），无重复掉落。

**表现与获取**

- [ ] GUI/Jade 信息与粉碎机骨架一致（并行显示 `x / 64`、每刻需求、待输出悬浮清单），BATH 进度条与声效正确；搅拌方块位置出现水花/翻滚粒子，方块本体无动画。
- [ ] 控制器按确认九宫格配方合成，恒产 1 个；中英文本地化完整。
- [ ] Easy / Normal / Expert 三档机器行为完全一致。
