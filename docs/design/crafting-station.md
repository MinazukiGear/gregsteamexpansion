# 合成站设计

本文档记录 Greg Steam Expansion 的合成站设计。合成站是本模组新增的一种工作台上位替代，不属于 GTCEu 机器体系，不消耗任何能量，也不执行机器配方；它的完整规格只在本文档维护，[杂项设计](miscellaneous.md) 只保留索引。

本文档已定案：全部规则由用户确认，可直接进入实现。各小节保留的“已排除备选”仅记录取舍理由，不是可选项；实现期待核验项集中在 7.2 与 7.3。

## 设计输入（已确认）

以下四项能力是合成站的既定设计输入，不因后续讨论改变：

- 合成站具有读取周围容器的能力。
- 合成站可以将物品保存在自身格子中，玩家取消交互或关闭界面时不会清空其中物品。
- 合成站可以使用锯子单向转化为竖半砖形态；该形态能够附着在任意箱子类容器或可放置的背包上，并读取所附着容器中的物品。
- 合成站自身具有 `9` 个工具槽位，用于放置来自各模组的工具。

## 初步方向（沿用既有讨论，已在正文具体化）

以下方向来自杂项设计中的初步建议，已由正文各节具体化；若与正文冲突，以正文为准：

- 把合成站定位为增强手动合成体验的工作台，而不是默认具备红石自动合成、批量配方队列或物流搬运能力的自动化机器。
- 自身合成格和工具槽由方块实体持久化；关闭界面、区块卸载和世界重载都不能清空内容。拆除、爆炸和形态转换时采用不丢失、不复制的统一规则。
- 读取外部容器时只把物品作为合成候选，合成站不主动搬入、不自动排序或整理外部容器；玩家在界面中的手动存取范围由 6.1 定义。一次合成先生成完整扣取计划，再同时结算自身格子、外部容器和工具耐久，避免发生部分扣取。
- 普通形态与竖半砖形态共用合成和工具逻辑；差异只放在外形、放置方式和可读取容器范围。竖半砖形态只读取其明确附着的单个容器。
- `9` 个工具槽与普通原料格分离。工具兼容优先服从配方声明、物品标签和标准容器剩余物或耐久语义，不按模组名称维护无限扩张的硬编码工具清单。
- 界面明确区分持久化合成格、工具槽、外部可用物品和合成结果。

## 第 1 步：定位与范围

### 1.1 身份与命名（已确认）

注册模型为双注册；显示命名保持“合成站”系列，仅为竖半砖形态分配独立 key：

| 对象 | 设计 |
| --- | --- |
| 合成站（普通形态） | 资源 ID `gregsteamexpansion:crafting_station`，注册字段 `CRAFTING_STATION`，中文名 合成站，英文名 Crafting Station |
| 合成站竖半砖 | 资源 ID `gregsteamexpansion:crafting_station_slab`，注册字段 `CRAFTING_STATION_SLAB`，中文名 合成站竖半砖，英文名 Crafting Station Slab |
| 方块实体 | 两个方块共用同一个方块实体类型，库存与合成语义完全一致 |
| 类型 | 本模组自有的含方块实体功能方块，不属于 GTCEu 机器电压体系 |

- 竖半砖物品只通过转换配方获得（5.1），不携带任何库存数据，最大堆叠 `64`；破坏竖半砖方块掉落完整合成站物品与内容物（5.4），因此竖半砖物品不会与库存数据同时存在。
- 两个方块都不计入 `items-and-blocks.md` 现有的“无方块实体普通方块”统计；归属已在物品与方块总览中单独记录。

### 1.2 基础合成能力（已确认）

- 合成站完整替代原版工作台：支持全部原版 `3×3` 有序与无序配方，并原生支持 GTCEu 在工作台配方中声明的工具位（锻造锤、扳手、剪线钳等，不消耗工具本体、只扣耐久）。
- 合成站与原版工作台在配方匹配结果上完全一致：原版工作台能做的它都能做，原版工作台不能做的它也不能做；外部容器供给与工具槽只是结算来源差异，不扩大配方范围。
- 已排除备选：只支持部分配方、无工具位配方回退原版工作台。理由：会造成两类工作台并存的割裂体验，削弱上位替代定位。

### 1.3 与上游同类内容的关系（已确认）

- 已核验 GTCEu 7.5.3 源码：未注册任何工作台类方块、机器或封面（`crafting_table` 只剩未注册的遗留纹理资产），不存在可复用的上游“合成站”。
- 合成站完全由本模组自建注册，不因上游遗留纹理而复用其 ID 或资源。
- 后续升级 GTCEu 版本时若上游新增同类内容，需重新回到本节评估关系，不自动迁移。

### 1.4 自动化边界（已确认）

合成站是纯手动内容，不暴露任何自动化接口：

- 不暴露 Forge 物品能力，漏斗、管道、机械臂等任何自动化设备不能放入、取出或查看其库存。
- 不支持红石信号触发合成、批量配方队列、自动输出或合成结果缓存。
- 不提供合成速度、产量或能耗方面的任何加成；合成站不消耗 EU、蒸汽或燃料。
- EMI/JEI 的配方填充与转移、界面内玩家手动操作（含 6.1 的外部区存取）都属于手动辅助，不属于自动化，允许存在。

已排除备选：允许漏斗、管道存取的半自动方案与内置红石自动合成。理由：与增强手动合成的定位冲突，且会引入外部自动化与多来源原子扣取之间的并发冲突面。

### 1.5 科技阶段与获取时机（已确认）

- 合成站定位为蒸汽时代中期内容：获取配方以 GTCEu 材料为基础（青铜板、青铜杆等），不使用电路、马达或其他电力时代产物。
- 玩家在取得对应 GT 材料前继续使用原版工作台，这是本定位的已知代价；最终配方只需青铜板与青铜杆（见 7.1），过渡期有限。

### 1.6 等级系列（已确认）

- 只有单一等级的合成站：`9` 个工具槽、读取规则与全部能力固定，不随材料或电压变化。
- 已排除备选：按材料或电压分级的多档合成站。理由：设计输入固定 `9` 个工具槽，单一等级最贴合“一个工作台上位”的简单定位；规模需求通过外部容器满足。未来确有需要再另行设计，不在此承诺。

### 1.7 使用权限与单人占用（已确认）

- 不内置每玩家或每方块的所有权权限：任何能接触方块的玩家都可以使用合成站。
- 同一时刻只允许一名玩家打开同一台合成站的界面（普通形态与竖半砖形态一致）：已有玩家打开时，其他玩家的打开请求被拒绝，界面不打开。
- 占用在界面关闭时立即释放；主动关闭、距离过远、方块被破坏或玩家断线都会关闭界面并释放占用。
- 拒绝打开时在动作栏显示一条简短提示：`合成站正在使用中`（英文 `Crafting Station is in use`）；这是打开拦截反馈，不属于 6.2 排除的界面状态显示。
- 已排除备选：多玩家同时打开。理由：消除并发操作的全部冲突面，结算原子性因此天然成立（见 4.5）。

## 第 2 步：自身库存与持久化

### 2.1 槽位构成（已确认）

合成站共 `19` 个自身槽位：`9` 个合成格 + `1` 个结果位 + `9` 个工具槽。

- 不设额外的缓存原料槽；“材料仓库”职责由外部容器承担。
- 已排除备选：增加 `9`–`27` 格缓存槽。理由：与外部容器读取的语义重叠；未来确有需要再另行设计。

### 2.2 结果位与取物方式（已确认）

- 结果位只做合成结果预览，不持久化存储；界面关闭时结果位不保留任何物品，不生成掉落物。
- 单击结果位：完成一次合成，产物进入光标或玩家背包。
- Shift 单击结果位：连续合成，直到原料耗尽、背包已满或工具耐久不足（细则见 4.4）。

### 2.3 持久化、拆除与爆炸（已确认）

- 合成格与工具槽内容由方块实体持久化：关闭界面、取消交互、区块卸载、世界重载均不清空。
- 结果位不持久化；未取走的预览在界面关闭时消失，不生成掉落物。
- 玩家挖掘、爆炸与非玩家破坏一律掉落完整合成站物品加全部格子与工具槽内容物；竖半砖形态同样掉落完整合成站物品（见 5.4）。
- 已排除备选：内容物写入物品 NBT 随物品保存。理由：原版容器语义规则统一，天然满足“不丢失、不复制”；物品 NBT 方案与最大堆叠 `64` 的物品语义冲突且存档成本高。

### 2.4 方块物理属性（已确认）

| 属性 | 设计值 |
| --- | --- |
| 硬度 | `2.5`（与原版工作台一致） |
| 爆炸抗性 | `2.5` |
| 声音类型 | 木质 |
| 挖掘工具 | 斧类加速；不要求工具，徒手可挖掘并掉落 |
| 掉落 | 掉落自身与全部内容物（见 2.3） |
| 活塞 | 不可推动（方块实体方块的通用规则，两形态一致） |

- 两种形态使用同一套物理属性；竖半砖形态的碰撞箱见 5.2。
- 可燃性沿用木质方块惯例，具体标签在实现时与原版工作台对齐。

## 第 3 步：外部容器读取边界

### 3.1 普通形态的读取范围（已确认）

- 普通形态只读取东西南北四个水平方向上直接相邻的 `4` 个位置；不读取上方、下方、斜角或更远的位置。
- 合成站自身不在读取范围内；四个位置彼此独立，不要求连续排布。
- 读取是实时的：打开界面、模拟合成与实际结算时都重新扫描，不缓存跨 tick 的容器内容。
- 不读取玩家物品栏、饰品栏、末影箱或任何非方块实体来源；玩家背包与合成站之间只有界面内的手动移动。
- 已排除备选：仅 `6` 面相邻、`3×3×3` 与 `5×5×5` 区域。理由：读取范围必须可控且方向无歧义，最终决定把范围严格限制在与合成站同一水平层的四个方向。

### 3.2 外部来源资格（已确认）

- 暴露 Forge 标准物品能力（`IItemHandler`）的方块实体即合法外部来源；不按模组维护白名单。
- 该判定天然覆盖原版箱子、木桶、潜影盒、GT 木桶、抽屉以及放置形态的各类背包模组（含精妙背包与精妙存储）。
- 加工类容器不属于存储，即使暴露物品能力也不作为外部来源与附着目标：原版熔炉、高炉、烟熏炉（`AbstractFurnaceBlockEntity`）、酿造台、漏斗、发射器与投掷器，以及 GTCEu 机器（`MetaMachineBlockEntity`，含蒸汽烤炉、蒸汽碾磨机等）。这些槽位具有输入/燃料/产物等角色语义，合成站不得读取、补料、归位或通过终端存取；按方块实体类判定可一并覆盖继承这些类的第三方加工容器。
- GT 板条箱是唯一的 GT 机器例外（`CrateMachine`，各级板条箱为真正的物品存储），照常可被读取与附着；GT 木桶（流体桶）没有物品格，在槽位检查处自然被跳过。
- 合成站不主动搬入、不排序、不整理外部容器；除合成扣取与玩家在界面中的手动存取（见 6.1）外，不修改外部容器。
- 末影箱没有方块实体物品能力，天然不会被读取；上面未列出的其他模组合成中间缓存类容器如发现被误读，逐案加入排除判定。
- 已排除备选：容器白名单。理由：白名单无法穷举第三方内容，能力判定天然兼容且不随模组增减失效。

### 3.3 竖半砖附着规则（已确认：仅侧面）

- 竖半砖形态只能附着在合法容器（资格同 3.2）的四个水平侧面；顶面与底面不可附着。
- 附着目标唯一且显式：与竖半砖背面紧邻的容器方块；附着关系在放置时确定，并写入方块实体。
- 只读取附着目标这一个容器，不执行普通形态的四面扫描；这是普通形态与竖半砖形态在读取规则上的唯一差异（既有方向）。
- 同一容器的同一侧面或不同侧面均允许附着任意数量的竖半砖，不设上限；每个竖半砖独立读取该容器。
- 目标失效：附着目标被挖掘、爆炸或替换为非容器时，竖半砖在同一游戏刻破坏并掉落完整合成站物品与内容物（5.4），不悬空残留、不丢失内容。
- 附着目标内部物品变化实时可见。

### 3.4 外部容器数量与扣取顺序（已确认：最多 1 个容器，东、西、北、南优先）

- 普通形态最多读取 `1` 个合法外部容器；多个合法容器相邻时，按固定世界方向顺序取第一个合法容器作为唯一来源：东 > 西 > 北 > 南。
- 该顺序是世界坐标的固定方向顺序，不依赖玩家朝向；同一位置的读取目标对所有玩家一致。
- 外部区仍然显示当前读取容器的方位（东、西、北、南之一，见 6.1）；这是来源标注，不属于 6.2 排除的状态提示。
- 唯一容器不可访问（如被保护模组拦截）时按空来源处理，不显示额外提示（随 6.2）；合成格内的材料仍然可以独立完成合成。
- 竖半砖形态同样只读取 `1` 个容器（其附着目标）；两种形态在来源数量上保持一致。
- 已排除备选：多容器同时扣取、`3×3×3` 或更大范围扫描。理由：单一来源让“哪些材料会被扣取”始终一目了然，也彻底消除多来源扣取顺序问题。

### 3.5 权限与保护模组（已确认）

- 首版不内置权限系统：没有分组、认领或每玩家开关。
- 打开合成站 GUI 本身的保护（如领地插件拦截交互）自然生效，合成站不绕过。
- 外部容器读取与手动存取在能力层面的保护行为取决于保护模组实现；把主流保护模组下“不可访问容器被当作空来源且不可存取”列入 7.2 验收清单，不在规格中硬编码任何保护模组。

## 第 4 步：合成与工具结算

### 4.1 配方图案模型（已确认）

已确认采用「格内消耗 + 外部补足 + 图案维持」，维持目标为补至配方所需数量。

已排除备选：模板幽灵格（格内物品不消耗，需要发明“模板数量 ≠ 消耗数量”的新语义且偏离原版匹配）与纯消耗无补位（每次合成后图案消失，“保存格子”的价值大打折扣）；图案维持的 A1 备选（补回扣取前数量）也已排除，其“格内弹药架、外部持续净流出”的语义不可控。

细则：

1. 配方匹配只使用合成格内的物品；外部容器不参与匹配，只在结算与补位时供货。格内图案不完整时，合成站不猜测玩家想合成什么。
2. 扣取计划按槽位生成：每个图案槽位先扣格内存量，缺口从外部容器按 3.4 规则从唯一来源补足；模拟全部成功后一次性提交（既有方向）。
3. 图案维持（合成成功后立即执行）：对本次合成中数量下降的图案槽位，从外部容器补回同种物品，每槽只补回到配方在该槽所需的数量（标准配方为 `1`）。单件图案槽保持常驻，成堆堆叠的槽自然消耗，外部容器只在格内不足时被使用。
4. 补位失败（外部无货）不影响本次合成结果，也不显示任何文字提示（随 6.2），空缺槽位以格内实际内容自明；不回滚已成功的合成。

### 4.2 工具槽语义（已确认）

- 工具位格留空时，自动从 `9` 个工具槽中寻找匹配类型的工具借用并扣其耐久；工具位格也仍可手动放入工具（原版习惯）。同类型工具有多份时，工具位格优先，工具槽按槽位顺序取第一份可用的。
- 收纳资格：能够在配方中充当工具位的耐久物品（GTCEu `GTToolType` 工具、声明对应 Forge `ToolAction` 的原版与第三方工具）。按能力与标签判定，不按模组名硬编码（既有方向）。无耐久、不可损耗的物品（如编程电路）不是工具，不收。
- 耐久耗尽：破损工具留在原槽位（工具槽或工具位格）并以红色边框提示，不自动丢弃、不自动换下一份；由玩家手动取出更换。
- 合成格中的工具按 Shift 移出时，优先进入工具槽常驻，溢出部分再进入玩家背包。
- 工具槽不作为原料来源：任何配方都不会消耗工具槽中的工具本体；合成站不提供工具修复、充能或升级。
- 已排除备选：工具槽只收纳、不参与结算。理由：`9` 个工具槽的设计输入正是为了让玩家不必反复摆放工具，“工具常驻站位、格子只放原料”是本方块的核心体验。

### 4.3 剩余物规则（已确认）

- 合成产生容器剩余物（如蛋糕返还空桶）时，优先放回当前唯一外部来源容器（普通形态为按 3.4 选出的容器，竖半砖形态为附着目标）。
- 外部容器放不下时进入玩家背包；仍放不下时掉落在合成站位置。
- 剩余物一律不留在合成格内：图案槽若被空桶占据，会破坏下一次配方匹配，违背图案常驻语义。
- 剩余物与扣取、图案维持、工具耐久在同一事务中结算；不会出现剩余物已入容器而扣取回滚的不一致状态。
- 剩余物按物品类型判定是否属于图案：GT 工具被合成扣取耐久后的副本与原物品同类型，视为图案物品留在原格（耐久已扣减）；不同类型的剩余物（如空桶）才按上方规则归位。
- 已排除备选：优先进入玩家背包。理由：材料存放在外部容器的使用方式下，剩余物直接归位容器更顺手。

### 4.4 连续合成（已确认）

- Shift 连续合成为逐轮执行：每轮独立完成“模拟 → 提交 → 图案维持”，轮与轮之间允许外部容器与玩家背包状态变化。
- 连续合成锁定开始时匹配的那个配方，每轮仅重新验证该配方是否仍然匹配（含工具槽自动供给的再验证）；即使剩余材料恰好满足其他配方，也不会在轮间切换执行。
- 任一轮失败（原料不足、背包已满、工具耐久耗尽）即停止；已完成的轮次保留，不对整次连续合成回滚。
- 每轮开始时重新扫描外部容器与工具槽；扫描结果不跨轮缓存。

### 4.5 原子性与并发（已确认）

- 一次合成是一个服务端事务：先完整模拟物品扣取、产出、工具耐久与剩余物，全部满足后一次性提交；任一不足则什么都不发生（既有方向）。
- 1.7 的单人占用使同一台合成站不存在并发操作；事务内不允许出现任何交错的半结算状态，也不需要额外的并发控制。
- 区块卸载时合成站不执行任何结算；界面因方块失效被强制关闭时，未取走的产物预览直接消失，不生成掉落物。

### 4.6 支持的配方范围（已确认）

- 只支持原版合成配方类型（`minecraft:crafting` 有序与无序），包括 GTCEu 注册到该类型的工具位配方。
- 不支持组装机、破碎机等其他 GT 配方类型，不支持其他模组的自定义合成体系（如模具浇铸）；合成站不是通用配方执行器。
- 若未来需要支持新配方类型，必须在本规格中显式追加，不通过泛化匹配隐式获得。

## 第 5 步：形态转换与放置

### 5.1 转换方式（已确认：仅工作台合成）

- 普通形态与竖半砖形态之间不存在任何世界内转换交互；转换只通过工作台合成配方完成：以合成站物品为输入，产出竖半砖物品。合成站自身作为工作台上位替代，同样可以执行该配方。
- 锯子的角色由配方的锯子工具位承担（不消耗工具本体，只扣耐久），延续设计输入中“使用锯子转化”的语义。
- 转换是单向的：不存在竖半砖物品到合成站物品的转换配方；完整形态通过破坏竖半砖回收（5.4）。
- 竖半砖物品的放置：只能附着在合法容器（资格同 3.2）的侧面放置——对容器的侧面右键放置，竖半砖占据该侧面相邻的格子，背面朝向容器；点击面不是侧面、或目标不是合法容器时放置失败并提示。
- 转换配方已定案（见 7.1）：`1` 个合成站加锯子工具位耐久，产出 `1` 个竖半砖物品，不消耗其他材料；使玩家反复移动竖半砖（破坏回收合成站 → 重新转换 → 再放置）不产生累积的材料负担。

### 5.2 竖半砖形态规格（已确认）

- 外形与碰撞：贴附在附着目标表面的竖直薄板，厚度约 `4/16`（与原版半砖同厚），占用自身格子内靠附着面的一侧；附着面仅限容器的四个水平侧面（3.3），附着面以外方向不提供碰撞。
- 竖半砖形态保留完整 GUI 与全部库存（合成格、工具槽与普通形态共用同一方块实体数据）；放置新竖半砖得到的是空库存方块，库存只存在于已放置方块中。
- 附着目标的判定只看方块实体身份，不读容器朝向；箱子类容器的开启动画被竖半砖遮挡时互不影响（箱子被上方方块阻挡的开启限制不适用于竖半砖，它不是完整方块）。
- 活塞不可推动（方块实体规则）；竖半砖形态本身不受重力影响。

### 5.3 支撑失效（已确认）

- 附着目标消失（挖掘、爆炸、被替换）的同一游戏刻，竖半砖破坏并掉落完整合成站物品与全部内容物。
- 普通形态没有支撑概念：它不依附任何方块，四周容器被移除只影响读取范围。
- 两形态在方块更新时都不做额外的邻居扫描；唯一的状态联动是附着目标的消失检测。

### 5.4 回转方式（已确认）

- 破坏竖半砖形态掉落完整合成站物品与全部内容物（与 2.3 一致）；竖半砖物品本身不返还。
- 重新获得竖半砖形态必须再次执行转换配方（5.1）；不存在竖半砖到合成站的转换配方，也不存在世界内形态切换。
- 形态方向的完整语义：普通 → 竖半砖只能通过合成转换；竖半砖 → 普通只能通过破坏回收；两条路径都不经过锯子的世界内交互。
- 已排除备选：竖半砖作为无法恢复普通形态的真单向物品。理由：破坏回收完整合成站保证玩家不会因转换永久损失方块本身，同时保住“单向转换”的设计输入语义。

## 第 6 步：界面与玩家反馈

### 6.1 界面布局（已确认）

外部来源区是手动终端区——玩家可以在界面中直接存取外部容器中的物品。

- 三区布局，整体风格与原版工作台一致且界面内不含任何文字说明：中部主面板（176×186，合成区 `3×3` + 箭头 + 结果位）、其下方工具区（`9` 个工具槽单行）与玩家背包；外部来源终端是独立面板，在存在合法来源容器时吸附于主面板左侧（无来源时整体隐藏）。
- 终端化边界：
  - 只限玩家在 GUI 中的手动操作；合成站仍不暴露 Forge 物品能力，1.4 的自动化边界不受影响。
  - 手动存入外部容器时遵循目标容器自身的槽位合法性，不能塞进其不允许的槽位；被保护模组标记为不可访问的容器同样不可存取，无专门提示（随 6.2）。
  - 合成站不自动整理、不自动分类、不主动搬移外部容器物品；一切移动由玩家发起。
  - 外部区显示当前唯一读取的容器及其方位（普通形态为按 3.4 选出的容器，竖半砖形态为附着目标）。
  - 终端面板内为来源容器的 `6×9 = 54` 格终端槽位（每页），右侧竖向滑条翻页，可滚动访问来源容器的全部格子；合成扣取、图案维持与剩余物归位始终作用于容器的完整库存，与滑条位置无关。
- 已排除备选：只读展示。理由：用户选择更强的手动终端体验；杂项设计中“外部只作为合成候选”的初步方向在外部区交互范围内由本决定取代，合成扣取的只读结算语义不变。

### 6.2 状态与失败提示（已确认：不显示状态）

- 合成站界面不提供状态栏、失败原因列表或可合成次数显示；界面只有槽位与物品本身。
- 合成失败时没有额外反馈：单击结果位无产物，Shift 连续合成提前停止，与原版工作台的沉默行为一致。
- 容器不可访问、图案维持失败、工具耐久耗尽等状态同样不产生文字提示，只通过界面内已有元素的可见状态表达（格内物品、工具耐久条、空缺槽位）。
- 已排除备选：固定优先级状态条与失败原因明细。理由：保持界面与原版工作台一致的简洁。

### 6.3 EMI/JEI 集成（已确认）

- 支持从 EMI/JEI 把工作台配方一键填入合成站（填充合成格，并在工具位格给出所需工具类型的提示）。
- 配方查看器中的合成站入口只展示原版合成配方，不虚构额外配方。
- 合成站没有 EU 配方，与[杂项设计](miscellaneous.md)中的 EMI 功耗显示规则无交集。

### 6.4 两形态的视觉区分（已确认）

- 普通形态：完整方块工作台模型，顶面合成台面纹理 + 四角工具位轮廓。
- 竖半砖形态：竖直薄板模型，正面复用台面语言并明确表现附着边缘；两种形态在 `16×16` 纹理下可快速区分。
- 界面标题使用对应方块的本地化名称：`合成站` / `合成站竖半砖`。

## 第 7 步：获取、兼容与验收

### 7.1 获取与转换配方（已确认）

产量与路线：

- 合成站在 Easy、Normal、Expert 下的获取配方都固定产出 `1` 个，不读取[全局工作强度](difficulty.md)的非控制器方块通用产量 `2 / 1 / 1`；该例外已登记到 difficulty.md 的接入基线。
- 不提供组装机路线；合成站与竖半砖都没有低电压自动化获取配方。

获取配方：`1` 个 GTCEu 青铜板（`plate / Bronze`）、`1` 个原版工作台（`minecraft:crafting_table`）与 `4` 个 GTCEu 青铜杆（`rod / Bronze`），固定产出 `1` 个合成站；不消耗工具位，不使用箱子或其他材料。

```text
R B R
. W .
R . R
```

| 符号 | 输入 |
| --- | --- |
| `B` ×1 | GTCEu 青铜板（`plate / Bronze`） |
| `R` ×4 | GTCEu 青铜杆（`rod / Bronze`） |
| `W` ×1 | 原版工作台（`minecraft:crafting_table`） |

- 图案表达“以四根青铜杆在工作台四角加固、顶部覆青铜板”的上位替代语义；水平镜像不改变图案，180° 旋转对称。
- 配方资源 ID 为 `gregsteamexpansion:shaped/crafting_station`。

转换配方：有序配方，锯子在左上、合成站在其正下方（左中），固定产出 `1` 个合成站竖半砖物品；除锯子耐久外不消耗任何材料。

```text
s . .
c . .
. . .
```

| 符号 | 输入 |
| --- | --- |
| `s` | 锯子工具位（不消耗工具本体，只扣耐久） |
| `c` ×1 | 合成站（`gregsteamexpansion:crafting_station`） |

- 图案为 `1×2` 竖列，可放在 `3×3` 网格的任意水平位置；不开启上下镜像，锯子固定在合成站上方。
- 配方资源 ID 为 `gregsteamexpansion:shaped/crafting_station_slab`。
- 不附加其他材料：破坏回收只返还合成站，玩家每次移动竖半砖都必须重新转换，额外材料会形成反复移动的累积成本。
- 锯子接受 GTCEu `GTToolType.SAW` 及声明 `SAW_DIG` 工具动作的等效工具；在合成站内执行该配方时，锯子也可由工具槽自动供给（4.2）。

### 7.2 兼容核验清单

实现后逐项核验：

- 原版容器：箱子、木桶、潜影盒（含染色与 NBT 变体）作为外部来源与附着目标。
- 排除规则：熔炉、高炉、烟熏炉、酿造台、漏斗、发射器/投掷器与 GTCEu 机器不被读取，也不能作为竖半砖的附着目标；例外为 GT 板条箱（可读取、可附着）。
- GTCEu 容器：木桶等；GTCEu 全部 `GTToolType` 工具放入工具槽并在工具位配方中被正确扣耐久。
- 原版工具：剪刀、铁镐等耐久工具的收纳与 ToolAction 判定。
- 背包模组：至少核验一个主流可放置背包（如 Sophisticated Backpacks）作为附着目标。
- 存储模组容器（抽屉等）暴露能力时的读取表现。
- 保护模组下不可访问容器被当作空来源且不可存取（3.5）。
- EMI/JEI 配方转移与填充。
- Jade/探针显示：形态、附着目标与读取范围（是否提供 Jade 集成到实现阶段再定）。

### 7.3 实现验收

1. `gregsteamexpansion:crafting_station` 与 `gregsteamexpansion:crafting_station_slab` 独立注册并共享同一方块实体类型；名称、模型、物品模型、掉落与中英文本地化完整，竖半砖物品只能通过转换配方获得。
2. 获取配方恰好消耗 `1` 青铜板、`1` 原版工作台、`4` 青铜杆并产出 `1` 个合成站；转换配方按锯上站下的有序图案产出 `1` 个竖半砖且锯子只扣耐久；三档配方完全一致，不存在组装机路线。
3. 原版工作台能制作的全部 `minecraft:crafting` 配方（含 GTCEu 工具位配方）都能在合成站完成；原版工作台不能制作的配方在合成站同样不能完成。
4. 合成格与工具槽在关闭界面、区块卸载、世界重载后不变；结果位不持久化；挖掘与爆炸掉落完整合成站物品与全部内容物，无丢失、无复制。
5. 普通形态只读取东、西、北、南四个直接相邻位置中按该顺序确定的第一个合法容器；竖半砖形态只读取其附着容器；来源容器外的相邻容器不被读取。
6. 一次合成为单事务：格内不足时从唯一来源原子补足，工具位格可由工具槽自动供给并扣耐久；任一输入不足时整次合成不发生，无部分扣取。
7. 图案维持只补回至配方所需数量；剩余物按“外部容器 → 玩家背包 → 掉落”结算且绝不留在合成格。
8. 一名玩家打开界面时其他玩家无法打开并收到动作栏提示；界面因任何原因关闭后占用立即释放。
9. 竖半砖只能附着在合法容器侧面放置；附着目标被移除的同一游戏刻竖半砖破坏并掉落完整合成站物品与内容物；不存在世界内形态转换交互。
10. 漏斗、管道等无法放入、取出或查看合成站库存；红石信号不触发合成；合成站不消耗任何能量。
11. 外部终端区可手动存取唯一来源容器物品并遵循目标槽位合法性，容器超过一页时可通过翻页访问全部格子；界面无状态栏与失败提示；EMI/JEI 配方转移可填入合成格并给出工具位提示。
